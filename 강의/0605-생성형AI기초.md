## 01. 생성형 AI란 — 판별형과의 차이 → [[생성형AI]]

**생성형(Generative) AI** = 학습한 데이터의 패턴을 바탕으로 텍스트·이미지·오디오·비디오 등 **새로운 콘텐츠를 생성**하는 AI. 기존의 **판별형(Discriminative) AI**가 입력을 분류·예측·탐지하는 데 그쳤다면, 생성형은 결과물을 직접 만들어낸다.

| 구분 | 판별형 AI | 생성형 AI |
|:---|:---|:---|
| 목적 | 분류·예측·탐지 | 새 콘텐츠 생성 |
| 출력 | 라벨·확률·점수 | 텍스트·이미지·영상·오디오 |
| 예시 작업 | 스팸 분류, 이상탐지 | 글쓰기, 그림 생성, 영상 제작 |
| 대표 모델 | (전통 분류기·회귀) | Sora, Nano Banana, GPT, Gemini Pro, Kling, Veo, Claude Opus |

> 위 "대표 모델" 목록은 슬라이드에 정상 추출된 고유명사. 판별/생성 정의 문장 자체는 `[원문 확인 필요]`.

## 03. AI 모델 vs 서비스 — 활용 3가지 방식

같은 AI라도 **모델**(가중치 덩어리)과 **서비스**(그 모델을 감싼 제품)는 다르다. AI 모델을 실제로 쓰는 길은 3가지.

| 방식 | 설명 | 대표 |
|:---|:---|:---|
| ① 웹 인터페이스(서비스) | 브라우저에서 바로 사용. 가장 쉬움 | ChatGPT, Claude, Gemini |
| ② API 호출 | 코드에서 모델을 호출, 앱에 통합 | OpenAI / Anthropic / Google API |
| ③ 오픈웨이트 직접 구동 | 공개된 가중치를 내 GPU에 올려 실행 | Llama(Meta), DeepSeek, Gemma(Google) |

```
쉬움 ───────────────────────────→ 어려움/자유도↑
웹 서비스   →   API   →   오픈웨이트(자체 GPU)
(설치X)      (코드)     (인프라 필요)
```

📌 **오픈웨이트(Open-weight)** = 모델 가중치가 공개되어 직접 내려받아 구동 가능. 단, GPU 등 자원이 필요하다는 단서만 추출됨. 각 방식 장단점 본문은 `[원문 확인 필요]`.

## 04. LLM 동작 원리 — Self-supervised & Auto-regression → [[LLM]]

LLM은 **다음 토큰을 예측**하도록 학습/생성한다. 두 핵심 원리:

**① Self-supervised Learning (자기지도학습)** — 레이블 없는 텍스트에서 "다음 단어"를 정답(Label) 삼아 스스로 학습. 사람이 라벨을 달 필요가 없어 인터넷 전체를 학습 데이터로 쓸 수 있다.

슬라이드 데모 (정상 추출, 문장: *Second Law of Robotics: A robot must obey the orders given it by human beings*):
```
"Second Law Of Robotics : ?"        → 정답 "A"
"Second Law Of Robotics : A ?"      → 정답 "Robot"
"... A robot ?"                      → 정답 "Must"
```

**② Auto Regression (자기회귀)** — 이전 토큰들을 바탕으로 다음 토큰의 **확률분포**를 산출하고 샘플링해서 한 토큰씩 이어붙인다.

슬라이드 출력 예시 (입력 `Second law of robotics : a`):

| 후보 토큰 | 확률 |
|:---|:---:|
| **Robot** | **0.80** |
| Person | 0.16 |
| Bird | 0.02 |
| Lion | 0.01 |

→ 최고 확률 `Robot` 선택 → `Second law of robotics : a Robot` → 다시 이 결과를 입력으로 반복.

→ [[LLM]] · [[자기지도학습]] · [[자기회귀]] 참조

## 05. 추론 모델과 Chain of Thought → [[추론모델]]

기존 LLM은 질문 → 답을 바로 냈다. **추론(Reasoning) 모델**은 답하기 전에 **추론 과정(생각의 사슬)을 먼저 생성**한다.

**Chain of Thought (CoT)** = 단계적 사고 과정을 거쳐 답을 도출하는 방식. 복잡한 수학·논리 문제에서 정확도가 크게 오른다.

```
[기존 LLM]   질문 ──────────────→ 답변
[추론 모델]  질문 → 추론 과정 → 답변
                  (Chain of Thought)
```
> "기존 LLM 모델 / 추론 모델 / 답변 / 추론 과정" 도식 라벨은 정상 추출. 세부 본문 `[원문 확인 필요]`.

## 06. 멀티모달 AI → [[멀티모달AI]]

**Multi Modal AI** = 여러 형태(모달)의 입력·출력을 함께 처리하는 AI. 텍스트만이 아니라 이미지·오디오·비디오를 넘나든다.

```
       ┌── Text ──┐
입력 ──┤   Image  ├── [ Multi Modal AI ] ── 출력 (Text/Image/Audio/Video)
       │   Audio  │
       └── Video ─┘
```

**예시** (정상 추출): OpenAI `ChatGPT`, Google `Gemini` — 텍스트·이미지·음성을 한 모델에서 처리.

## 07. 이미지 생성 — Diffusion Model → [[Diffusion모델]]

**Diffusion(확산) 모델** = 이미지에 노이즈를 점진적으로 더했다가, 거꾸로 노이즈를 제거하며 이미지를 만들어내는 생성 방식.

```
[Forward Diffusion]  Data ──→ 노이즈 점점 추가 ──→ Noise
                                                      │
[Reverse Denoising]  Data ←── 노이즈 점점 제거 ←── Noise (여기서 생성)
```

| 단계 | 슬라이드 용어 | 방향 |
|:---|:---|:---|
| 정방향 | `Fixed Forward Diffusion Process` | Data → Noise |
| 역방향(생성) | `Generative Reverse Denoising Process` | Noise → Data |

**사례** (정상 추출): **Gemini 3 Pro Image**(별칭 **Nano Banana Pro**), 이전 버전 `Gemini 2.5 Flash`. Google 2025-11-20 발표.
- 참고: https://blog.google/intl/ko-kr/company-news/technology/nano-banana-pro/

## 09. AI Agent → [[AIAgent]]

**AI Agent** = 목표를 받아 **스스로 계획하고 도구를 사용해 실행**하는 AI. 단발성 생성을 넘어 작업을 자율적으로 수행한다.

**핵심 속성 4가지** (영어 라벨 정상 추출):

| 속성 | 영어 | 의미 |
|:---|:---|:---|
| 목표 지향성 | Goal-Oriented | 주어진 목표를 향해 동작 |
| 자율성 | Autonomy | 사람 개입 없이 스스로 판단 |
| 인식 | Perception | 환경·상태를 관찰 |
| 행동 | Action | 도구/API 호출로 작업 실행 |

```
목표 입력 → [인식] → [계획] → [행동: 도구·API] → 결과 관찰 → 반복 → 목표 달성
```
> "생성형 AI → AI Agent" 확장 비교 슬라이드 존재. 각 속성 설명 본문 `[원문 확인 필요]`.

## 10. Physical AI → [[PhysicalAI]]

**Physical AI** = 소프트웨어를 넘어 **센서·카메라·IoT 등 물리 장치와 연동**해 현실 세계와 상호작용하는 AI. 로봇·자율주행이 대표.

| 구분 | Software AI | Physical AI |
|:---|:---|:---|
| 작동 무대 | 디지털(텍스트·이미지) | 물리 세계 |
| 입출력 | 데이터 | 센서·카메라·IoT + 구동 장치 |
| 예시 | 챗봇, 이미지 생성 | 로봇, 자율주행 |

**사례** (정상 추출): **NVIDIA OpenUSD**, **디지털 트윈(Digital Twin)** 기반 Physical AI 시뮬레이션 — 현실을 가상으로 복제해 학습/검증.

## 11. 산업별 AI 활용 사례

> 출처: 산업 활용 PDF(슬라이드 OCR 복원). 세 사례 모두 "도입 배경 → 활용 전략 → 성과" 골격. 상세는 [[AI산업활용]].

**① 제조 — LG전자 (스마트팩토리)**: 생성형 AI + 디지털 트윈 + 데이터 분석으로 공정·설비·에너지를 통합 관리. 다품종·복잡 공정으로 관리 난이도가 오르고 이상 원인 분석이 사람 경험에 의존하던 한계를 풀려는 것. 센서 데이터 분석 + 생성형 AI 이상 원인 대응, 가상 공장(디지털 트윈)에서 병목·불량 사전 예측, 음성·텍스트로 설비 상태 조회까지. **성과: 생산성 17%↑ / 에너지 효율 30%↑ / 불량 품질 비용 70%↓.**

**② 금융 — 모건 스탠리 (자산관리)**: 문서·지식이 방대해 검색 품질이 사람 역량에 좌우되던 문제를, 내부 지식 검색·요약 Assistant로 해결. 요약·응답 초안 생성을 업무 흐름에 녹임. **성과: 어드바이저 도입률(Advisor adoption) 20% → 80% / 문서 접근률 개선 98%+ / 문서 검색 시간 감소.**

**③ IT·개발 — 채널코퍼레이션 (AI Agent 개발 자동화)**: 대규모 코드베이스 수정·리팩토링·PR과 길어지는 CI/리뷰 루프가 병목. [[AIAgent]]가 구현·리팩토링·PR을 맡고 개발자는 설계·판단에 집중, CI 피드백을 자동화하고 `worktree`로 다중 Agent를 병렬 구동(앱 설치·결제·웹훅·OAuth·MCP 등 핵심 시스템 개발). **성과: 약 97만 줄 코드 수정 / 560개 이상 PR 자동 머지 / CI 실행 시간 80%↓.** 라이브 보강: **[[Cursor]]** 소개 — 채팅 프롬프트로 코드 생성·디버깅을 자동 수행하고 에러 시 스스로 수정 반복, 여러 모델(Claude/Gemini/ChatGPT) 선택 가능. 강사 권장은 "지금은 불필요, **파이널 프로젝트 때 한 달 유료**".

| 산업 | 기업 | 핵심 | 성과 |

| 금융 | 모건 스탠리 | 내부 지식 검색·요약 Assistant | 어드바이저 도입 20→80% / 문서 접근률 98%+ |

## 12. 윤리·안전 가이드 ① — 데이터·보안 → [[AI윤리가이드]]

**AI 확산 현황 (한국IDC 조사)**: 국내 조직의 **72%**가 생성형 AI 도입(사용 중이거나 곧 도입 예정), **78%**가 도입으로 직원 생산성이 개선됐다고 평가, 개인의 **86.0%**가 AI 도구를 개인·조직 차원에서 활용. AI가 '기본 도구'로 자리잡았다 → 그래서 보안·팩트체크·에티켓이 더 중요. AI 윤리가 중요한 4대 위험: **개인정보 유출 · 기업 기밀 유출 · 허위 정보 생성 · 저작권 문제.**

**위험성 — 삼성전자 ChatGPT 사례 (라이브 강조)** — AI에 입력한 데이터가 학습·유출될 수 있다. 강사는 초기 ChatGPT 시기 **삼성전자 직원들이 회사 기밀을 ChatGPT에 입력** 해 보안 이슈가 된 실제 사례로 경각심을 강조했다("삼성전자 ChatGPT 보안" 검색 권장). **비밀번호·API 키·회사 기밀·개인정보는 절대 업로드 금지.** DeepSeek 등 일부 모델의 과도한 데이터 수집 우려도 언급(개인 사용은 큰 차이 없으나 **회사 차원에선 가려 쓰라**). OpenAI·Anthropic 정책 참고(https://openai.com/ko-KR/policies/terms-of-use/).

## 13. 윤리·안전 가이드 ② — 환각·아첨·검증·책임 → [[Hallucination]]

**환각 (Hallucination)** = 모델이 근거 없는 정보를 사실처럼 그럴듯하게 생성하는 오류. LLM이 "다음에 올 그럴듯한 토큰"을 예측하는 구조라 본질적으로 발생. **강사 강조: 환각은 완전히 제거 불가** — 환각 없는 모델은 현재도 없고 (인간이 사고하는 한) 앞으로도 없을 것이며, **모델 성능 향상과 별개로** 발생한다. 발생 원인 4가지: **① 모델 자체의 잘못된 지식 ② 논리적 오류 ③ 존재하지 않는 근거자료 인용 ④ 업데이트되지 않은 정보.** 완화책은 **[[RAG]](레그)** 로 양질의 정보를 함께 제공하는 것. 논문·법률·전략 문서는 **하나하나 직접 검증** 필수.

**아첨 (Sycophancy)** = LLM이 과도하게 사용자를 치켜세우고 맞장구치는 현상. 단순 과장 화법이 아니라 잘못된 정보 제공·유저 편견 강화로 신뢰도에 직결된다. 원인은 학습 방식·유저 피드백·시스템 프롬프트 등 다양. **실제로 OpenAI는 ChatGPT 업데이트 후 아첨 현상이 심각해지자 결국 롤백 패치를 진행**했다. 라이브에선 "아첨한다는 얘기가 있다"며 "100% 완벽한 모델은 없으니 검증하라"로 연결.

**교차검증** — AI 출력은 **초안(draft)** 으로 보고 사람이 반드시 검증·활용. 3가지 방법: **① 공식 자료 확인(공식 문서·논문·기관 자료) ② 다른 출처 비교(교차 검증) ③ 숫자·데이터 검증(통계·수치·계산 재확인).** 전략·법률은 오히려 검증 부담(판례 확인 등)이 늘기도 한다.

**RLHF·피드백으로 모델 개선 (라이브 신규)** — 챗봇 답변의 **좋아요/싫어요** 는 단순 만족도가 아니라 **강화학습([[RLHF]])의 입력** 이다. 좋아요=보상처럼 작용해 모델이 그 방향으로 더 잘 답하게 됨 → 마음에 안 드는 답은 **싫어요를 적극 눌러** 유도 가능. 이 아이디어는 OpenAI ChatGPT(GPT-3 계열) **2022 논문** 의 핵심 키워드(RLHF/강화학습)로, 현재 대부분 모델에 차용됨(정확한 논문 제목은 InstructGPT 계열로 추정, `[원문 확인 필요]`). 심화 검색: **"RAG + 강화학습"**.

**저작권·책임 — AIR CANADA 챗봇 / 가짜 판례**: 캐나다 최대 항공사 AIR CANADA의 웹사이트 AI 챗봇이 **규정에 없는 항공료 할인을 안내**했고, **회사가 책임지고 그대로 할인해 줘야 한다는 민사 중재 결정**이 나왔다. 또 다른 사례로 **노무사가 AI가 만든 가짜 판례(존재하지 않는 판례)를 검증 없이 제출**했다가 발각. 검증 안 된 AI 출력에 사용자/기업이 책임을 진다는 경고. 저작권 위험 4가지(학습 데이터 출처 불분명 / 원문 유사 문장 재생산 / 책임 소재 불분명 / 저작권자 소송)와 콘텐츠 사용 의사결정 4단계(유사성 점검 → 권리·기간 확인 → 사용 목적 구분 → 리스크 관리)도 함께 다룸 → [[AI윤리가이드]].

| 위험 | 무엇 | 대응 |
|:---|:---|:---|
| Hallucination | 근거 없는 사실 생성 (완전 제거 불가) | 교차검증·출처 확인·[[RAG]] |
| Sycophancy | 무비판적 동조 | 반론 요청·객관 자료 대조 |
| 책임 귀속 | 챗봇 오답의 법적 책임 | 기업이 책임(AIR CANADA) |
| 모델 개선 | 좋아요/싫어요 피드백 | [[RLHF]] 보상으로 방향 유도 |

→ [[Hallucination]] · [[Sycophancy]] · [[RLHF]] · [[RAG]] · [[AI윤리가이드]] 참조

## 14. Human in the Loop — AI는 도구 → [[HumanInTheLoop]]

**Human in the Loop (HITL)** = AI 작업 루프에 인간의 검토·개입을 두는 협업 방식. **AI는 초안을 만들고, 최종 판단·검증은 인간이 한다.** AI가 아무리 뛰어나도 핵심 단계에선 사람이 직접 개입해 정확성·완성도를 높여야 한다.

```
Human (기획)            AI (생성)                 Human (결정)
명확한 목표         →   초안 Draft           →    사실 검증·할루시네이션 방지
배경 지식(Context)      데이터 분석·예측           결과물 수정
구체적 지시            논리 오류 점검            최종 실행 여부 결정
```

마무리 메시지: **"AI는 도구(tool)"** — 비판적·책임감 있게 사용하라. LLM의 학습 방식 한계를 이해하고, 결과를 맹신하지 말 것.

→ [[HumanInTheLoop]] · [[AI윤리가이드]] 참조

## 15. ★ 심볼릭 AI — "모델 + 지식" 아키텍처 → [[심볼릭AI]]

> 라이브 4-6교시의 핵심. 강사가 그림판으로 직접 그려 설명한, 이번 수업에서 **가장 중요한 개념틀**.

겉모습은 ChatGPT·Gemini·Claude가 다 달라 보여도, **모든 생성형 AI 서비스가 공유하는 기본 구조는 같다.** 강사는 이를 **심볼릭 AI(Symbolic AI)** 라 부르며, **1960~70년대에 등장한 개념** 이 지금의 생성형 AI에 그대로 차용되고 있다고 강조했다.

```
사용자 ──질문──▶ [ AI 시스템 = 모델(Model) + 지식(Knowledge) ] ──답변──▶ 사용자
```

**아키텍처 자체는 안 바뀐다. 바뀌는 건 딱 둘.**

| 구성 요소 | 누가 바꾸나 | 설명 |
|:---|:---|:---|
| **모델(Model)** | 사용자는 **선택만** | 직접 못 만든다. 빅테크가 만든 것 중 고른다 |
| **지식(Knowledge)** | 사용자가 **업로드** | 무엇을 올리느냐가 **답변 품질을 결정** |

**서비스 설계 함의** — 내가 LLM 기반 서비스를 만든다면 반드시 두 가지를 제공해야 한다.
1. 사용자가 **모델을 선택** 할 수 있게
2. 사용자가 **지식을 업로드** 할 공간 (예: Genspark의 "드라이브")

### 지식 업로드 비교 실습 (D2)

같은 도구라도 **일반 채팅 vs 지식 업로드** 의 답변 품질 차이가 크다.

```
[일반 채팅]    질문 → 모델만으로 답 → 짧고 일반적
[지식 업로드]  질문 + 내가 올린 자료 → 상세·전문적, 출처(페이지)까지 제시
```

- 절차: 참고자료 다운로드 → 프로젝트/챗봇에 **4개 파일 업로드** → 지침 입력 → 저장 → 채팅 시작.
- 비교 기준: 답변 양 / 완성도·구체성 / **출처 표기 여부**.
- 시연: 통계 교재(녹취상 "DSUR")를 올린 뒤 **Robust Regression** 을 물으니 **298페이지** 근거 제시(영어로 검색해야 매칭). 회귀 예제엔 **tips 데이터** 사용.
- 도구별 차이: Gemini "프로 모드"는 답을 신중히(느리게) 생성. 입력이 컨텍스트 윈도우를 넘으면 처리 불가. ChatGPT는 지침이 길면 일부 잘리는 현상 관찰.
- **팀 협업(D3):** 한 명만 프로젝트(지식+지침)를 세팅 → **공유 링크** 전달 → 팀 전체가 동일 품질 답변 사용.

> ⚠️ 강사 발음상 "샘플릭/시인블랙 AI"로 녹취됐으나 문맥상 **Symbolic AI**. 학술적 Symbolic AI(규칙·기호 기반 고전 AI)와 의미 범위가 다를 수 있어, 여기서는 강사의 "모델+지식 구조" 의미로 정리.

→ [[심볼릭AI]] · [[RAG]] · [[생성형AI]] 참조

## 16. ★ 문서·기획 논리 — 바바라 민토 『논리의 기술』 → [[SCQA]]

> 라이브 4-6교시에서 강사가 **가장 비중 있게** 다룬 신규 주제. 보고서·기획안·전략 컨설팅의 표준 논리틀(맥킨지식).

### SCQA — 도입부 논리 → [[SCQA]]

결론부터 말하기 위한 도입부 설계틀. **S**ituation → **C**omplication → **Q**uestion → **A**nswer.

| 요소 | 뜻 | 핵심 규칙 | 예시 |
|:---|:---|:---|:---|
| **S** 상황 | 논쟁 없는 배경 사실 | 모두 동의하는 것만 | "3분기 매출 5% 증가" |
| **C** 전개 | S와 **모순·충돌** 되는 문제 | 단순 현황 나열 금지 | "그런데 영업이익률은 하락" |
| **Q** 질문 | C가 부르는 핵심 질문 | 자연히 떠오르게 | "왜 수익성이 떨어지나?" |
| **A** 답변 | Q의 결론 | 핵심 메시지 | "원가 구조 개선이 시급" |

- **가장 어려운 건 C(Complication).** C를 잘 만들면 **Q·A가 자동으로 따라온다.** C에는 "이대로 지속되면 어떤 위기"까지 담겨야 한다.
- 실무에선 **이해관계자(stakeholder)** 와 통제 불가 외부 변수(예: HBM 수급 차질) 때문에 C 정의가 더 어렵다.

### 피라미드 원칙 — 전체 구조 → [[피라미드원칙]]

**결론을 최상단에 두고 탑다운으로 전개.** 보고/발표는 현황 설명이 아니라 **의사결정을 구하는 행위** — 상대는 바쁘므로 **결론부터** 말한다.

```
        [ 결론 = SCQA의 A ]
       /        |        \
   [근거1]   [근거2]   [근거3]   ← MECE로 구성
```

### MECE — 근거를 짜는 원칙 → [[MECE]]

**M**utually **E**xclusive, **C**ollectively **E**xhaustive = **중복 없이(상호 배타) + 누락 없이(전체 포괄).** 근거 3개는 서로 안 겹치고, 모두 결론(탑)을 향해야 한다. 사고는 연역·귀납 병행.

### 실습 과제 (E4)

1. **잼스(프로젝트) 설정** — 『논리의 기술』 자료·지침을 업로드해 프로젝트 세팅(15번 절차 활용).
2. **전략 컨설팅 리포트** — 시나리오: *로테이션 소개팅 100회, 애프터 성공 0회, 외모·경제력은 준수, 실패 이유 모름.* 내담자가 연애정보회사(=상담자=수강생)를 찾아옴. **SCQA + 피라미드 + MECE** 로 성공 전략 리포트 작성.

**공통 피드백 (강사):**
- 답변 품질은 프롬프트 형식보다 **구체적 상황 맥락** 제공 여부가 더 좌우한다.
- 다수 결과물에서 **S와 C가 섞이거나 C가 단순 현상 설명** 에 머무는 문제 — C엔 "이대로면 닥칠 위기"가 들어가야 한다.
- 강사 시연: 상담자 관점 관찰 가설(말이 빠름, 모든 걸 해결하려는 태도 등)을 더해 구체화 → 대화 지분율 7:3 조정, 해결사 태도 버리기, 만남을 평가가 아닌 소통으로 재프레이밍.
- **출력물을 그대로 쓰지 말고 SCQA를 보고 수정·보완할 것** (반복 강조) → [[HumanInTheLoop]].

→ [[SCQA]] · [[피라미드원칙]] · [[MECE]] 참조
