# 윈도우 함수 (Window Function)

**정의**: **행과 행 사이의 관계를 정의**해 순위·집계·이전/이후 참조·비율을 계산하는 함수. `OVER` 절을 **필수**로 쓰며, 집계를 해도 **원본 행 수를 유지**한다.

---

## 왜 필요한가

[[GROUP BY]] 집계는 행을 압축한다(국가별 1행). 하지만 "각 고객 행은 그대로 두고 **옆에 국가 평균·순위·누적합을 붙이고** 싶다"면 GROUP BY로는 안 된다. 윈도우 함수는 원본 행을 유지한 채 계산 컬럼만 추가해 이 문제를 푼다. 순위·전월대비·누적·이동평균 같은 분석 쿼리의 핵심.

---

## 어떻게 작동하나

```sql
SELECT 윈도우함수(인수)
OVER ( [PARTITION BY 칼럼] [ORDER BY 절] [WINDOWING 절] )
FROM 테이블;
```

```
[GROUP BY]          [윈도우 함수]
국가 합계            고객 국가 구매액 순위
KR   300   압축 →    A   KR  150   1
US   250            B   KR  100   2   ← 행 유지 + 컬럼만 추가
                    C   US  250   1
```

- [[OVER절]]의 3요소: [[PARTITION BY]](칸막이) / `ORDER BY`(정렬·순위 기준) / [[윈도우프레임|WINDOWING]](행 범위).
- 종류: 순위([[순위함수]]), 집계+OVER([[집계윈도우]]), 행순서([[FIRST_VALUE LAST_VALUE]]·[[LAG LEAD]]), 비율([[비율함수]]·[[NTILE]]).

---

## 실제 예시

```sql
-- 국가별 고객 순위 (행 유지 + 순위 컬럼) — chinook
SELECT c.Country, c.CustomerId, SUM(i.Total) AS Total,
       RANK() OVER (PARTITION BY c.Country ORDER BY SUM(i.Total) DESC) AS CountryRank
FROM customers c JOIN invoices i ON c.CustomerId = i.CustomerId
GROUP BY c.Country, c.CustomerId;
```

---

## 자주 헷갈리는 것

**GROUP BY vs 윈도우**: GROUP BY는 행을 줄이고, 윈도우는 행을 유지한다. PARTITION BY는 "그룹"이 아니라 "계산 범위 칸막이"일 뿐 행을 압축하지 않는다.

**WHERE로 못 거른다**: 윈도우 함수는 SELECT 단계에서 계산되므로 같은 쿼리의 WHERE에서 `WHERE rank=1`처럼 못 쓴다 → **인라인뷰로 감싼 뒤** 바깥 WHERE에서 필터.
