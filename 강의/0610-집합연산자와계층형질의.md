# 06/10 · 집합 연산자와 계층형 질의

SQL 데이터 다루기 2번째 차시. 조인 없이 두 SELECT 결과를 합치는 **집합 연산자**(UNION / UNION ALL / INTERSECT / EXCEPT)와, 동일 테이블의 상위-하위 관계를 펼치는 **계층형 질의**(Oracle CONNECT BY · 표준 재귀 CTE)를 다뤘다. 이론은 **관계형 대수**(일반 집합 연산 + 순수 관계 연산)에서 출발하고, 실습은 SQLite Chinook DB로 집계·서브쿼리·집합 연산·재귀 CTE를 단계적으로 작성한다. 라이브 핵심은 "분할하고 합치기" 풀이 전략.

> 실습 DB: SQLite Chinook(테이블 11개). 이론 슬라이드는 Oracle/SQL Server/MariaDB 기준, **실습 SQL은 SQLite 기준** → 아래 DBMS 차이에 주의.
>
> 📌 **정답 출처**: ✅ 실제 답지 = `Day03_lecture.sql`(완전 정답본) + 노션 발표용 답지(`0610_notion.sql`). `Day03_students.sql`은 헤더+빈칸 스켈레톤이라 정답 기준은 lecture.sql 단일. ⚠ 단 lecture.sql 두 곳에 원문 버그/의도불명(아래 05절 주석) → 보정형으로 표기.

## 01. 관계형 대수 → [[관계형대수]]

**관계형 대수(Relational Algebra)** = 관계형 DB에서 원하는 정보를 유도하는 기본 연산의 집합. 크게 둘로 나뉜다.

- **일반 집합 연산**: 합집합(=UNION), 교집합(=INTERSECT), 차집합(=EXCEPT), 카티션 곱(=CROSS JOIN). → 집합 연산자의 이론적 뿌리.
- **순수 관계 연산**: 셀렉션(σ, WHERE — 행 필터), 프로젝션(∏, SELECT — 열 선택), 조인([[JOIN]]), 디비전(÷).

> 카티션 곱(CROSS JOIN)은 JOIN 단원 소관이라 집합 연산자에서는 UNION/INTERSECT/EXCEPT 3종에 집중. 디비전(÷)은 강사 언급상 "현업에서 거의 안 씀".

## 02. 집합 연산자 → [[집합연산자]]

**집합 연산자(Set Operator)** = **조인을 쓰지 않고** 둘 이상의 SELECT 결과를 세로로 결합하는 방법. 종류: UNION / UNION ALL / INTERSECT / EXCEPT.

**공통 규칙** (lecture.sql PART 3 헤더 ✅):
1. 각 SELECT의 **컬럼 수가 동일**해야 한다.
2. 대응 컬럼의 **데이터 타입이 호환**되어야 한다.
3. **첫 번째 쿼리의 컬럼명**이 최종 결과셋의 컬럼명이 된다.
4. **ORDER BY는 최종 결합 결과에만** 적용(각 SELECT 뒤가 아니라 전체 맨 끝에 1번).

| 연산자 | 중복 제거 | 정렬 발생 | 역할 |
|:---|:---:|:---:|:---|
| UNION | O | O | 합집합 |
| UNION ALL | X | X | 합집합(빠름) |
| INTERSECT | O | O | 교집합 |
| EXCEPT | O | O | 차집합 |

```
컬럼 수·타입 호환되는 두 결과를 세로로 쌓는다

  SELECT A,B FROM 표1        ┐
       (UNION/ALL/           ├─►  하나의 결과셋
        INTERSECT/EXCEPT)    │     (첫 쿼리 컬럼명 사용)
  SELECT A,B FROM 표2        ┘
                              └─ ORDER BY 는 여기 1번만
```

→ [[집합연산자]] · [[UNION]] · [[UNION ALL]] · [[INTERSECT]] · [[EXCEPT]] 참조

## 03. UNION / UNION ALL → [[UNION]] · [[UNION ALL]]

**UNION** = 합집합. 두 결과를 합친 뒤 **중복 제거**(이를 위해 정렬 과정이 발생). **UNION ALL** = 합집합이지만 **중복 제거·정렬을 안 함 → 더 빠름**. 가장 중요한 차이는 "중복을 제거하느냐".

**(a) 직원 + 고객 통합 명단** — 상수 컬럼('Employee'/'Customer')으로 출처 구분 ✅ 실제 답지(lecture 3-1a / 노션 동일):
```sql
SELECT FirstName, LastName, 'Employee' AS Type
FROM employees
UNION
SELECT FirstName, LastName, 'Customer'
FROM customers
ORDER BY FirstName, LastName;
```

**(b) 구매 이력 유무별 고객 분류** — 서브쿼리 IN/NOT IN을 UNION으로 결합 ✅(lecture 3-1b):
```sql
SELECT CustomerId, FirstName || ' ' || LastName AS 고객명, 'Has Invoice' AS 상태
FROM customers
WHERE CustomerId IN (SELECT DISTINCT CustomerId FROM invoices)
UNION
SELECT CustomerId, FirstName || ' ' || LastName, 'No Invoice'
FROM customers
WHERE CustomerId NOT IN (SELECT DISTINCT CustomerId FROM invoices)
ORDER BY CustomerId;
```

**(c) 소계 패턴 — 연도별 매출 + 전체 합계** (UNION ALL) ✅(lecture 3-2a):
```sql
SELECT strftime('%Y', InvoiceDate) AS 연도, ROUND(SUM(Total), 2) AS 매출합계
FROM invoices
GROUP BY 연도
UNION ALL
SELECT '── 전체합계', ROUND(SUM(Total), 2)
FROM invoices
ORDER BY 연도;
```

> 라이브: "엑셀처럼 합계 행을 마지막에 붙이는" 소계 패턴. 개별 쿼리(연도별 / 전체)를 각각 실행 확인 → UNION ALL로 결합하는 순서로 진행. 컬럼 수가 안 맞으면 "SELECT 결과 컬럼 수가 다르다" 오류. 정렬은 자동이 아니므로 끝에 ORDER BY 명시.
>
> ⚠ 노션 답지 3-2(a)는 전체합계 행만 `ROUND(..., 1)`로 자릿수가 1로 적혀 있으나, lecture.sql과 일관성을 위해 `2`로 통일(소수 둘째 자리). 표기 차이일 뿐 로직 동일.

→ [[UNION]] · [[UNION ALL]] · [[서브쿼리]] · [[집계함수]] 참조

## 04. INTERSECT / EXCEPT → [[INTERSECT]] · [[EXCEPT]]

**INTERSECT** = 교집합(양쪽에 다 있는 행). **EXCEPT** = 차집합(앞 결과에서 뒤 결과를 뺌, = Oracle의 MINUS). 둘 다 중복 제거.

**(a) 2009·2010 모두 구매한 고객 (INTERSECT) → 이름까지 JOIN 확장** ✅(lecture 3-3b / 노션 동일):
```sql
-- 1단계: 교집합으로 CustomerId 집합 추출
SELECT CustomerId FROM invoices WHERE strftime('%Y', InvoiceDate) = '2009'
INTERSECT
SELECT CustomerId FROM invoices WHERE strftime('%Y', InvoiceDate) = '2010';

-- 2단계: 그 집합을 인라인 뷰로 만들어 customers와 JOIN → 이름 출력
SELECT c.CustomerId, c.FirstName, c.LastName
FROM customers c
INNER JOIN (
    SELECT CustomerId FROM invoices WHERE strftime('%Y', InvoiceDate) = '2009'
    INTERSECT
    SELECT CustomerId FROM invoices WHERE strftime('%Y', InvoiceDate) = '2010'
) inv ON inv.CustomerId = c.CustomerId;
```

**(b) 이탈 고객 — 2009 구매 but 2010 미구매 (EXCEPT)** ✅(lecture 3-4b / 노션 동일):
```sql
SELECT CustomerId FROM invoices WHERE strftime('%Y', InvoiceDate) = '2009'
EXCEPT
SELECT CustomerId FROM invoices WHERE strftime('%Y', InvoiceDate) = '2010'
ORDER BY CustomerId;
```

**(c) 플레이리스트에 없는 트랙 (전체 트랙 − 플리 트랙)** ✅(lecture 3-4c):
```sql
SELECT TrackId, Name FROM tracks
EXCEPT
SELECT t.TrackId, t.Name
FROM tracks t
JOIN playlist_track pt ON t.TrackId = pt.TrackId
ORDER BY TrackId;
```

> 라이브: INTERSECT 결과를 임시 테이블처럼 JOIN해 이름까지 확장(서브쿼리·조인 결합). EXCEPT는 마케팅 "이탈 고객" 비유로 설명.
>
> ⚠ **데이터 특이사항**: Chinook은 Customer와 Invoice의 CustomerId가 거의 완전 매칭 → "청구서 없는 고객" 같은 EXCEPT 예제 결과가 비어 보일 수 있음(학습 효과 한계, 강사 언급).
>
> ⚠ **DBMS 차이 주의**: INTERSECT/EXCEPT는 **MySQL 미지원**(JOIN 등으로 대체). EXCEPT는 Oracle에선 `MINUS`, **MariaDB는 10.3+**부터 지원. SQLite는 셋 다 지원. → [[INTERSECT]]·[[EXCEPT]] 노트 참조.

## 05. 집계 함수 · 서브쿼리 복습 → [[집계함수]] · [[서브쿼리]]

이번 실습은 [[집계함수]](COUNT/SUM/AVG/MAX/MIN/GROUP_CONCAT)와 [[서브쿼리]](WHERE/FROM/SELECT 위치별, 연관/비연관)를 집합 연산자의 재료로 다시 활용한다. (개념 상세는 [[0609-SQL함수와서브쿼리]] 참조.)

- **GROUP_CONCAT**(SQLite) = 그룹 내 값을 문자열로 연결. `GROUP_CONCAT(Name, ' / ')`로 구분자 지정, `DISTINCT`로 중복 제거.
- **[[GROUP BY]] vs [[HAVING]]**: WHERE는 집계 전 행 필터, HAVING은 집계 후 그룹 필터.
- **인라인 뷰**(FROM절 서브쿼리) / **스칼라 서브쿼리**(SELECT절) / **연관 서브쿼리**(외부 값 참조, 행마다 재실행) / **[[EXISTS]]**(존재 여부).

**복합 예제 — 장르별 매출 리포트 + 전체합계** (집계 + 3-테이블 조인 + UNION ALL) ✅(lecture 4-1 / 노션 동일):
```sql
SELECT g.Name AS 장르,
       COUNT(DISTINCT ii.InvoiceId)              AS 청구서수,
       SUM(ii.Quantity)                          AS 판매수량,
       ROUND(SUM(ii.UnitPrice * ii.Quantity), 2) AS 총매출
FROM invoice_items ii
INNER JOIN tracks t ON ii.TrackId = t.TrackId
INNER JOIN genres g ON t.GenreId  = g.GenreId
GROUP BY g.Name
UNION ALL
SELECT '── 전체합계',
       COUNT(DISTINCT InvoiceId),
       SUM(Quantity),
       ROUND(SUM(UnitPrice * Quantity), 2)
FROM invoice_items
ORDER BY 장르;
```

> ⚠ **lecture.sql 4-2 "확인 3" 버그(보정 표기)**: 원문은 여는 `SELECT ... FROM (`가 없이 닫는 `);`만 남은 orphan 괄호 → **그대로 실행 시 문법 오류**. 의도는 "판매됐지만 플리에 없는 트랙"이므로 괄호 래핑 없이 아래처럼 단순화하면 동작한다(보정형):
> ```sql
> SELECT DISTINCT TrackId FROM invoice_items
> EXCEPT
> SELECT DISTINCT TrackId FROM playlist_track;
> ```
>
> ⚠ **lecture.sql 1-4(a) `/ 10000` 의도불명(보정 표기)**: "가장 긴 트랙 재생시간(분)"인데 ms→분 환산이면 `/ 60000`이어야 맞다. 원문은 `/ 10000`(보존). 분 단위 의도라면 `MAX(Milliseconds) / 60000.0`이 정답.

## 06. 계층형 질의 → [[계층형질의]] · [[재귀CTE]]

**계층형 질의(Hierarchical Query)** = 동일 테이블 안에 상위-하위 관계(예: 관리자-사원)가 들어 있는 **순환 구조 데이터**를 펼쳐 조회. 부모 컬럼이 NULL인 행이 Root.

```
        A (Root, ReportsTo=NULL, lvl 0)
       /|\
      B C D        ← A의 직속 부하 (lvl 1)
        |
        E          ← C의 직속 부하 (lvl 2)
```

### 06.1 Oracle — CONNECT BY
```sql
SELECT LEVEL, 사원번호, 관리자
FROM 직원
START WITH 관리자 IS NULL          -- 루트 지정
CONNECT BY PRIOR 사원번호 = 관리자;  -- 상위↔하위 연결
```
- `LEVEL`(깊이, 루트=1), `CONNECT_BY_ROOT`(루트 값), `CONNECT_BY_ISLEAF`(리프 0/1), `SYS_CONNECT_BY_PATH(컬럼,구분자)`(루트→현재 경로).
- `LPAD(' ', 4*(LEVEL-1))`로 계층 들여쓰기.

### 06.2 SQLite/표준 — 재귀 CTE (WITH RECURSIVE)
SQLite는 CONNECT BY 미지원 → **`WITH RECURSIVE`로 대체**. **앵커 쿼리**(루트, lvl=0)에서 시작 → `UNION ALL` → **재귀 쿼리**(직속 부하를 찾아 lvl+1) → 매칭이 없을 때까지 반복.

**(5-1) 기본 보고 체계 전체 조회** ✅ 실제 답지(lecture 5-1 / 노션 동일):
```sql
WITH RECURSIVE emp_hierarchy(
    EmployeeId, FirstName, LastName, Title, ReportsTo, lvl
) AS (
    -- Anchor: 최상위(Root)
    SELECT EmployeeId, FirstName, LastName, Title, ReportsTo, 0 AS lvl
    FROM employees
    WHERE ReportsTo IS NULL
    UNION ALL
    -- Recursive: 직속 부하 반복 탐색
    SELECT e.EmployeeId, e.FirstName, e.LastName,
           e.Title, e.ReportsTo, h.lvl + 1
    FROM employees e
    JOIN emp_hierarchy h ON e.ReportsTo = h.EmployeeId
)
SELECT lvl                                          AS 계층레벨,
       EmployeeId                                   AS 직원ID,
       SUBSTR('                ', 1, lvl * 4)
           || FirstName || ' ' || LastName          AS 직원명,
       Title                                        AS 직책,
       ReportsTo                                    AS 관리자ID
FROM emp_hierarchy
ORDER BY lvl, EmployeeId;
```

**(5-3) 경로(PATH) 추적 + Leaf/Branch 판별** ✅(lecture 5-3 / 노션 동일, 핵심 발췌):
```sql
-- CTE에 path 컬럼 추가: 앵커 path = 이름, 재귀 path = 부모path || ' > ' || 이름
SELECT lvl AS 계층레벨, EmployeeId AS 직원ID, path AS 조직경로, Title AS 직책,
       CASE WHEN EmployeeId NOT IN (
                SELECT ReportsTo FROM employees WHERE ReportsTo IS NOT NULL
            ) THEN 'Leaf' ELSE 'Branch' END AS 노드유형
FROM emp_path
ORDER BY path;
```

> 라이브: 앵커 = `ReportsTo IS NULL` 루트, 재귀 = 상위 EmployeeId = 하위 ReportsTo 매칭하며 레벨 증가. SUBSTR 공백으로 계층 들여쓰기(환경에 따라 의도대로 안 보일 수 있음). 5-2는 계층 결과에 Customer/Invoice 조인+GROUP BY를 결합(직원별 담당 고객수·매출), 5-4는 레벨별 인원수에 UNION ALL로 합계 행 추가. 강사는 타이핑 추종이 어려워 코드 제공 중심으로 전환.
>
> ⚠ **DBMS 차이**: 계층형은 Oracle `CONNECT BY` vs SQL Server 2005+/MariaDB 10.2+/SQLite의 `WITH RECURSIVE` 두 갈래. → [[계층형질의]]·[[재귀CTE]] 노트 참조.

## 보충

📌 **UNION vs UNION ALL은 "중복 제거" 하나로 갈린다.** 중복이 없거나 중복 제거가 필요 없으면 UNION ALL이 빠르다(정렬·중복비교 생략). 소계/합계 행 붙이기엔 UNION ALL이 정석.

📌 **ORDER BY는 집합 연산 전체 결과에 단 한 번.** 각 SELECT 뒤에 붙이면 안 된다(공통 규칙 4). 정렬을 보장하려면 반드시 맨 끝에 명시.

📌 **DBMS 호환성 한 줄 요약**: INTERSECT/EXCEPT는 MySQL 미지원, EXCEPT = Oracle MINUS(MariaDB 10.3+). 계층형은 Oracle CONNECT BY ↔ 표준 WITH RECURSIVE. SQLite는 집합 4종 + 재귀 CTE 모두 지원하나 CONNECT BY는 미지원.

📌 **재귀 CTE의 종료 조건은 "더 이상 매칭되는 하위가 없을 때".** 자기참조 데이터에 사이클이 있으면 무한 반복 위험 → 데이터 무결성(루트 NULL, 사이클 없음) 전제.

📌 **lecture.sql 원문 버그 2건은 보정형으로 표기**(위 05 주석): 4-2 확인3 orphan `);`, 1-4(a) `/ 10000`. 실행 정답은 노션 답지/보정 쿼리 기준.
