OS가 컴퓨터에서 하는 일과 리눅스 터미널 사용법. 1~6교시 통합 강의로, 이론을 중심으로 하고 후반에 Git Bash로 리눅스 명령어를 직접 쳐보는 실습이 곁들여졌다.

## 01. 운영체제 (OS)

**OS(Operating System)** 는 하드웨어와 앱 사이에서 자원을 관리하는 시스템 소프트웨어다. 앱이 CPU·메모리·디스크를 직접 건드리지 않아도 되게 중간에서 교통정리한다.

컴퓨터를 구성하는 3가지 핵심 하드웨어:

| 구성 요소 | 역할 | 특성 |
|:---|:---|:---|
| **CPU** | 모든 계산을 처리하는 두뇌 | 매우 빠름 |
| **메모리 (RAM)** | 실행 중 데이터 임시 저장 | **휘발성** — 전원 끄면 사라짐 |
| **보조기억장치 (SSD·HDD)** | 파일 영구 저장 | **비휘발성** — 전원 꺼도 유지 |

→ "메모리 부족" = RAM 부족 / "용량 부족" = SSD 부족. 다른 문제다.

**OS가 관리하는 4가지**:

| 기능 | 하는 일 |
|:---|:---|
| **프로세스 관리** | 실행 중인 프로그램 생성·스케줄링·종료 (02장) |
| **메모리 관리** | 각 프로세스에 메모리 할당·보호 (02장) |
| **파일 시스템 관리** | 데이터 저장·검색·권한 (03장) |
| **네트워크 관리** | 포트·통신 자원 제어 (07장) |

**OS별 특성**: Windows는 일반 사용자 중심, Linux는 서버 환경에서 특히 많이 쓰임(개발·배포에 강함), macOS는 Unix 계열이라 Linux와 명령어가 비슷한 면이 있다. (자세한 관계는 맨 아래 [보충](#보충) 참조)

## 02. 프로세스와 스레드

**프로그램**: 디스크에 저장된 파일 상태 (아직 실행 안 된 것)
**프로세스**: 프로그램이 실행되어 메모리에 올라간 상태

```
카카오톡 앱 아이콘 = 프로그램
화면에 떠서 동작 중인 카카오톡 = 프로세스
```

같은 프로그램을 두 번 실행하면 두 개의 독립 프로세스가 생긴다.

**스레드**: 프로세스 안에서 실제로 일하는 단위. 크롬 탭 하나가 별도 프로세스인 이유 = 탭이 죽어도 다른 탭에 영향 없게.

**멀티프로세싱 / 멀티스레딩**: 작업을 여러 프로세스·스레드로 나눠 병렬 처리하면 속도가 빨라진다. 반복 작업이나 [[크롤링]]처럼 기다리는 시간이 많은 작업에서 특히 효과가 크다.

프로세스 메모리 구조:

```
┌──────────┐
│  Stack   │ ← 함수 호출, 지역 변수 (자동 관리)
├──────────┤
│   Heap   │ ← 동적 데이터 (직접 관리 — 메모리 누수 주의)
├──────────┤
│   Data   │ ← 전역 변수 (프로그램 내내 유지)
├──────────┤
│   Code   │ ← 실행할 명령어 (읽기 전용, 컴파일된 코드)
└──────────┘
```

> **컴파일(Compile)**: 사람이 쓴 코드를 기계(CPU)가 이해하는 기계어로 변환하는 과정. Code 영역에 올라가는 건 이렇게 변환된 결과다.

**가상 메모리**: RAM이 부족할 때 SSD 일부를 RAM처럼 사용. 그래서 8GB RAM 컴퓨터도 8GB 이상 프로그램 실행 가능 (느려지지만).

## 03. 파일 시스템

리눅스 철학: **"모든 것은 파일이다"** — 텍스트, 설정, 장치, 소켓 모두 파일로 취급.

| 개념 | 설명 | 예시 |
|:---|:---|:---|
| **절대 경로** | 루트(/)부터 전체 주소 | `/home/user/문서` |
| **상대 경로** | 현재 위치 기준 | `./파일`, `../Desktop` |
| **숨김 파일** | `.`으로 시작 | `.bashrc`, `.ssh` |

**파일 메타데이터**: 파일은 이름뿐 아니라 유형·위치·크기·**권한**·생성/수정 시간 같은 정보를 함께 갖는다. **디렉터리(폴더)** 도 사실은 그 안에 든 파일들의 정보를 담는 특수한 파일이다.

**파일 권한 (Permission)**:

```bash
$ ls -al
-rwxr-xr--  파일명
 ↑↑↑ ↑↑↑ ↑↑↑
 소유자 그룹 기타

r=읽기(4)  w=쓰기(2)  x=실행(1)
chmod 755 파일  →  소유자(7=rwx), 그룹(5=r-x), 기타(5=r-x)
chmod 644 파일  →  소유자(6=rw-), 그룹(4=r--), 기타(4=r--)
```

**링크와 마운트** (둘 다 "다른 곳에 연결"이지만 별개 개념):

- **링크(Link)**: Windows 바로가기처럼 원본 파일에 접근하는 또 다른 경로. 리눅스에는 **심볼릭 링크**(바로가기와 거의 같음)와 **하드 링크**(같은 실체를 가리키는 또 다른 이름)가 있다.
- **마운트(Mount)**: USB·외장디스크 같은 물리 장치(또는 다른 저장공간)를 특정 디렉터리에 **연결해서 OS가 그 안을 들여다볼 수 있게** 하는 작업. 예) **구글 코랩에서 구글 드라이브를 마운트**하면 코랩이 내 드라이브 파일을 자기 폴더처럼 읽고 쓴다.

## 04. 리눅스 핵심 명령어

**위치·탐색**:
```bash
pwd                  # 현재 위치 출력
ls -al               # 파일 목록 (숨김 포함 + 상세 정보)
cd ~/Desktop         # 바탕화면으로 이동
cd ..                # 상위 폴더로
```

**파일·폴더 관리**:
```bash
mkdir mydir          # 폴더 생성
mkdir -p a/b/c       # 중첩 폴더 한번에
touch hello.txt      # 빈 파일 생성
cp a.txt b.txt       # 복사
mv a.txt b.txt       # 이동 또는 이름 변경
rm a.txt             # 삭제 (휴지통 없이 영구 삭제!)
rm -r mydir          # 폴더째 삭제
```

**파일 내용 확인**:
```bash
cat a.txt            # 전체 출력
head -20 a.txt       # 앞 20줄
tail -20 a.txt       # 뒤 20줄
tail -f server.log   # 실시간 로그 모니터링
grep "error" log.txt # "error" 포함 줄만 출력
grep -n "error" log  # 줄 번호 포함
```

**파이프(|) — 명령어 연결**:
```bash
# 앞 명령의 출력을 뒷 명령의 입력으로 전달
ps -aux | grep python       # 실행 중 프로세스 중 python만
cat log.txt | grep "404"    # 로그에서 404 에러만
ls -al | grep ".py"         # .py 파일만 필터링
```

**프로세스 관리**:
```bash
ps -aux              # 전체 프로세스 목록
top                  # 실시간 CPU·메모리 사용량
kill -9 1234         # PID 1234 강제 종료
```

## 05. 예약 작업과 원격 접속

**cron — 반복 예약 실행**:

```bash
crontab -e           # 예약 작업 편집기 열기

# 형식: 분 시 일 월 요일 명령어
0  9  *  *  1  /backup.sh      # 매주 월요일 오전 9시
*/5  *  *  *  *  /check.sh     # 5분마다
0  0  1  *  *  /monthly.sh     # 매월 1일 자정
```

**SSH — 원격 접속**:

```bash
ssh user@192.168.0.1           # IP로 접속
ssh user@server.example.com    # 도메인으로 접속
```

서버 관리, AWS EC2 접속, GitHub Actions 배포 모두 SSH 기반.

## 06. 정규표현식 (Regex)

특정 패턴의 문자열을 찾는 규칙. grep과 함께 자주 쓴다.

| 패턴 | 의미 | 예시 |
|:---:|:---|:---|
| `.` | 임의 문자 1개 | `a.b` → acb, a1b |
| `*` | 앞 문자 0번 이상 반복 | `ab*` → a, ab, abb |
| `[0-9]` | 숫자 하나 | 전화번호 패턴 |
| `^` | 문자열 시작 | `^010` → 010으로 시작 |
| `$` | 문자열 끝 | `.txt$` → .txt로 끝남 |

```bash
grep "^ERROR" server.log     # ERROR로 시작하는 줄
grep "[0-9]\{3\}" data.txt   # 숫자 3개 연속인 줄
```

## 07. 포트와 컨테이너 (네트워크·배포 맛보기)

> OS의 네 번째 기능인 **네트워크 관리**와 맞닿는 부분. 라이브에서 강사가 말로 강조한 현업 맥락이다.

### 포트(Port)와 포트 충돌

**포트**는 한 컴퓨터(IP) 안에서 프로그램끼리 통신을 구분하는 번호다. 웹 주소(URL)에도 들어 있지만 기본 포트는 보통 숨겨져 있다.

- 예) **Jupyter Notebook 기본 포트 8888**. 이미 다른 프로그램이 8888을 쓰고 있으면 **포트 충돌**이 나서 실행이 안 된다.
- 일부 프로그램은 충돌이 나면 **다음 빈 포트(8889…)를 자동으로 잡아준다**.

→ [[포트]] 참조

### 컨테이너와 쿠버네티스

- **컨테이너([[Docker]])**: 코드·라이브러리·설정을 한 상자에 담아 **OS에 관계없이 어디서나 똑같은 개발 환경**으로 띄우는 기술. "내 컴퓨터에선 되는데 서버에선 안 돼" 문제를 없앤다. 보안·운영상 이유로 서비스를 컨테이너 단위로 **분리**하는 게 일반적이다.
- **쿠버네티스([[쿠버네티스]])**: 컨테이너가 많아지면 일일이 관리하기 어렵다. 여러 컨테이너를 **자동으로 배치·감시·복구·확장**해주는 통합 관리 도구.

> 강사 강조: **명령어 암기보다 리눅스/OS 원리(프로세스·포트 등) 이해가 우선.** "쿠버네티스만 외우는 학습"은 면접에서 한계가 있다.

## 08. Git Bash로 첫 리눅스 실습

Git을 설치하면 Windows에서도 **Git Bash**로 리눅스 명령어를 연습할 수 있다. (별도 우분투/서버 없이 바로 손에 익히기)

```bash
# 바탕화면 우클릭 → 추가 옵션 표시 → "Open Git Bash Here"
mkdir newfolder        # 폴더 생성
cd newfolder           # 이동 (Tab 자동완성 활용)
touch 2026-05-27.txt   # 빈 파일 생성
ls                     # 목록 확인
```

> 강사 팁: 초반에는 **복사·붙여넣기 대신 직접 타이핑**으로 손에 익혀라. `cd`에서 `Tab` 자동완성도 습관 들이기.

## 보충

📌 **`rm -rf /`**: 루트 폴더 전체 강제 삭제. 절대 실행 금지. 인터넷에서 "재미로" 알려주는 악의적인 명령어.

📌 **컨텍스트 스위칭**: CPU는 실제로 한 번에 하나의 프로세스만 처리. OS가 ms 단위로 빠르게 전환해서 동시에 돌아가는 것처럼 보이게 함. 전환할 때마다 현재 상태를 저장·복원하는 비용 발생.

📌 **macOS와 Linux는 "사촌"**: 둘 다 **Unix 철학을 공유하는 Unix 계열(Unix-like)** 이라 터미널 명령어가 비슷하다. 다만 macOS는 **Darwin/BSD** 계열이고 Linux는 **독립적으로 만든 커널**이라, "비슷하지만 같은 OS는 아니다". (라이브에서 "macOS는 Linux와 유사하나 다르다"고 설명한 부분의 정확한 배경)

📌 **"Linux = 서버용"은 단순화**: Linux는 서버에서 점유율이 압도적이라 그렇게 불리지만, 데스크탑·임베디드·안드로이드(커널)까지 폭넓게 쓰인다. "서버에서 특히 많이 쓰임"이 더 정확하다.

📌 **[explainshell.com](https://explainshell.com/)**: 모르는 명령어 붙여넣으면 각 옵션을 설명해줌. 리눅스 입문자 필수 북마크.
