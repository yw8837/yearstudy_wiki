# 외래키 (FOREIGN KEY)

**정의**: 다른 테이블의 [[기본키]]를 **참조**하는 컬럼. 테이블 사이의 **관계**를 정의하고 참조 무결성을 보장한다.

---

## 왜 필요한가

[[관계형데이터베이스]]는 데이터를 여러 테이블로 나눠 저장한다. 그 테이블들을 **올바르게 연결**하고, "존재하지 않는 부모를 가리키는 잘못된 데이터"를 막으려면 외래키가 필요하다.

---

## 어떻게 작동하나

```sql
CREATE TABLE professor (
    prof_id VARCHAR(10) PRIMARY KEY,
    dept_id VARCHAR(10),
    FOREIGN KEY (dept_id) REFERENCES department(dept_id)   -- department의 PK 참조
);
```

- FK 값은 **부모 테이블의 PK에 존재하는 값**이거나 **NULL**만 가능.
- 없는 값을 넣으면 → 참조 무결성 위반(에러).

```sql
-- 존재하지 않는 학과 'GHOST' 참조 → ❌ 에러
INSERT INTO student (student_id, name, dept_id, grade)
VALUES ('S9998', '유령학생', 'GHOST', 1);
```

---

## 실제 예시

- `school_db`: professor/student의 `dept_id` → department, course의 `prof_id` → professor, enrollment의 `student_id`·`course_id` → student·course.

---

## 자주 헷갈리는 것

**[[기본키]] vs 외래키.** PK는 "이 테이블의 식별자"(NOT NULL+UNIQUE), FK는 "다른 테이블의 PK를 가리키는 컬럼"(NULL 허용).

**⚠ SQLite는 FK가 기본 OFF.** `PRAGMA foreign_keys = ON;`을 커넥션 직후 선언해야 FK 제약이 실제로 작동한다.

**DROP 순서.** FK가 있으면 부모를 먼저 못 지운다 → 자식 → 부모 역순으로 [[DROP TABLE]].
