# 실무 문법 패턴 정리

실무에서 자주 쓰는 파이썬 심화 문법 6가지를 **섹션별로 한눈에**. 자세한 설명은 개념 페이지 링크에서.

> 강의 출처: [[0604-실무문법패턴]] · 상세: [[컴프리헨션]] · [[람다]] · [[정렬]]

---

## 1. f-string → [[문자열]]

```python
name, salary = "Alice", 6500
f"{name}님 {salary}만원"     # 변수·식을 { } 안에
f"{3.14159:.2f}"             # 3.14    소수점 2자리
f"{1234567:,}"               # 1,234,567  천 단위 콤마
f"{0.123:.1%}"               # 12.3%   퍼센트
f"{'INFO':>7}"               # 오른쪽 정렬 7칸
```

- 문자열 앞에 **`f`** + `{ }` 안에 변수·식을 넣는 출력 포매팅 (Python 3.6+)
- `:.2f`(소수), `:,`(콤마), `:%`(퍼센트), `:>7`(정렬) — 표·로그 출력에 유용

## 2. 리스트 컴프리헨션 → [[컴프리헨션]]

```python
[x**2 for x in range(5)]              # 기본: [0,1,4,9,16]
[x for x in seq if x > 0]             # 필터: 조건 맞는 것만 (if 뒤)
["합격" if s>=60 else "불합격" for s in scores]   # 변환: if-else (앞)
```

- `for` 반복으로 리스트 만드는 걸 **한 줄로** 압축
- ⚠️ **필터 `if`는 뒤**, **`if-else`는 앞** — 위치가 다름!

## 3. sorted — 정렬 → [[정렬]]

```python
sorted(scores, reverse=True)                 # 내림차순 (원본 유지)
sorted(words, key=len)                       # 글자 수 기준
sorted(data, key=lambda m: m["salary"])      # 특정 키 기준
sorted(data, key=lambda m: (m["team"], -m["salary"]))  # 다중 기준
```

- `sorted()`=원본 유지하고 새 리스트 반환 / `list.sort()`=원본 변경
- **`key`**=무엇을 기준으로 정렬할지. 튜플 `(기준1, 기준2)`로 다중 정렬

## 4. enumerate — 인덱스 + 값

```python
for i, season in enumerate(["봄","여름"]):     # 0 봄 / 1 여름
    print(i, season)
for rank, team in enumerate(teams, start=1):  # 1번부터 (순위)
    print(rank, team)
```

- 반복하면서 **인덱스와 값을 동시에** 꺼냄
- `range(len(...))`보다 깔끔. `start=1`로 시작 번호 지정

## 5. lambda · map · filter → [[람다]]

```python
square = lambda x: x**2               # 이름 없는 한 줄 함수
list(map(lambda x: x*2, nums))        # 각 요소에 함수 적용
list(filter(lambda x: x%2==0, nums))  # 조건 맞는 것만 (짝수)
```

- **lambda**=한 줄짜리 익명 함수 (`def`로 풀어 쓸 수 있음)
- `map`/`filter` 결과는 **`list()`로 감싸야** 보임. 복잡하면 `def`가 가독성↑

## 6. `__name__` → [[모듈과패키지]]

```python
def add(a, b): return a + b

if __name__ == "__main__":     # 이 파일을 직접 실행할 때만
    print(add(3, 4))           # import되면 이 줄은 안 돌아감
```

- 파일을 **직접 실행할 때만** 동작하는 블록 (import 시 제외)
- "정의 코드"와 "실행 코드"를 분리 — 모듈로 재사용하면서 테스트도 가능
