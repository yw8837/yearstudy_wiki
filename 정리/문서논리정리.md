# 문서·기획 논리 정리 (SCQA · 피라미드 · MECE)

바바라 민토 『논리의 기술』 기반 보고/기획 논리틀을 **한눈에**. 상세는 개념 페이지 링크에서.

> 강의 출처: [[0605-생성형AI기초]] (E 섹션) · 상세: [[SCQA]] · [[피라미드원칙]] · [[MECE]]

---

## 1. 큰 그림 — 결론부터, 탑다운

```
보고/발표 = 현황 설명이 아니라 '의사결정을 구하는 행위'
→ 상대는 바쁘다 → 결론부터 말한다 (피라미드 원칙)
도입부는 SCQA로 깔고, 본론은 피라미드 + 근거는 MECE
```

---

## 2. SCQA — 도입부 논리 → [[SCQA]]

```
S 상황   : 모두 동의하는 배경 사실      "3분기 매출 5% 증가"
C 전개   : S와 모순·충돌되는 문제(긴장)  "그런데 영업이익률은 하락"
Q 질문   : C가 부르는 핵심 질문         "왜 수익성이 떨어지나?"
A 답변   : Q의 결론(핵심 메시지)        "원가 구조 개선이 시급"
```

- **가장 어려운 건 C.** C를 잘 만들면 **Q·A가 자동으로 따라온다.**
- C는 단순 현황이 아니라 **"이대로면 닥칠 위기"** 까지 담아야 한다.
- 실무에선 이해관계자·통제 불가 외부 변수(예: HBM 수급) 때문에 C가 더 어렵다.

## 3. 피라미드 원칙 → [[피라미드원칙]]

```
        [ 결론 = SCQA의 A ]      ← 맨 위에 먼저
       /        |        \
   [근거1]   [근거2]   [근거3]   ← 결론을 떠받침 (MECE)
```

- 결론을 한 문장으로 꼭대기에, 그 아래 근거 3개 내외, 다시 그 아래 세부.
- 컨설팅·기획·정부 부서까지 쓰는 표준.

## 4. MECE → [[MECE]]

```
중복 없이(상호 배타) + 누락 없이(전체 포괄)
→ 근거 3개는 서로 안 겹치고, 모두 결론(탑)을 향한다
```

- 양이 아니라 **분류 기준** 의 문제. 기준을 먼저 정하면 쉬워진다.
- 사고는 연역·귀납 병행. 실무에선 중복·누락이 생각보다 많다.

---

## 5. 실습 — 전략 컨설팅 리포트

```
시나리오: 로테이션 소개팅 100회, 애프터 성공 0회, 외모·경제력 준수, 이유 모름
요구: SCQA + 피라미드 + MECE로 성공 전략 리포트 작성
```

**강사 피드백 (핵심):**
- 품질은 프롬프트 형식보다 **구체적 상황 맥락** 제공 여부가 좌우.
- **S와 C가 섞이거나 C가 단순 현상 설명** 에 그치는 실수가 흔함.
- 상담자 관점 관찰 가설을 더해 구체화 (예: 대화 지분율 7:3, 해결사 태도 버리기, 만남을 평가 아닌 소통으로 재프레이밍).
- **출력물을 그대로 쓰지 말고 SCQA를 보고 수정·보완** → [[HumanInTheLoop]].
