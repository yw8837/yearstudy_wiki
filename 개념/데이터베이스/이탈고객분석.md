# 이탈고객(Churn) 분석

**정의**: 한동안 구매·활동이 없는 **이탈 위험 고객을 데이터로 선별**하는 분석. 마지막 활동일과 기준일의 차이, 재주문 간격 등을 계산해 리텐션 대상을 찾는다. 마케팅·쇼핑몰 분석의 단골 주제(라이브13 §3).

---

## 왜 필요한가

신규 유치보다 **기존 고객 유지(리텐션)** 가 효율적이라, "곧 떠날 것 같은 고객"을 미리 찾아 케어해야 한다. SQL로 "마지막 구매 후 오래 지난 고객"을 정의·추출하는 것이 출발점.

---

## 어떻게 작동하나

핵심 3요소: **`MAX(주문일)`** + **기준일 일수 차([[strftime julianday|julianday]])** + **[[HAVING]] 필터**.

```sql
-- 5개월 이상 미구매 이탈 후보 — classicmodels
SELECT c.customerName, c.country,
       MAX(o.orderDate) AS LastOrderDate,
       CAST(julianday('2005-05-31') - julianday(MAX(o.orderDate)) AS INTEGER) AS DaysSinceLast
FROM customers c JOIN orders o ON c.customerNumber = o.customerNumber
GROUP BY c.customerNumber
HAVING MAX(o.orderDate) < '2005-01-01'        -- 2005 이후 구매=활성, 그 전까지만=이탈
ORDER BY DaysSinceLast DESC;
```

- 기준일 `2005-05-31` = 데이터의 마지막 주문일. `2005-01-01` 이후 구매하면 활성, 그 전까지만 산 고객이 이탈 후보.

---

## 실제 예시 (재주문 간격 — LAG)

```sql
-- 직전 주문과의 간격이 큰 고객 = 이탈 위험 — classicmodels
... LAG(o.orderDate,1) OVER (PARTITION BY c.customerNumber ORDER BY o.orderDate) AS prevDate ...
WHERE prevDate IS NOT NULL                    -- 첫 주문은 비교 대상 없음 → 제외
ORDER BY DaysSincePrevOrder DESC;
```

---

## 자주 헷갈리는 것

**첫 주문은 NULL**: [[LAG LEAD|LAG]]로 직전 주문일을 가져오면 첫 주문은 prevDate가 NULL → `WHERE prevDate IS NOT NULL`로 제외.

**전체 vs 상대 비교**: 단순 "오래 안 산 고객"보다, **같은 국가 동료(peer)의 평균보다 더 오래 안 산 고객**으로 좁히면 진짜 이탈자에 가깝다(라이브13 §3.2, 셀프조인+서브쿼리 종합).
