# 06/04 · 파이썬 라이브러리 활용

남이 만든 강력한 도구를 **가져다 쓰고**, 내가 만든 코드를 **PyPI에 배포해 전 세계에 공유**하는 법. 한 줄 요약: **`pip install`로 도구를 빌려 쓰고, `uv`+`hatchling`+`twine`으로 내 패키지를 PyPI에 올린다(테스트 통과 → 버전 올리며 배포).**

> 이날 4~6교시는 강사가 실제로 PyPI에 올린 패키지 **`mathlib-evanjjh`**(3모듈·실제 v0.1.5 배포)를 예제로 배포 전 과정을 따라갔다. 라이브 시연 자체는 인증 메일 문제로 막혔지만, 패키지는 사전/이후에 실제 배포되어 `pip install`로 설치된다.

## 01. 라이브러리란

**라이브러리 = 누군가 미리 만들어 둔 코드 묶음.** 바퀴를 다시 발명하지 않는 게 핵심. 기본 문법만으로는 시각화·크롤링·AI 같은 고급 기능 구현이 어렵다 → 라이브러리 활용이 필수.

| 구분 | 설명 | 예시 |
|:---|:---|:---|
| **표준 라이브러리** | 파이썬 기본 내장 (설치 불필요) | `math`·`random`·`datetime`·`os`·`json` |
| **외부 라이브러리** | 따로 설치해서 사용 | `numpy`·`pandas`·`requests`·`matplotlib` |

대표 외부: **numpy**(배열계산)·**pandas**(표 데이터)·**matplotlib/seaborn**(시각화)·**requests**(웹요청)·**scikit-learn**(머신러닝)·**BeautifulSoup**(크롤링).

> 도서관 비유: 필요한 책만 골라 빌리듯, 필요한 라이브러리만 골라 쓴다. 전 세계 라이브러리는 **PyPI**(Python Package Index) 창고에 모여 있고 `pip`로 내려받는다. → [[크롤링]]

→ [[파이썬라이브러리]] 참조

## 02. 모듈 · 패키지 · 라이브러리 · 프레임워크

배포를 이해하려면 이 4단계 포함 관계부터 잡아야 한다.

| 용어 | 정의 | 단위 |
|:---|:---|:---|
| **모듈**(Module) | 함수·클래스·변수를 담은 **단일 `.py` 파일** | 파일 |
| **패키지**(Package) | 여러 모듈을 묶은 **폴더** (`__init__.py` 필요) | 폴더 |
| **라이브러리**(Library) | 패키지를 포함한 더 큰 **배포 단위** (문서·매뉴얼 포함, "상품화된 코드") | 배포물 |
| **프레임워크**(Framework) | 여러 사람이 공동 개발·기여하는 더 큰 구조 | 생태계 |

> 포함 관계: 모듈(`.py`) ⊂ 패키지(폴더) ⊂ 라이브러리(배포 단위). → [[모듈과패키지]]

## 03. 설치 · 사용 — `pip` / `import`

```bash
pip install pandas            # 설치
pip install pandas==2.2.0     # 특정 버전
pip install --upgrade pandas  # 업그레이드
pip list                      # 설치 목록
pip freeze > requirements.txt # 의존성 목록 저장
pip install -r requirements.txt   # 그대로 한 번에 설치
```

> 우리 과정은 **uv**로 관리: `uv add pandas` · `uv sync`. `requirements.txt`로 한 번에 설치하는 방식은 구형 PC에서 수십 분 걸리기도 한다 → **uv가 더 빠르고 편리**. → [[uv]]

```python
import pandas as pd          # 관례 별칭(as)
import numpy as np

df = pd.DataFrame({"이름": ["A","B"], "점수": [95, 82]})
print(df["점수"].mean())      # 88.5
print(pd.__version__)         # 버전 확인 습관 (문서·검색·질문 시 기준)
```

> 💡 **import 후 `__version__`으로 버전 확인하는 습관.** 라이브러리는 버전마다 동작이 다르고, 문서·AI 답변도 특정 버전 기준으로 안내한다. 버전이 다르면 경고·오작동이 날 수 있다.

## 04. 내 패키지를 PyPI에 배포 — `mathlib-evanjjh` 실전

내가 만든 코드도 패키지로 만들어 올리면 누구나 `pip install` 가능. 이날은 사칙연산 클래스 패키지 **`mathlib-evanjjh`**(실제 PyPI 배포본, 3모듈)를 예제로 전 과정을 따라갔다. 자세한 절차·주의는 → **[[PyPI배포]]**

**전체 흐름 (한눈에)**

```
PyPI 계정·API 토큰 발급
  → GitHub repo 생성(Public · .gitignore Python · MIT)
  → src 레이아웃 + __init__.py
  → uv init / uv add --dev pytest twine
  → pyproject.toml(hatchling) 메타정보 작성
  → 코드 작성(Arithmetic 등) + pytest 통과
  → ~/.pypirc 에 토큰 저장(절대 git 커밋 금지)
  → version bump → twine upload dist/*
```

**① src 레이아웃** — 배포명(하이픈)과 import명(언더스코어)을 구분한다.

```
mathlib-evanjjh/            # 배포명: 하이픈
├─ src/
│  └─ mathlib_evanjjh/      # import명(폴더명): 언더스코어 — 하이픈 불가
│     ├─ __init__.py
│     ├─ arithmetic.py      # 실제 배포본 3모듈:
│     ├─ geometric.py       #   arithmetic / geometric / trigonometry
│     └─ trigonometry.py
├─ tests/
│  └─ test_arithmetic.py
├─ pyproject.toml
└─ README.md
```

```bash
uv init .
uv add --dev pytest twine     # 테스트·업로드 도구
```

**② pyproject.toml** (hatchling 빌드 백엔드)

```toml
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[project]
name = "mathlib-evanjjh"
version = "0.1.0"
authors = [{ name = "EvanJJH", email = "you@example.com" }]
description = "A class-based utility package for arithmetic, geometric sequences, and trigonometry"
readme = "README.md"
requires-python = ">=3.8"
```

> ⚠️ `authors`의 email은 **예시값**으로 둘 것. (강의 원자료엔 실제 메일이 있었으나 공개 산출물엔 `you@example.com`처럼 치환)

**③ 클래스 작성 → ④ pytest 테스트 통과 → 배포**

```python
# src/mathlib_evanjjh/arithmetic.py
class Arithmetic:
    def __init__(self, a, b):
        self.a, self.b = a, b
    def add(self):      return self.a + self.b
    def subtract(self): return self.a - self.b
    def multiply(self): return self.a * self.b
    def divide(self):
        if self.b == 0:
            raise ValueError("0으로 나눌 수 없습니다.")
        return self.a / self.b
```

```bash
uv run pytest          # 테스트 전부 통과해야 배포 진행 → [[pytest]]
```

**⑤ 버전 bump → twine 업로드** (★ 핵심)

```bash
# ~/.pypirc  (홈 디렉터리, git 커밋 절대 금지!)
# [pypi]
# username = __token__
# password = pypi-...        ← 발급받은 토큰(1회만 표시)

uv run twine upload dist/*
```

> 🔑 **버전 지속 업데이트가 핵심**: 기능을 추가할 때마다 `version`을 올린다(`0.1.0 → 0.2.0 → …`). **동일 버전 재업로드는 불가** → 변경하면 반드시 bump. 이 패키지도 점진적으로 올라가 **실제 v0.1.5**까지 배포됐다.

**작동 확인** (배포된 3모듈 — 설치는 하이픈, import는 언더스코어)

```python
!pip install mathlib-evanjjh        # → mathlib_evanjjh-0.1.5 설치
from mathlib_evanjjh.arithmetic import Arithmetic
from mathlib_evanjjh.geometric import GeometricSequence
from mathlib_evanjjh.trigonometry import Trigonometry

print(Arithmetic(10, 2).add())          # 12
print(GeometricSequence(first=1, ratio=2, n=5).generate())  # [1, 2, 4, 8, 16]
print(Trigonometry(30).sin())           # 0.5
```

## 보충

📌 **왜 코드를 공개(배포)하나**: 커뮤니티 기여 + 포트폴리오·취업 경쟁력. 강사 메시지 — "회사=학교가 아니다", 오픈소스 기여가 확실한 검증 근거다. 개발 지망생은 **작은 라이브러리 1개를 직접 배포**(src/`__init__.py` 구조 + pytest 통과 + 버전 점진 업)해보길 권장.

📌 **`.pypirc`는 git에 절대 커밋 금지** — 토큰이 그대로 노출된다. `.gitignore`로 막고, 토큰은 발급 시 1회만 보이니 즉시 안전 보관. → [[API키보안]]

📌 **빌드 도구 — uv 흐름 우선**: 이 과정은 `uv add --dev pytest twine` + **hatchling** 빌드 + `twine upload`를 메인으로 쓴다. 일반적으로 많이 보이는 `pip install build` → `python -m build`는 **대안**으로만 알아두면 된다.

📌 **TestPyPI**: 실수해도 안전한 연습용 저장소(test.pypi.org). 처음엔 여기 먼저 올려 흐름을 익히면 좋다.

📌 **시맨틱 버저닝**: `major.minor.patch`(예 `2.2.0`). 큰 변화=major, 기능추가=minor, 버그수정=patch.

> ℹ️ `geometric.GeometricSequence`·`trigonometry.Trigonometry`는 시그니처·출력만 확인됐고 **내부 구현 소스는 미확보** — 위 예시도 시그니처/출력까지만 인용한 것이다.
