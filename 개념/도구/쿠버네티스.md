# 쿠버네티스 (Kubernetes, k8s)

**정의**: 수많은 [[Docker]] 컨테이너를 **자동으로 배치·감시·복구·확장**해주는 컨테이너 통합 관리(오케스트레이션) 도구.

> 📌 **아직 깊게 다루지 않은 미리보기**입니다. 컨테이너의 "다음 단계"로 개념만 가볍게. (라이브 강의에서 흐름상 언급)

---

## 왜 필요한가

[[Docker]]로 서비스를 컨테이너 한두 개로 띄우는 건 쉽다. 하지만 실제 서비스는 보안·운영상 이유로 기능별로 컨테이너를 **여러 개로 분리**하고, 트래픽이 늘면 컨테이너 수를 늘려야 한다. 컨테이너가 수십·수백 개가 되면 사람이 일일이 켜고 끄고 살펴볼 수 없다.

→ "컨테이너가 많아지면 통합 관리가 필요하다" → 그 역할을 쿠버네티스가 맡는다.

---

## 어떻게 작동하나

컨테이너들의 "관리자"가 되어 사람 대신 다음을 자동으로 처리한다.

| 기능 | 설명 |
|:---|:---|
| **배치(Scheduling)** | 어느 서버에 어떤 컨테이너를 띄울지 자동 결정 |
| **자가 복구(Self-healing)** | 컨테이너가 죽으면 자동으로 다시 띄움 |
| **확장(Scaling)** | 트래픽이 늘면 컨테이너 수를 자동으로 늘리고, 줄면 줄임 |
| **로드 밸런싱** | 들어온 요청을 여러 컨테이너에 고르게 분배 |

```
Docker        : 컨테이너 1개를 만든다·띄운다
Kubernetes    : 컨테이너 수백 개를 자동으로 관리한다
```

---

## 자주 헷갈리는 것

**"Docker vs 쿠버네티스, 둘 중 뭘 써야 하나"**: 경쟁 관계가 아니라 **단계**다. Docker로 컨테이너를 만들고, 그 컨테이너들을 쿠버네티스가 관리한다. 함께 쓴다.

**"쿠버네티스를 외우면 취업에 유리"**: 강사 강조 — 도구 명령어 암기보다 **리눅스/OS 원리(프로세스·[[포트]] 등) 이해가 먼저**다. 원리 없이 "쿠버네티스만 외우는 학습"은 면접에서 한계가 있다.

---

## 더 알면 좋은 것

📌 **오케스트레이션(Orchestration)**: 여러 컨테이너를 지휘자처럼 조율한다는 뜻. 쿠버네티스가 이 분야의 사실상 표준.

📌 **k8s**: Kubernetes의 줄임말. K와 s 사이 글자가 8개라 8로 줄여 쓴다.

📌 **매니지드 서비스**: 직접 구축이 복잡해서 클라우드의 관리형 서비스(AWS EKS, GCP GKE, Azure AKS)를 많이 쓴다.
