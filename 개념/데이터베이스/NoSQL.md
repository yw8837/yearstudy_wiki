# NoSQL (Not only SQL)

**정의**: 관계형 모델을 따르지 않는 DB. **미리 정의된 스키마가 없고**(유연한 스키마), 저장 형식에 제한이 적다. [[관계형데이터베이스]]와 대비된다.

---

## 왜 필요한가

데이터 구조가 일관적이지 않거나 자주 바뀌는 경우, 또는 이미지·자연어 같은 **비정형 데이터**를 대량으로 빠르게 저장해야 할 때. 정해진 표(스키마)에 억지로 끼워 넣기 어려운 데이터에 적합하다.

---

## 어떻게 작동하나

- **유연한 스키마**: 행마다 컬럼 구성이 달라도 된다. 미리 표 구조를 못박지 않는다.
- **수평 확장(scale-out)**: 서버를 늘려 분산 저장 → 대용량을 빠르게 처리.
- 저장 모델이 여러 가지: 문서(Document)·키값(Key-Value)·컬럼·그래프 등.

| 종류 | 모델 | 예 |
|:---|:---|:---|
| MongoDB | 문서(JSON 유사) | 유연한 레코드 |
| Redis | 키-값 | 캐시·세션 |
| Cassandra | 와이드 컬럼 | 대규모 분산 |

---

## 실제 예시

- 로그·센서 데이터처럼 구조가 자주 바뀌고 양이 많은 데이터를 MongoDB에 저장.
- 세션·캐시를 Redis 키-값으로 빠르게 읽고 쓰기.

---

## 자주 헷갈리는 것

**NoSQL = SQL 안 씀?** 아니다. "Not only SQL"(SQL만 쓰는 게 아니다)의 약자. 일부 NoSQL은 SQL 유사 질의를 지원한다.

**무조건 NoSQL이 빠르다?** 아니다. 무결성·정규화가 중요한 정형 데이터엔 [[관계형데이터베이스]]가 더 안전하고 적합하다. "분석에 어떤 DB를 쓸 것인가"의 선택 문제(강사 강조).

---

## 더 알면 좋은 것

📌 **공간(지도) 데이터는 PostgreSQL 추천**(강사, PostGIS 맥락). 분석 현업에선 클라우드 DW(BigQuery 등)도 많이 쓴다.
📌 RDB의 강점은 **명확한 스키마·정규화·무결성**, NoSQL의 강점은 **유연성·수평 확장**. 트레이드오프다.
