# 집합 연산자 (Set Operator)

**정의**: **조인을 쓰지 않고** 둘 이상의 SELECT 결과를 **세로로 결합**하는 연산자. UNION / UNION ALL / INTERSECT / EXCEPT 4종.

---

## 왜 필요한가

서로 다른 테이블(또는 같은 테이블의 다른 조건)에서 나온 결과를 **하나의 결과셋으로 합치거나, 겹치는/빠지는 부분만** 뽑고 싶을 때 쓴다. JOIN이 행을 가로로 잇는다면, 집합 연산자는 결과를 세로로 쌓는다.

---

## 어떻게 작동하나

```sql
SELECT FirstName, LastName FROM employees
UNION
SELECT FirstName, LastName FROM customers
ORDER BY FirstName;          -- ORDER BY 는 전체 결과에 1번만
```

**공통 규칙 4가지**:
1. 각 SELECT의 **컬럼 수가 동일**.
2. 대응 컬럼의 **데이터 타입이 호환**.
3. **첫 번째 쿼리의 컬럼명**이 최종 결과셋 컬럼명.
4. **ORDER BY는 최종 결합 결과에만** (각 SELECT 뒤가 아니라 맨 끝 1번).

| 연산자 | 중복 제거 | 정렬 | 역할 |
|:---|:---:|:---:|:---|
| [[UNION]] | O | O | 합집합 |
| [[UNION ALL]] | X | X | 합집합(빠름) |
| [[INTERSECT]] | O | O | 교집합 |
| [[EXCEPT]] | O | O | 차집합 |

---

## 실제 예시

- 직원 + 고객 통합 명단([[UNION]]), 2009·2010 모두 구매한 고객([[INTERSECT]]), 이탈 고객([[EXCEPT]]).

---

## 자주 헷갈리는 것

**JOIN vs 집합 연산자**: JOIN은 키로 행을 가로 연결(컬럼이 늘어남), 집합 연산자는 같은 모양의 결과를 세로로 결합(행이 늘거나 걸러짐). "컬럼 수·타입이 맞아야 한다"는 제약은 집합 연산자만의 특징.

---

## 더 알면 좋은 것

📌 **DBMS 호환성**: SQLite는 4종 모두 지원. **MySQL은 INTERSECT/EXCEPT 미지원**(JOIN 등으로 대체). EXCEPT는 Oracle에서 `MINUS`, MariaDB는 10.3+부터 지원.
