# 복합 기본키 (Composite Key)

**정의**: **2개 이상의 컬럼을 묶어** 하나의 [[기본키]]로 삼는 것. 한 컬럼만으론 행을 유일하게 구분할 수 없을 때 쓴다.

---

## 왜 필요한가

수강·주문 이력처럼 **연결(N:M 중간) 테이블**은 단일 컬럼으로 행이 안 구분된다. "학생+강의 조합"이 한 번만 존재해야 하므로 두 컬럼을 함께 PK로 잡는다.

---

## 어떻게 작동하나

```sql
CREATE TABLE enrollment (
    student_id  VARCHAR(10),
    course_id   VARCHAR(10),
    enroll_date DATE NOT NULL,
    CONSTRAINT enrollment_pk PRIMARY KEY (student_id, course_id),  -- 복합 PK
    FOREIGN KEY (student_id) REFERENCES student(student_id),
    FOREIGN KEY (course_id)  REFERENCES course(course_id)
);
```

- `(student_id, course_id)` **조합**이 유일해야 한다 → 같은 학생이 같은 강의를 두 번 수강 등록 못 함.

```sql
-- 같은 (student_id, course_id) 재INSERT → ❌ 복합 PK 중복
```

---

## 실제 예시

- `enrollment(student_id, course_id)` — student–course의 N:M을 푸는 연결 테이블의 PK.

---

## 자주 헷갈리는 것

**컬럼 옆에 못 쓴다.** 단일 PK는 `student_id VARCHAR(10) PRIMARY KEY`로 컬럼 옆에 쓰지만, 복합 PK는 **테이블 레벨**에서 `PRIMARY KEY (a, b)`로 따로 정의한다. 이때 [[CONSTRAINT명시]]로 이름을 주면 깔끔하다.

**복합 PK ≠ FK 2개.** enrollment는 복합 PK이면서 동시에 [[외래키]] 2개를 가진다 — 별개의 제약이다.

---

## 더 알면 좋은 것
