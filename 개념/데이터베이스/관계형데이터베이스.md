# 관계형 데이터베이스 (RDB)

**정의**: 하나 이상의 **테이블**로 이루어지며, 서로 **연결된 데이터**를 가지는 데이터베이스. [[SQL]]로 제어한다.

---

## 왜 필요한가

데이터를 의미 단위(고객·주문·상품)로 **테이블에 나눠 저장**하고, 테이블 간 관계로 연결하면 중복을 줄이고 무결성을 지키기 쉽다. 가장 널리 쓰이는 DB 형태다.

---

## 어떻게 작동하나

**테이블 = 컬럼(Column) + 레코드(Record)로 구성된 표.** 모든 테이블은 고유 이름으로 구분된다.

| 사번 | 이름 | 성별 |
|:---|:---|:---|
| 001 | 홍길동 | 남성 |
| 002 | 김철수 | 남성 |
| 003 | 김영희 | 여성 |

- **레코드(행)** = 가로 한 줄(하나의 데이터 단위).
- **컬럼(열)** = 세로 한 칸(속성). 실무에선 **필드(field)** 라고도 부른다.
- 테이블끼리는 키([[기본키]]·외래키)로 연결되며, 합칠 때 [[JOIN]]을 쓴다.

---

## 실제 예시

- chinook DB: `artists` — `albums` — `tracks`가 ArtistId·AlbumId로 연결.
- 고객(`customers`)과 주문(`invoices`)이 CustomerId로 연결.

---

## 자주 헷갈리는 것

**컬럼 vs 레코드**: 컬럼은 "어떤 속성"(세로), 레코드는 "한 건의 데이터"(가로).

**관계형 vs 비관계형(NoSQL)**: 관계형은 정해진 스키마의 표, NoSQL은 유연한 문서·키값 구조.

---

## 더 알면 좋은 것

📌 **정규화**: 중복·수정 이상·무결성 문제를 줄이려 테이블을 나누는 설계. 나눈 걸 조회 시 다시 [[JOIN]]으로 합친다.
