# Docker

**정의**: 애플리케이션과 실행에 필요한 모든 것(코드·라이브러리·설정)을 **컨테이너**라는 상자에 담아, **어느 컴퓨터에서나 똑같이 실행**되게 하는 도구.

> 📌 **아직 수업에서 다루지 않은 미리보기**입니다. 개념만 가볍게. (실제 배울 때 보강 예정)

---

## 왜 필요한가

"내 컴퓨터에선 되는데 서버에선 안 돼" 문제를 없앤다. 컨테이너는 OS·라이브러리 버전까지 통째로 담아서, 개발 PC든 서버든 **환경이 완전히 동일**해진다. 배포·협업이 훨씬 쉬워진다.

---

## 어떻게 작동하나

- **이미지(Image)**: 실행 환경의 "설계도/스냅샷" (예: python 3.13 + 라이브러리)
- **컨테이너(Container)**: 이미지를 실제로 띄운 "실행 중인 인스턴스"
- **Dockerfile**: 이미지를 만드는 레시피(텍스트 파일)

```bash
docker build -t myapp .     # Dockerfile로 이미지 빌드
docker run myapp            # 이미지를 컨테이너로 실행
docker ps                   # 실행 중인 컨테이너 목록
docker images               # 이미지 목록
```

---

## 자주 헷갈리는 것

**이미지 vs 컨테이너**: 이미지 = 설계도(정적), 컨테이너 = 그걸 실행한 상태(동적). 이미지 하나로 컨테이너 여러 개 가능.

**컨테이너 vs 가상머신(VM)**: VM은 OS를 통째로 가상화(무겁다). 컨테이너는 OS 커널은 공유하고 **앱 실행 환경만 격리**(가볍고 빠르다). → [[운영체제]]

---

## 더 알면 좋은 것

📌 **Docker Hub**: 이미지를 공유하는 저장소(GitHub의 이미지 버전). `docker pull python` 처럼 받아 씀.

📌 **docker-compose**: 여러 컨테이너(웹+DB 등)를 한 번에 정의·실행하는 도구.
