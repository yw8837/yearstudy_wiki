# 계층형 질의 (Hierarchical Query)

**정의**: **동일 테이블 안에 상위-하위(부모-자식) 관계**가 들어 있는 순환 구조 데이터를 펼쳐 조회하는 질의. 대표 사례: 관리자-사원, 카테고리-하위카테고리.

---

## 왜 필요한가

조직도·댓글 트리·분류 체계처럼 한 테이블이 자기 자신을 참조하는(self-reference) 데이터를 "누가 누구 밑인지, 몇 단계 깊이인지" 순서대로 조회하려면 일반 SELECT로는 부족하다.

---

## 어떻게 작동하나

부모 컬럼(예: ReportsTo)이 **NULL인 행이 Root(최상위)**. 거기서 시작해 하위로 한 단계씩 펼친다.

```
        A (Root, ReportsTo=NULL, lvl 0)
       /|\
      B C D     ← lvl 1
        |
        E       ← lvl 2
```

두 가지 구현 방식(DBMS별):
- **Oracle**: `CONNECT BY` (`START WITH 부모 IS NULL CONNECT BY PRIOR 자식 = 부모`)
- **SQL Server / MariaDB / MySQL / SQLite**: [[재귀CTE]] (`WITH RECURSIVE`)

---

## 실제 예시

- 직원 보고 체계 전체 출력(레벨별 들여쓰기), 조직 경로(`A > C > E`) 추적, 리프(최하위) 직원 판별.

---

## 자주 헷갈리는 것

**CONNECT BY vs WITH RECURSIVE**: 결과는 같지만 문법 갈래가 다르다. Oracle 전용 `CONNECT BY`는 `LEVEL`·`CONNECT_BY_ROOT`·`SYS_CONNECT_BY_PATH` 같은 전용 키워드를 제공하고, 표준 SQL 진영은 [[재귀CTE]]로 동일 기능을 구현한다. SQLite는 **CONNECT BY 미지원** → WITH RECURSIVE만 사용.

---

## 더 알면 좋은 것

📌 Oracle 전용 키워드: `LEVEL`(깊이, 루트=1), `CONNECT_BY_ROOT`(루트 값), `CONNECT_BY_ISLEAF`(리프 여부 0/1), `SYS_CONNECT_BY_PATH(컬럼, 구분자)`(루트→현재 경로). `LPAD`로 계층 들여쓰기.
