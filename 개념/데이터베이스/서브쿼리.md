# 서브쿼리 (Subquery)

**정의**: 하나의 쿼리 안에 포함된 **또 하나의 쿼리.** 메인쿼리가 서브쿼리를 포함하는 종속 관계.

---

## 왜 필요한가

"평균보다 긴 트랙", "elice 급여보다 많이 받는 사람"처럼 **기준 값을 미리 모를 때** 그 값을 쿼리로 구해 조건에 넣을 수 있다.

```sql
-- elice 급여를 몰라도 검색
SELECT * FROM employee
WHERE 급여 > (SELECT 급여 FROM employee WHERE 이름 = 'elice');
```

---

## 어떻게 작동하나

**반환 형태별 분류**:
- **단일행** = 1개 값 반환. 연산자 `= <> > >= < <=`.
- **다중행** = 2행 이상. `IN`(하나라도 만족), `ANY`(하나라도, 비교 가능), `ALL`(모두, 비교 가능).
  - ⚠️ **SQLite는 ANY/ALL 미지원 → MIN/MAX로 대체** (ALL→MAX, ANY→MIN).

**위치별 분류**: WHERE절 / [[스칼라서브쿼리]](SELECT절) / FROM절(파생, 별칭 필수) / [[EXISTS]](상관).

**주의사항**: ① 괄호와 함께 ② 안에서 **ORDER BY 불가** ③ 연산자의 **오른쪽** ④ **SELECT문만**.

---

## 실제 예시

```sql
SELECT Name FROM tracks
WHERE Milliseconds > (SELECT AVG(Milliseconds) FROM tracks);  -- 평균보다 긴 트랙
```

---

## 자주 헷갈리는 것

**핵심 학습법**: **"분할 → 각각 실행 → 합치기".** 메인/서브를 먼저 텍스트로 구분하고, 서브쿼리만 따로 실행해 확인한 뒤 합친다(바로 코딩 금지).

**조인 vs 서브쿼리**: 같은 결과가 나오는 경우가 많다. "정답은 하나가 아니며" 결과 기준으로 이해.

---

## 더 알면 좋은 것

📌 **상관 서브쿼리(correlated)**: 바깥 행을 참조하는 서브쿼리([[스칼라서브쿼리]]·[[EXISTS]]). 바깥 행마다 다시 평가된다.
