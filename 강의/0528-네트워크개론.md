# 05/28 · 네트워크 개론

네트워크 이론 집중. OSI 7계층부터 실제 통신 흐름, 보안까지. 개념이 많아 연결고리 잡는 게 핵심.

---

## 01. 네트워크 기본

**네트워크** = 기기들이 연결되어 데이터를 주고받는 구조 전체. Wi-Fi, 블루투스, 회사 내부망, 인터넷 모두 네트워크다.

**네트워크 규모**:

| 유형 | 범위 | 예시 |
|:---|:---|:---|
| PAN | 개인 기기 ~10m | 블루투스 이어폰 |
| LAN | 건물·캠퍼스 | 회사 Wi-Fi |
| WAN | 국가·대륙 이상 | 인터넷 |

**통신 방식**:
- **유니캐스트**: 1:1 (카카오톡 DM)
- **멀티캐스트**: 1:그룹 (단체 카톡방)
- **브로드캐스트**: 1:전체 (DHCP가 IP 할당할 때 전체에 뿌림)

---

## 02. OSI 7계층

네트워크 통신을 7단계로 나눈 국제 표준. 각 계층이 독립적으로 역할 수행.

```
7. 응용(Application)    ← HTTP, DNS, FTP
6. 표현(Presentation)   ← SSL/TLS, 데이터 형식 변환
5. 세션(Session)        ← 연결 유지·관리
────────────────────────────────────────
4. 전송(Transport)      ← TCP, UDP
3. 네트워크(Network)    ← IP, 라우팅
2. 데이터링크           ← Ethernet, Wi-Fi, MAC
1. 물리(Physical)       ← 케이블, 신호
```

실무에서는 OSI보다 **TCP/IP 4계층** (응용/전송/인터넷/네트워크액세스)을 더 많이 쓴다. OSI는 교육용 개념 모델.

**데이터 전송 흐름**: 보낼 때 각 계층에서 헤더 추가(포장), 받을 때 역순으로 제거(뜯기).

## 03. IP 주소

인터넷에 연결된 모든 기기의 고유 주소.

| 종류 | 형태 | 특징 |
|:---|:---|:---|
| **IPv4** | `192.168.0.1` | 32비트, 약 42억 개 → 거의 소진 |
| **IPv6** | `2001:0db8::1` | 128비트, 사실상 무제한 |

**공인 IP vs 사설 IP**:
```
인터넷
  ↕ 공인 IP (123.45.67.89) ← 전 세계 유일
공유기 ← NAT로 변환
  ↓ 사설 IP (192.168.0.x) ← 내부에서만
PC·폰·TV
```

집 Wi-Fi에서 `192.168.0.x`가 뜨는 이유 = 사설 IP. 공유기가 하나의 공인 IP를 여러 기기와 공유.

## 04. DNS와 DHCP

**DNS**: 도메인 이름 → IP 주소 변환. `google.com` 입력 → DNS가 `142.250.x.x`로 변환 → 해당 서버 접속.

```
브라우저: "google.com의 IP 알려줘"
DNS 서버: "142.250.x.x입니다"
브라우저: 해당 IP로 접속
```
이 과정 전체가 0.1초 이내. DNS = 인터넷 전화번호부.

**DHCP**: 기기가 네트워크 연결 시 IP를 자동 할당하는 프로토콜. Wi-Fi 연결하면 IP가 자동으로 잡히는 이유.

→ [[DNS]] 참조

## 05. TCP vs UDP

| | TCP | UDP |
|:---|:---|:---|
| 연결 | 3-way handshake 후 통신 | 바로 전송 |
| 신뢰성 | 보장 (손실 시 재전송) | 없음 (손실 허용) |
| 속도 | 느림 | 빠름 |
| 사용 | 웹, 이메일, 파일 전송 | 스트리밍, 게임, DNS |

**TCP 3-way Handshake** — 연결 수립 과정:

```
클라이언트 → "연결할게요" (SYN)       → 서버
클라이언트 ← "OK, 나도 준비됨" (SYN+ACK) ← 서버
클라이언트 → "확인, 시작" (ACK)       → 서버
```

왜 3번? 2번이면 클라이언트만 확인, 3번이 양쪽 모두 확인하는 최소값.

## 06. HTTP

웹 통신 규약. 무상태(Stateless) — 서버는 이전 요청을 기억 못함.

**요청 구조**:
```
GET /api/users/1 HTTP/1.1
Host: api.example.com
Authorization: Bearer eyJ...

(바디 없음, GET은 보통 바디 생략)
```

**상태 코드**:

| 범위 | 의미 | 대표 코드 |
|:---:|:---|:---|
| 2xx | 성공 | 200 OK, 201 Created |
| 4xx | 클라이언트 오류 | **401** 인증필요, **403** 권한없음, **404** 없음 |
| 5xx | 서버 오류 | **500** 서버오류 |

## 07. 보안 — 해시

**해시**: 데이터를 고정 길이 문자열로 변환하는 단방향 함수. 원본으로 되돌릴 수 없다.

```
"비밀번호1234" → SHA-256 → "03ac674216f..."
"비밀번호1235" → SHA-256 → "a665a45920..." ← 완전히 다른 결과
```

활용:
- **비밀번호 저장**: DB에 원본 대신 해시값 저장 → 해킹당해도 원본 노출 안 됨
- **파일 무결성**: 다운로드 전후 해시값 비교 → 변조 여부 확인

현재 표준: **SHA-256** (MD5·SHA-1은 이미 깨짐, 사용 금지)

## 08. 인증 — 쿠키·세션·JWT

HTTP가 기억 못하는 문제를 보완하는 세 가지 방법:

**쿠키**: 서버가 브라우저에 저장하는 작은 파일. 이후 요청마다 자동 첨부.

**세션**: 정보는 서버에, 클라이언트엔 ID만 발급. 쿠키보다 안전하지만 서버 부하.

**JWT**: 정보를 토큰 안에 직접 담음. 서버 저장 불필요 → 서버 여러 대로 확장할 때 유리.

```
JWT 구조: Header.Payload.Signature
Payload = 사용자 정보 (누구나 읽을 수 있음, 위조만 방지)
```

| 방식 | 저장 위치 | 보안 | 서버 부하 |
|:---|:---:|:---:|:---:|
| 쿠키 | 브라우저 | 낮음 | 없음 |
| 세션 | 서버 | 높음 | 있음 |
| JWT | 클라이언트 | 중간 | 없음 |

→ [[쿠키와세션]] 참조

## 보충

📌 **인증 vs 인가**: 인증(Authentication) = "당신이 누구냐?" / 인가(Authorization) = "무엇을 할 수 있냐?". 로그인 = 인증, 관리자 페이지 접근 가능 여부 = 인가.

📌 **PUT vs PATCH**: 수업에서 "PUT이 보안 이슈가 있어서 PATCH가 나왔다"고 했는데 부정확. PUT = 전체 교체, PATCH = 부분 수정. 보안 문제 아님.

📌 **DNS가 UDP를 쓰는 이유**: DNS 질의·응답이 짧아서 TCP 연결(3-way handshake)이 오버헤드. 응답 512바이트 초과 시만 TCP 사용.

📌 **레인보우 테이블**: 자주 쓰는 비밀번호의 해시값을 미리 계산해놓은 표. 단순 SHA-256 저장만으로는 뚫림 → 솔트(Salt) 추가 필수.
