# 06/12 · 그룹 함수 & 윈도우 함수

SQL 데이터 다루기 4번째 차시. **윈도우 함수**(`OVER` 절로 행과 행의 관계를 정의 — 원본 행 수를 유지한 채 순위·집계·이전/이후 참조·비율 계산)와 **그룹 함수**(`GROUP BY` 집계에 소계·총계 레벨을 추가 — ROLLUP/CUBE/GROUPING SETS)를 배운 날. 다만 **수업은 슬라이드 목차 순서대로 흐르지 않았다** — 오전은 지난 Day04 **이탈고객 분석 복습**으로 시작해 윈도우 함수 개념을 잡고 순위→PARTITION→누적합→LAG/LEAD 순으로 실습했고, **그룹 함수(ROLLUP/CUBE)는 오후 후반에 개념만** 다뤘다. 아래 본문은 그 **라이브 진행 순서**를 축으로 삼는다.

> 🗂 **DB 2종 혼용 — 코드마다 라벨 확인.** chinook(음악 판매, 컬럼명 PascalCase: `CustomerId`·`InvoiceDate`) / classicmodels(모형 판매, camelCase: `customerNumber`·`orderDate`). 슬라이드 개념 예시는 가상 테이블 `EMPLOYEE`.
>
> 📌 **윈도우 함수는 SQLite 3.25.0+ 부터.** 실습 첫 줄 `SELECT sqlite_version();`로 버전 확인 권장. 그리고 **ROLLUP/CUBE/GROUPING SETS는 SQLite 미지원** → `UNION`/`UNION ALL`로 대체(슬라이드는 Oracle/MariaDB 문법으로 설명). → 아래 **보충** 절의 차이표 참고.

## 01. (복습) 이탈고객 분석 — Day04 문제5·12 → [[이탈고객분석]]

수업은 윈도우 함수 전에, 지난 차시 **이탈고객(Churn) 탐지** 복습으로 열렸다(라이브13 §3). 마케팅·쇼핑몰 분석에서 빈번한 실전 주제다.

**[Day04 문제5] 5개월 이상 미구매 이탈 후보 (GROUP BY + HAVING):** *(classicmodels)*
```sql
SELECT c.customerName, c.country,
       MAX(o.orderDate) AS LastOrderDate,
       CAST(julianday('2005-05-31') - julianday(MAX(o.orderDate)) AS INTEGER) AS DaysSinceLastOrder
FROM customers c
INNER JOIN orders o ON c.customerNumber = o.customerNumber
GROUP BY c.customerNumber, c.customerName, c.country
HAVING MAX(o.orderDate) < '2005-01-01'        -- 2005-01-01 이후 구매=활성, 그 전까지만=이탈후보
ORDER BY DaysSinceLastOrder DESC LIMIT 15;
```

- **기준일 2005-05-31** = 주문 테이블의 마지막 주문일. `julianday(기준일) - julianday(MAX(주문일))`로 마지막 구매 후 며칠 지났는지 계산. → [[strftime julianday]]
- 이탈 탐지 공식 = `MAX(orderDate)` + 일수 차 + `HAVING`으로 필터. → [[이탈고객분석]] · [[HAVING]]

**[Day04 문제12] 국가별 상대비교 종합 쿼리 (약 60줄):** SELF JOIN + EXISTS + 스칼라/인라인뷰 서브쿼리를 총망라한 ~60줄 쿼리. "전체 이탈"이 아니라 **같은 국가 동료(peer)와 비교해 평균보다 오래 안 산 고객만** 진짜 이탈자로 선별한다. 강사: "풀라는 문제가 아니라 **현업 복잡도 체감용**"(라이브13 §3.2). 전문은 실습 답지 참조.

→ [[이탈고객분석]] · [[SELF JOIN]] · [[HAVING]] · [[strftime julianday]] 참조

## 02. 윈도우 함수란? — "행을 줄이지 않는 집계" → [[윈도우함수]]

복습 후 본 주제로 진입(라이브13 §4.3). **윈도우 함수**의 한 줄 정의: **행과 행 사이의 관계를 정의하는 함수, `OVER` 절 필수, 집계해도 원본 행 수를 유지.**

```
[GROUP BY 집계]               [윈도우 함수]
국가  합계                     고객  국가  구매액  국가순위
KR    300   ← 행이 압축됨       A    KR   150    1
US    250                      B    KR   100    2     ← 원본 행 그대로 +컬럼만 추가
                               C    KR    50    3
                               D    US   250    1
```

- **GROUP BY는 행을 압축**(국가별 1행)하지만, **윈도우 함수는 원본 행을 그대로 두고 계산 컬럼만 옆에 붙인다.** 이게 핵심 차이. → [[윈도우함수]] · [[GROUP BY]]
- 기본 문법:
    ```sql
    SELECT 윈도우함수(인수)
    OVER ( [PARTITION BY 칼럼] [ORDER BY 절] [WINDOWING 절] )
    FROM 테이블;
    ```
- `OVER`의 3요소: **PARTITION BY**(전체를 소그룹으로 쪼개는 칸막이) / **ORDER BY**(소그룹 내 정렬) / **WINDOWING**(행 범위, ROWS/RANGE). → [[OVER절]] · [[PARTITION BY]] · [[윈도우프레임]]
- 지원: MySQL 8.0.22+, MariaDB 10.2+, **SQLite 3.25.0+**.

> ⚠ **SQLite 차원집계 제약(라이브13 §4.2).** 그룹 함수 ROLLUP/CUBE/GROUPING SETS는 SQLite 미지원 → UNION 대체. 이 사실을 윈도우 함수 들어가기 전에 먼저 짚고 감(그래서 오늘 그룹함수는 개념만, 실습은 윈도우 중심).

→ [[윈도우함수]] · [[OVER절]] · [[PARTITION BY]] · [[윈도우프레임]] 참조

## 03. 순위 함수 — RANK / DENSE_RANK / ROW_NUMBER → [[순위함수]]

가장 먼저 실습한 윈도우 함수(라이브13 §5.1). 셋의 차이는 **동률(같은 값) 처리 방식**이다.

| 함수 | 동률 처리 | 예시(값 동일 2개) |
|:---|:---|:---|
| **RANK** | 동률 동일순위, 다음 순위 **건너뜀** | 1, 2, 3, **3**, 5 |
| **DENSE_RANK** | 동률 동일순위, **안 건너뜀** | 1, 2, 3, **3**, 4 |
| **ROW_NUMBER** | 동률도 **고유 연속번호** | 1, 2, 3, 4, 5 |

**[문제1] 고객별 총구매액 순위 (3종 비교):** *(chinook)*
```sql
SELECT c.CustomerId,
       c.FirstName || ' ' || c.LastName AS CustomerName,
       c.Country,
       ROUND(SUM(i.Total), 2)                          AS TotalPurchase,
       RANK()       OVER (ORDER BY SUM(i.Total) DESC)   AS Rank,
       DENSE_RANK() OVER (ORDER BY SUM(i.Total) DESC)   AS DenseRank,
       ROW_NUMBER() OVER (ORDER BY SUM(i.Total) DESC)   AS RowNumber
FROM   customers c
JOIN   invoices  i ON c.CustomerId = i.CustomerId
GROUP BY c.CustomerId, c.FirstName, c.LastName, c.Country
ORDER BY TotalPurchase DESC LIMIT 10;
```

- **핵심 패턴(라이브13 §5.1):** 먼저 `GROUP BY`로 고객별 집계를 만든 뒤, **그 결과를 "해치지 않고" 윈도우 함수로 순위 컬럼만 추가**한다. `RANK() OVER (ORDER BY SUM(...))`처럼 OVER 안의 ORDER BY가 순위 기준.
- 슬라이드 예시(EMPLOYEE 급여): ELICE(10000)=1/1/1, JESSICA·JANNET(6000 동률)=3/3/3 vs 3/3/**4**, ROBERT(1500)=**6**/5/6. → RANK·DENSE_RANK·ROW_NUMBER가 동률에서 갈린다.

→ [[순위함수]] · [[RANK DENSE_RANK ROW_NUMBER]] · [[GROUP BY]] 참조

## 04. PARTITION BY — "칸막이 치고 그 안에서 다시" → [[PARTITION BY]]

순위 다음 실습(라이브13 §5.2, 과제 형태로 제시 후 함께 풀이). 강사 표현: **"칸막이를 치고 그 안에서 순위를 다시 매김".**

**[문제2] 국가별 고객 총구매액 순위:** *(chinook)*
```sql
SELECT c.Country,
       c.FirstName || ' ' || c.LastName AS CustomerName,
       ROUND(SUM(i.Total), 2)           AS TotalPurchase,
       RANK() OVER (
           PARTITION BY c.Country               -- 국가별로 칸막이
           ORDER BY SUM(i.Total) DESC
       ) AS CountryRank
FROM   customers c
JOIN   invoices i ON c.CustomerId = i.CustomerId
GROUP BY c.Country, c.CustomerId, c.FirstName, c.LastName
ORDER BY c.Country, CountryRank;
```

- `OVER (ORDER BY ...)` = **전체** 기준 순위. `OVER (PARTITION BY country ORDER BY ...)` = **국가별로 순위를 새로 1번부터** 매김.
- GROUP BY의 "그룹"과 헷갈리기 쉬운데, PARTITION BY는 행을 압축하지 않고 **순위 계산 범위만** 나눈다.

## 05. 서브쿼리 vs 윈도우 — 같은 행에 평균 붙이기 → [[집계윈도우]]

라이브13 §5.3. "각 행 옆에 그룹 평균을 붙이는" 같은 일을 스칼라 서브쿼리로도 / 윈도우로도 할 수 있는데, **윈도우가 더 간결**하다는 비교.

**[문제3] 국가별 평균 청구금액:** *(chinook)*
```sql
-- (A) 스칼라 서브쿼리 — 행마다 서브쿼리 재실행
SELECT i.InvoiceId, i.BillingCountry, i.Total,
       (SELECT ROUND(AVG(Total), 2) FROM invoices i2
        WHERE i2.BillingCountry = i.BillingCountry) AS CountryAvgTotal
FROM invoices i
ORDER BY i.BillingCountry, i.Total DESC;

-- (B) 윈도우 함수 — 한 줄로 간결 ✅
SELECT InvoiceId, BillingCountry, Total,
       ROUND(AVG(Total) OVER (PARTITION BY BillingCountry), 2) AS CountryAvgTotal
FROM invoices
ORDER BY BillingCountry, Total DESC;
```

- 일반 집계함수(SUM/AVG/MAX/MIN…)에 `OVER()`를 붙이면 **GROUP BY 없이도** 그룹 통계를 각 행에 붙일 수 있다. → [[집계윈도우]]
- (A)는 연관 서브쿼리라 행마다 재실행, (B)는 한 번에 처리. 결과는 같지만 윈도우가 읽기 쉽고 빠르다. → [[스칼라서브쿼리]] · [[연관서브쿼리]]

→ [[집계윈도우]] · [[집계함수]] · [[스칼라서브쿼리]] 참조

## 06. 누적합 (Running Total) — WINDOWING(ROWS BETWEEN) → [[누적합]]

라이브13 §5.4. **"창(window)의 너비/범위"** 개념을 잡는 핵심 실습. `ROWS BETWEEN ...`으로 어디부터 어디까지 더할지 정한다.

**[문제4] 전체합계 + 누적합계:** *(chinook)*
```sql
SELECT InvoiceId, InvoiceDate, Total,
       ROUND(SUM(Total) OVER (), 2)                AS GrandTotal,     -- 전체합 (창=전체)
       ROUND(SUM(Total) OVER (
           ORDER BY InvoiceDate
           ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW           -- 처음~현재 = 누적
       ), 2)                                       AS RunningTotal
FROM invoices
ORDER BY InvoiceDate LIMIT 20;
```

```
ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW   → [처음 ━━━●        ] 누적합
ROWS BETWEEN CURRENT ROW AND UNBOUNDED FOLLOWING   → [        ●━━━ 끝] 잔여합
```

- `UNBOUNDED PRECEDING ~ CURRENT ROW` = **처음부터 현재 행까지** = 누적합.
- 프레임을 `CURRENT ROW AND UNBOUNDED FOLLOWING`으로 바꾸면 **잔여합**(뒤로 갈수록 줄어듦)으로 값이 완전히 달라진다 → 창 범위 설정이 결과를 바꾼다는 걸 직접 실험(라이브13 §5.4).
- `SUM(Total) OVER ()` (빈 OVER) = 정렬·파티션 없이 **전체 합**. ⚠ 단, GROUP BY 결과 위에 `SUM() OVER()`를 다시 쓰면 의도와 다를 수 있음 → 아래 09절 GrandTotal 정정 참고.

→ [[누적합]] · [[윈도우프레임]] · [[이동평균]] 참조

## 07. FIRST_VALUE / LAST_VALUE — 파티션 첫/끝 값 → [[FIRST_VALUE LAST_VALUE]]

라이브13 §5.5. 국가별로 총액 오름차순 정렬했을 때, 첫 값(=최소) / 마지막 값(=최대)을 각 행에 붙인다.

**[문제5] 국가별 최소/최대 청구금액:** *(chinook)*
```sql
SELECT InvoiceId, BillingCountry, Total,
       FIRST_VALUE(Total) OVER (
           PARTITION BY BillingCountry ORDER BY Total ASC
           ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING   -- 전체 창 명시!
       ) AS CountryMinTotal,
       LAST_VALUE(Total) OVER (
           PARTITION BY BillingCountry ORDER BY Total ASC
           ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
       ) AS CountryMaxTotal
FROM invoices ORDER BY BillingCountry, Total;
```

> ⚠ **LAST_VALUE 함정.** `ORDER BY`를 쓰면 프레임 기본값이 `UNBOUNDED PRECEDING ~ CURRENT ROW`(현재 행까지)라서, LAST_VALUE가 "지금까지 중 마지막" = **현재 행 값**이 나와 의도한 최대값이 안 나온다. 반드시 `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`으로 **전체 창을 명시**해야 한다.

→ [[FIRST_VALUE LAST_VALUE]] · [[윈도우프레임]] · [[PARTITION BY]] 참조

## 08. LAG / LEAD — 이전·이후 행 참조 → [[LAG LEAD]]

라이브13 §5.6. **LAG = 이전 N번째 행, LEAD = 이후 N번째 행**의 값을 옆 컬럼으로 가져온다. 전월대비·주문간격·이동평균 분석의 핵심.

**[문제6] 이전/다음 청구금액:** *(chinook)*
```sql
SELECT InvoiceId, InvoiceDate, Total,
       LAG(Total,  1) OVER (ORDER BY InvoiceDate) AS PrevInvoiceTotal,   -- 직전 행 (첫 행은 NULL)
       LEAD(Total, 1) OVER (ORDER BY InvoiceDate) AS NextInvoiceTotal    -- 다음 행 (끝 행은 NULL)
FROM invoices ORDER BY InvoiceDate LIMIT 20;
```

- LAG → **첫 행**은 이전 값이 없어 `NULL`. LEAD → **마지막 행**은 이후 값이 없어 `NULL`.
- "전월/전일 대비", "누적" 같은 키워드가 나오면 윈도우 함수를 떠올릴 것(라이브46 §4.2).

**[문제7 — 자율실습] 전월 대비 매출 증감 (MoM):** *(chinook)* `strftime('%Y-%m', InvoiceDate)`로 연·월을 묶고 `LAG`로 전월 값을 가져와 증감 계산.
```sql
SELECT strftime('%Y-%m', InvoiceDate) AS YearMonth,
       ROUND(SUM(Total), 2)           AS MonthlyTotal,
       LAG(ROUND(SUM(Total),2),1) OVER (ORDER BY strftime('%Y-%m', InvoiceDate)) AS PrevMonthTotal,
       ROUND(SUM(Total) - LAG(SUM(Total),1) OVER (ORDER BY strftime('%Y-%m', InvoiceDate)), 2) AS MoM_Diff
FROM invoices GROUP BY strftime('%Y-%m', InvoiceDate) ORDER BY YearMonth;
```
> 증감액 = 이번달 − 전월, 증감률 = (이번달 − 전월) / 전월 (라이브46 §4.2). 강사가 직접 풀이 권장한 자율실습.

→ [[LAG LEAD]] · [[strftime julianday]] · [[누적합]] 참조

## 09. 비율 함수 — RATIO_TO_REPORT / PERCENT_RANK / CUME_DIST / NTILE → [[비율함수]]

라이브46 §4.1에서 문법 위주로 소개. 비율·백분위·등급 분할 함수들.

| 함수 | 의미 | 범위/비고 |
|:---|:---|:---|
| **RATIO_TO_REPORT** | 파티션 전체 SUM 대비 비율 | Oracle 전용. SQLite/MariaDB는 **`값 / SUM(값) OVER()`** 로 대체 |
| **PERCENT_RANK** | 순위 백분율 | `[0,1]`, **최고=0** 최저=1 |
| **CUME_DIST** | 누적 백분율(이하 건의 비율) | `(0,1]` |
| **NTILE(N)** | 정렬 후 **N등분** 그룹 번호 | 1~N |

**[문제9] 상위 고객 PERCENT_RANK / CUME_DIST:** *(chinook)*
```sql
SELECT c.CustomerId, c.FirstName || ' ' || c.LastName AS CustomerName,
       ROUND(SUM(i.Total), 2) AS TotalPurchase,
       ROUND(PERCENT_RANK() OVER (ORDER BY SUM(i.Total) DESC), 4) AS PctRank,
       ROUND(CUME_DIST()    OVER (ORDER BY SUM(i.Total) DESC), 4) AS CumeDist
FROM customers c JOIN invoices i ON c.CustomerId = i.CustomerId
GROUP BY c.CustomerId, c.FirstName, c.LastName
ORDER BY TotalPurchase DESC LIMIT 10;
```

**[문제10] 직원 고용일 3그룹 분류 (NTILE):** *(chinook)*
```sql
SELECT EmployeeId, FirstName || ' ' || LastName AS EmployeeName, Title, HireDate,
       NTILE(3) OVER (ORDER BY HireDate) AS HireGroup    -- 고용일 순 3등분
FROM employees ORDER BY HireDate;
```

> 💡 **학습법(라이브46 §5):** 모르는 함수(예: NTILE)는 **① 공식 문서 먼저 → ② 안 되면 LLM** 순서로. 코드 암기보다 **용어·개념·문제정의 능력**이 중요하다고 강사 강조.

### ⚠ GrandTotal 출제 오류 정정 (라이브46 §4.3)

**[문제8] 국가별 매출비율 — 강사 정정 동반:** *(chinook)*
```sql
SELECT BillingCountry,
       ROUND(SUM(Total), 2)                      AS CountryTotal,
       ROUND(SUM(Total) OVER (), 2)              AS GrandTotal,      -- ⚠ 의도와 다를 수 있음
       ROUND(SUM(Total) / SUM(Total) OVER (), 4) AS RevenueRatio
FROM invoices GROUP BY BillingCountry ORDER BY CountryTotal DESC;
```

> 강사가 **GrandTotal(전체합)이 이상하게 나오는 문제 + 출제 오류를 인정**했다(라이브46 §4.3). `GROUP BY` 결과 위에 다시 `SUM() OVER()`를 쓰면 전체합이 의도대로 안 나올 수 있다. **권장 대안 = 전체합을 스칼라 서브쿼리로 별도 산출해 분모로 쓰기:**
> ```sql
> ... SUM(Total) / (SELECT SUM(Total) FROM invoices) AS RevenueRatio ...
> ```
> 윈도우만으로 처리하려면 인라인뷰 등으로 복잡해진다. → [[문제4]]의 GrandTotal에도 동일 주의. → [[스칼라서브쿼리]]

→ [[비율함수]] · [[NTILE]] · [[PERCENT_RANK CUME_DIST]] · [[스칼라서브쿼리]] 참조

## 10. 그룹 함수 — ROLLUP / CUBE / GROUPING SETS (개념 + SQLite UNION 대체) → [[ROLLUP CUBE GROUPING_SETS]]

오후 후반에 **개념만** 다룬 부분(라이브46 §4.4). GROUP BY 집계에 **소계·총계 등 집계 레벨**을 더하는 함수들인데, **SQLite는 모두 미지원** → UNION 계열로 흉내낸다.

| 함수 | 생성 레벨 | SQLite 대체 |
|:---|:---|:---|
| **ROLLUP(A,B)** | (A,B)+(A)+전체 = **3레벨** | `UNION ALL` |
| **CUBE(A,B)** | (A,B)+(A)+(B)+전체 = **4레벨**(모든 조합) | `UNION` |
| **GROUPING SETS(A,B)** | (A)별 + (B)별 = **2레벨** | `UNION ALL` |

**[문제12] ROLLUP 대체 — 장르·미디어타입별 + 장르소계 + 전체:** *(chinook)*
```sql
-- (장르, 미디어타입) 조합
SELECT g.Name AS Genre, mt.Name AS MediaType,
       COUNT(t.TrackId) AS TrackCount, ROUND(AVG(t.UnitPrice),2) AS AvgPrice
FROM tracks t JOIN genres g ON t.GenreId=g.GenreId
              JOIN media_types mt ON t.MediaTypeId=mt.MediaTypeId
GROUP BY g.Name, mt.Name
UNION ALL
-- 장르별 소계 (MediaType=NULL)
SELECT g.Name, NULL, COUNT(t.TrackId), ROUND(AVG(t.UnitPrice),2)
FROM tracks t JOIN genres g ON t.GenreId=g.GenreId GROUP BY g.Name
UNION ALL
-- 전체 합계 (둘 다 NULL)
SELECT NULL, NULL, COUNT(TrackId), ROUND(AVG(UnitPrice),2) FROM tracks
ORDER BY Genre, MediaType;
```

- CUBE 대체(문제13)는 여기에 **미디어타입별 소계**를 한 블록 더 UNION(중복 제거 위해 `UNION ALL` 대신 `UNION`). GROUPING SETS 대체(문제14)는 장르별 + 미디어타입별 두 블록만 `UNION ALL`.
- 슬라이드의 Oracle 문법은 `GROUP BY ROLLUP(D.NAME, J.NAME)` / `CUBE(...)` / `GROUPING SETS(...)` 한 줄이면 끝나지만, **SQLite는 위처럼 SELECT를 여러 번 UNION**해야 해 코드가 길어진다(라이브13 §4.2). 그룹함수 실습은 Elice 플랫폼 예제 참고 권장.

→ [[ROLLUP CUBE GROUPING_SETS]] · [[GROUP BY]] · [[UNION]] · [[UNION ALL]] 참조

## 11. classicmodels 실전 — territory 순위·누적·NTILE·이탈 → [[순위함수]] · [[이탈고객분석]]

라이브46 §4.5~4.6. **여러 테이블 JOIN + 윈도우**의 실전 쿼리(코드 길고 복잡).

**[실전1] territory별 영업사원 실적 순위 (RANK + PARTITION BY):** *(classicmodels)* 5테이블 JOIN + `Shipped` 필터 + 지역(NA/EMEA/APAC)별 순위.
```sql
SELECT e.firstName || ' ' || e.lastName AS SalesRep, off.territory,
       COUNT(DISTINCT c.customerNumber) AS CustomerCount,
       ROUND(SUM(od.quantityOrdered * od.priceEach), 2) AS TotalSales,
       RANK() OVER (PARTITION BY off.territory
                    ORDER BY SUM(od.quantityOrdered * od.priceEach) DESC) AS TerritoryRank
FROM employees e
JOIN offices off ON e.officeCode = off.officeCode
JOIN customers c ON e.employeeNumber = c.salesRepEmployeeNumber
JOIN orders o ON c.customerNumber = o.customerNumber
JOIN orderdetails od ON o.orderNumber = od.orderNumber
WHERE e.jobTitle LIKE '%Sales Rep%' AND o.status = 'Shipped'
GROUP BY e.employeeNumber, e.firstName, e.lastName, off.territory
ORDER BY off.territory, TerritoryRank;
```

**[Day05 변형] 각 지역 1등만 추출 (인라인뷰 + WHERE rank=1):** *(classicmodels)*
```sql
SELECT * FROM ( /* 위 [실전1] 쿼리 그대로 */ ) a
WHERE a.TerritoryRank = 1;
```
> ⚠ **윈도우 함수 결과는 같은 레벨 WHERE로 못 거른다**(윈도우는 SELECT 단계에서 계산되므로). "1등만" 같은 필터는 **쿼리를 인라인뷰로 감싼 뒤 바깥에서 `WHERE rank=1`**(라이브46 §4.5).

**[실전2~3 / 시계열]:** 월별 누적매출(`SUM() OVER(ORDER BY YearMonth ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)`), 국가별 신용한도 `NTILE(3)` 등급, MoM 증감(`LAG`), **고객 재주문 간격**(`LAG(orderDate)` + `julianday` 차이 → 첫 주문은 NULL이라 제외, 간격 긴 고객 = 이탈 위험군), 결제 패턴 `LAG/LEAD`(4회 이상 고객). → [[누적합]] · [[NTILE]] · [[LAG LEAD]] · [[이탈고객분석]]

## 보충

📌 **윈도우 함수 vs GROUP BY — 한 문장 구분.** GROUP BY는 **행을 압축**(그룹당 1행), 윈도우 함수는 **원본 행을 유지하고 계산 컬럼만 추가**한다. "각 행 옆에 그룹 통계를 붙이고 싶다" → 윈도우. "그룹당 요약 한 줄" → GROUP BY.

📌 **OVER 절 3요소 정리.** `OVER(PARTITION BY 칸막이 ORDER BY 정렬 WINDOWING 행범위)`. PARTITION BY는 순위/집계 범위를 나누고(생략 시 전체), ORDER BY는 순위·누적의 기준, WINDOWING(`ROWS BETWEEN ...`)은 더할 행 범위를 정한다.

📌 **프레임 기본값 함정(LAST_VALUE).** `OVER`에 `ORDER BY`가 있고 `ROWS BETWEEN`을 생략하면 기본 프레임이 `UNBOUNDED PRECEDING ~ CURRENT ROW`다. 그래서 LAST_VALUE가 현재 행 값을 반환해 의도와 어긋난다 → **전체 최대/최소를 원하면 `... AND UNBOUNDED FOLLOWING`까지 명시**.

📌 **표준/Oracle ↔ SQLite 차이(이번 차시 핵심).**

| 항목 | 표준/Oracle (슬라이드) | SQLite (실습) |
|:---|:---|:---|
| 윈도우 함수 | 지원 | **3.25.0+** 부터 (`SELECT sqlite_version();`) |
| RATIO_TO_REPORT | `RATIO_TO_REPORT(x) OVER()` | **없음** → `x / SUM(x) OVER()` |
| ROLLUP | `GROUP BY ROLLUP(A,B)` | **없음** → `UNION ALL` (3레벨) |
| CUBE | `GROUP BY CUBE(A,B)` | **없음** → `UNION` (4레벨) |
| GROUPING SETS | `GROUP BY GROUPING SETS(A,B)` | **없음** → `UNION ALL` (2레벨) |
| 연·월 / 일수차 | `TO_CHAR`, 날짜 연산 | `strftime('%Y-%m', d)`, `julianday(a)-julianday(b)` |

📌 **GrandTotal은 스칼라 서브쿼리가 안전(강사 정정).** GROUP BY 결과 위에 `SUM() OVER()`로 전체합을 구하면 값이 의도와 달라질 수 있다(라이브46 §4.3, 강사 출제 오류 인정). 전체합/분모는 `(SELECT SUM(x) FROM 테이블)` 스칼라 서브쿼리로 빼는 걸 권장. → [[스칼라서브쿼리]]

📌 **시험 공지(라이브13 §6.1 / 라이브46 §6).** 다음 주 **월요일 = 윈도우 함수 중심 "라이트" 테스트**(개념 확인형), **화요일 = 종합 시험**(난도 있는 문제 포함 가능). 서브쿼리보다 **오늘 범위(윈도우)** 위주 출제 예고. 이후 수업은 ERD·정규화 등 이론/보충 예정.
