# 데이터베이스 — 정규화 (Normalization) 정리

> 출처: [[0616-데이터모델링과데이터베이스구현]]
> 상세: [[이상현상]] · [[정규화]] · [[함수종속]] · [[부분함수종속]] · [[이행함수종속]] · [[완전함수종속]] · [[결정자]] · [[1NF]] · [[2NF]] · [[3NF]] · [[BCNF]] · [[4NF]] · [[5NF]] · [[다치종속]] · [[조인종속]] · [[역정규화]] · [[MySQL]] · [[DCL]] · [[GRANT REVOKE]] · [[인덱스Index]] · [[데이터모델링]] · [[ERD]]

[[데이터모델링]]·[[ERD]]로 그린 설계를 **정제하는 규칙**. 중복을 줄여 [[이상현상]]을 제거한다. 실습 DBMS는 [[SQLite]](`normalization_compare`), 슬라이드 DB 구현은 [[MySQL]] 기준.

---

## 1. 왜 정규화인가 — 이상현상 → [[이상현상]]

| 이상 | 상황 | 예 |
|:---|:---|:---|
| 삽입 이상 | 관련 데이터 없으면 추가 불가 | 학생 없이 학과 등록 불가 |
| 갱신 이상 | 한 사실이 여러 행 중복 | 학과 건물 변경 시 전체 행 수정 |
| 삭제 이상 | 한 행 삭제로 정보 손실 | 마지막 학생 삭제 시 학과도 소멸 |

[[정규화]] = 이상현상 제거를 위한 구조화. **무결성↑·중복↓.** 단계: [[1NF]]→[[2NF]]→[[3NF]]→[[BCNF]]→[[4NF]]→[[5NF]].

---

## 2. 함수 종속 — 분해의 기준 → [[함수종속]]

```
함수종속        X → Y (X 알면 Y 하나로 결정)        학번 → 학생이름
완전함수종속    복합키 전체에 종속                  성적 → (학번+과목코드)
부분함수종속    복합키 일부에만 종속  → 2NF로 제거   학생이름 → 학번
이행함수종속    비키 속성 경유 간접  → 3NF로 제거   학번 → 학과코드 → 학과이름
```

[[결정자]] = X→Y의 X. [[BCNF]] 판정 기준("결정자이면서 후보키 아닌 것").

---

## 3. 단계별 분해 (1NF → 2NF → 3NF)

| 단계 | 제거 대상 | 결과 테이블 |
|:---|:---|:---|
| **[[1NF]]** | 다중값 → 원자값 | `student_course_1nf` (복합 PK) |
| **[[2NF]]** | [[부분함수종속]] | `student_2nf` / `course_2nf` / `enrollment` |
| **[[3NF]]** | [[이행함수종속]] | `department`/`professor`/`student`/`course`/`enrollment_3nf` |

- **1NF:** `course_ids='CS101,CS102'`(다중값) → 행 분리, **복합 PK `(student_id, course_id)`**. 학과·교수 정보는 여전히 행마다 중복.
- **2NF:** 학생/과목/수강 3분리. ⚠ 학과정보(`dept_*`)가 `student_2nf`에 잔존 → 이행 종속 남음.
- **3NF:** 학과·교수를 독립 테이블로 빼고 [[외래키|FK]] 연결 → 이행 종속 해소.

## 4. 정리 — BCNF · 4NF · 5NF · 역정규화

| 정규형 | 제거 대상 |
|:---|:---|
| [[BCNF]] | 결정자이면서 후보키 아닌 것 |
| [[4NF]] | [[다치종속]](독립적 다중값) |
| [[5NF]] | [[조인종속]](분해 후 재조인 시 가짜 튜플) |
| [[역정규화]] | (역방향) 성능 위해 의도적 중복 허용 |

🔑 **3NF는 타협 불가 기준선**(99% 응용 충분). [[역정규화]]는 read-heavy·OLAP(Star/Snowflake)·NoSQL에서 **성능 측정·근거** 있을 때만.

---

## 5. ★ 4단계 이상현상 비교 (normalization_compare 데모)

동일 데이터를 4단계 DB에 저장 → 갱신/삽입/삭제 시 이상 발생 비교.

| 단계 | 갱신(학과) | 갱신(교수) | 삽입 | 삭제 | 종합 |
|:---:|:---:|:---:|:---:|:---:|:---|
| 비정규화 | 존재 | 존재 | 존재 | 존재 | 이상 구조 |
| 1NF | 존재 | 존재 | 존재 | 존재 | 이상 구조 |
| 2NF | **잔존** | 정상 | 정상 | 정상 | 이행 종속 잔존 |
| 3NF | 정상 | 정상 | 정상 | 정상 | **정상** |

**핵심:** UI/입력이 같아도 정규화 단계에 따라 이상이 갈린다. **2NF는 학과 갱신 이상만 잔존**, 3NF에서 모두 해소 → 2NF↔3NF 차이의 직관적 증거.

## 6. DB 구현 (MySQL 기준) → [[MySQL]] · [[DCL]] · [[인덱스Index]]

- **설치/실행:** `choco/brew install mysql` → `net start mysql`/`mysql.server start` → `mysql -u root -p`.
- **DB 생성:** `CREATE DATABASE` / `SHOW DATABASES` / `USE` / `DROP DATABASE`.
- **[[DCL]]:** `CREATE USER ... IDENTIFIED BY` → `GRANT ... TO` → `FLUSH PRIVILEGES` → `SHOW GRANTS` / `REVOKE`. → [[GRANT REVOKE]]
- **[[인덱스Index]]:** `CREATE INDEX` / `SHOW INDEX` / `ALTER TABLE ... DROP INDEX`. 큰 테이블·변경 적음·WHERE/ORDER BY/JOIN·중복도 낮은 컬럼에 유리.

---

## ⚠ SQLite vs MySQL (슬라이드=MySQL ↔ 실습=SQLite)

| 항목 | MySQL | SQLite |
|:---|:---|:---|
| 사용자/권한 | GRANT/REVOKE/CREATE USER | **없음** |
| DB 단위 | CREATE/USE DATABASE | 없음(파일=DB) |
| 인덱스 조회 | `SHOW INDEX` | `PRAGMA index_list` |
| 인덱스 삭제 | `ALTER TABLE ... DROP INDEX` | `DROP INDEX 인덱스명;` |
| ENUM | `ENUM(...)` | 없음 → [[CHECK]] 대체 |
