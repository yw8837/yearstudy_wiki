# 프로세스 (Process)

**정의**: 실행 중인 프로그램. 디스크에 저장된 프로그램이 메모리에 올라가 CPU에 의해 실행되는 상태.

---

## 왜 필요한가

같은 카카오톡 앱이라도 실행 전(프로그램)과 실행 후(프로세스)는 다르다. 프로세스가 되면 OS로부터 메모리를 할당받고, CPU 시간을 받아서 동작한다.

---

## 어떻게 작동하나

### 프로그램 vs 프로세스

```
프로그램: /Applications/KakaoTalk.app  ← 디스크에 있는 파일
프로세스: 실행 중인 카카오톡           ← 메모리에 올라가 동작 중
```

같은 프로그램을 두 번 실행하면 두 개의 독립적인 프로세스가 생긴다.

### 프로세스 메모리 구조

```
높은 주소
┌─────────────┐
│   Stack     │ ← 함수 호출, 지역 변수 (자동 관리)
├─────────────┤
│     ↓       │
│     ↑       │
├─────────────┤
│    Heap     │ ← 동적 할당 데이터 (수동 관리)
├─────────────┤
│    Data     │ ← 전역 변수, 정적 변수
├─────────────┤
│    Code     │ ← 실행할 코드 (읽기 전용)
└─────────────┘
낮은 주소
```

- **Stack**: 함수 호출할 때마다 쌓이고, 함수 끝나면 자동 반환
- **Heap**: `malloc()`, `new` 등으로 직접 할당·해제. **메모리 누수** 주의
- **Data**: 프로그램 시작부터 끝까지 유지
- **Code**: 실행할 명령어. 변경 불가

### 스레드(Thread)

프로세스 안에서 실제로 일을 처리하는 단위. 하나의 프로세스에 여러 스레드가 있을 수 있다.

```
프로세스 (크롬)
├── 스레드 1: 화면 렌더링
├── 스레드 2: 네트워크 요청
├── 스레드 3: JavaScript 실행
└── 스레드 4: 다운로드 처리
```

스레드들은 프로세스의 메모리를 공유한다. 그래서 빠르지만 하나가 망가지면 전체에 영향.

| 비교 | 프로세스 | 스레드 |
|:---|:---|:---|
| 메모리 | 각자 독립 | 공유 |
| 생성 비용 | 무거움 | 가벼움 |
| 영향 범위 | 독립 (다른 프로세스 영향 없음) | 공유 (하나 오류 → 전체 영향 가능) |

### 작업 전환 (Context Switching)

CPU는 실제로 한 번에 하나의 프로세스만 처리한다. OS가 아주 빠르게(ms 단위) 프로세스를 전환해 동시에 실행되는 것처럼 보이게 한다.

```
[프로세스 A 실행] → [A 중단, 상태 저장] → [프로세스 B 실행] → [B 중단] → [A 재개]
```

전환할 때마다 현재 상태(레지스터 값 등)를 저장·복원하는 비용이 발생.

---

## 실제 예시

```bash
# 실행 중인 프로세스 목록
ps -aux

# 출력 예시
USER   PID  %CPU  %MEM  COMMAND
user   1234  0.5   1.2   /usr/bin/python3
user   1235  2.1   0.8   /usr/bin/node

# PID로 프로세스 강제 종료
kill -9 1234

# 실시간 CPU·메모리 사용 모니터링
top
```

- 작업관리자(Windows) / 활성 상태 보기(Mac) = 실행 중인 프로세스 목록
- 앱이 "응답 없음"이 될 때 = 해당 프로세스가 멈춘 것
- 크롬이 탭마다 별도 프로세스인 이유: 탭 하나가 죽어도 다른 탭에 영향 없게

## 자주 헷갈리는 것

**"스레드가 많을수록 빠르다"**: 아니다. 스레드 수가 CPU 코어 수를 넘어가면 작업 전환 비용만 늘어난다. 오히려 느려질 수 있다.

**"메모리 누수는 큰 프로그램에서만 발생"**: 아니다. Heap에 할당한 메모리를 해제하지 않으면 어떤 프로그램도 발생한다. 앱을 오래 쓰면 느려지는 원인 중 하나.

**"프로세스 종료 = 메모리 해제"**: 맞다. 프로세스가 종료되면 OS가 할당한 메모리 전체를 회수한다. 그래서 재시작하면 다시 빨라지는 것.

---

## 더 알면 좋은 것

📌 **데드락(Deadlock)**: 두 프로세스가 서로 상대방의 자원을 기다리며 영원히 멈추는 상황. A는 B의 자원을, B는 A의 자원을 기다림 → 둘 다 영원히 대기.

📌 **IPC(Inter-Process Communication)**: 프로세스 간 데이터를 주고받는 방법. 파이프, 소켓, 공유 메모리, 메시지 큐 등.

📌 **Zombie Process**: 프로세스는 종료됐지만 부모 프로세스가 종료 상태를 회수하지 않아 테이블에 남아있는 상태. 자원은 해제됐지만 PID를 점유.
