# SSH (Secure Shell)

**정의**: 로컬 컴퓨터에서 원격 서버에 **안전하게(암호화) 접속**해 명령을 실행하는 프로토콜.

---

## 왜 필요한가

클라우드 서버(AWS EC2 등)는 내 책상 옆에 있는 게 아니라 멀리 떨어진 데이터센터에 있다. 그 서버를 켜고 끄고, 코드를 올리고, 로그를 보려면 **원격에서 터미널로 접속**해야 한다. 이때 통신 내용이 평문으로 오가면 비밀번호·키가 그대로 노출된다. SSH는 이 원격 접속 구간을 통째로 암호화해 안전하게 만든다.

> 한 줄 정리: **내 PC ↔ 원격 서버를 잇는 암호화된 터미널 통로.**

---

## 어떻게 작동하나

### 구조 (클라이언트 ↔ 서버)

```
내 PC (SSH 클라이언트)  ──암호화 채널──▶  원격 서버 (SSH 서버 실행 중)
   ssh 명령                                OpenSSH 등이 22번 포트에서 대기
```

원격 서버에는 **SSH 서버 프로그램(OpenSSH 등)이 설치·실행 중**이어야 접속이 된다. 기본 포트는 22번.

### 접속 명령

```bash
ssh user@192.168.0.100        # IP로 접속
ssh user@server.example.com   # 도메인으로 접속
```

- `user` = 원격 서버의 사용자 계정
- 접속하면 그 순간부터 입력하는 명령은 **내 PC가 아니라 원격 서버에서** 실행된다.

### 운영체제별 사용

| 환경 | 방법 |
|:---|:---|
| Mac · Linux | 터미널에 기본 `ssh` 내장 → 바로 사용 |
| Windows | 기본 `ssh` 또는 **PuTTY** 같은 별도 클라이언트 사용 |

---

## 실제 예시

- AWS EC2 인스턴스를 만들면 `ssh -i key.pem ubuntu@<공인IP>` 로 접속해 Linux 명령어로 서버를 관리한다.
- 원격 서버에 배포한 웹앱이 죽으면 SSH로 들어가 `tail -f` 로 로그를 보고 `kill` 로 프로세스를 정리한다.
- 오픈소스 LLM을 직접 돌리려면 GPU 서버에 SSH로 접속해 환경을 세팅한다. → 네트워크·서버 이해가 전제되는 이유.

---

## 자주 헷갈리는 것

**SSH vs FTP/SFTP**: SSH는 원격 **명령 실행**이 목적, FTP는 **파일 전송**이 목적. SFTP는 SSH 위에서 파일을 안전하게 전송하는 방식이라 둘은 짝꿍처럼 쓰인다.

**"비밀번호로만 접속한다"**: 실무에서는 비밀번호보다 **키 페어(공개키/개인키)** 방식을 더 많이 쓴다. 개인키는 내 PC에, 공개키는 서버에 등록해 두면 비밀번호 없이 안전하게 접속. AWS의 `.pem` 파일이 바로 개인키.

## 더 알면 좋은 것
