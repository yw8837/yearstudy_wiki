# 리눅스 파일 권한 (Permission)

**정의**: 파일·폴더에 대해 **누가(소유자/그룹/기타)** 무엇을(읽기·쓰기·실행) 할 수 있는지 정하는 규칙.

---

## 왜 필요한가

여러 사용자가 한 서버를 함께 쓰기 때문에, 아무나 시스템 파일을 바꾸거나 지우면 안 된다. 권한은 "이 파일은 내가 읽고 쓰지만, 남은 읽기만" 같은 통제를 가능하게 한다. `Permission denied` 에러를 만나면 십중팔구 이 문제다.

---

## 어떻게 작동하나

### 권한 읽기 — `ls -al`

```bash
$ ls -al
drwxr-xr-x  2 user staff   64 ...  myfolder
-rw-r--r--  1 user staff   28 ...  hello.txt
```

맨 앞 10글자를 끊어 읽는다:

```
d  rwx  r-x  r-x
│   │    │    │
│   │    │    └ 기타(others) 권한
│   │    └───── 그룹(group) 권한
│   └────────── 소유자(owner) 권한
└────────────── d=폴더 / -=파일
```

| 문자 | 의미 | 숫자 |
|:---:|:---|:---:|
| `r` | 읽기 | 4 |
| `w` | 쓰기 | 2 |
| `x` | 실행 | 1 |
| `-` | 권한 없음 | 0 |

### 권한 바꾸기 — `chmod`

숫자는 r(4)+w(2)+x(1)을 더해서 표현.

```bash
chmod 755 script.sh    # rwxr-xr-x (소유자 전권, 나머지 읽기·실행)
chmod 644 index.html   # rw-r--r-- (소유자 읽기·쓰기, 나머지 읽기만)
```

- `7` = 4+2+1 = rwx
- `6` = 4+2 = rw-
- `5` = 4+1 = r-x

### 관리자 권한 — `sudo`

```bash
sudo apt install 패키지   # 관리자(root) 권한으로 실행
```

---

## 실제 예시

```bash
# 실행 권한이 없어 스크립트가 안 돌 때
chmod +x deploy.sh     # 실행 권한 추가
./deploy.sh

# Permission denied → 관리자 권한 필요
sudo systemctl restart nginx
```

---

## 자주 헷갈리는 것

**`chmod 777` 남용**: 모두에게 전권(rwxrwxrwx). 편하지만 보안상 위험 — 아무나 수정·실행 가능. 꼭 필요한 경우 외 금지.

**`sudo` 남용**: 관리자 권한은 시스템 파일도 바꿀 수 있어, 잘못 쓰면 시스템이 망가진다. 일반 작업엔 쓰지 않는 게 원칙.

**숫자 순서**: 항상 **소유자-그룹-기타** 순. `chmod 644`는 6(소유자)·4(그룹)·4(기타).

---

## 더 알면 좋은 것

📌 **`chown`**: 파일 소유자 변경. `sudo chown user:group file`.

📌 **기호 모드**: 숫자 대신 `chmod u+x`(소유자에 실행 추가), `chmod o-w`(기타 쓰기 제거)처럼도 가능.
