# 06/08 · SQL 시작하기

관계형 데이터베이스와 SQL의 기본 개념을 잡고 실습 환경(VS Code + SQLTools + SQLite)을 구축한 뒤, chinook DB로 **SELECT 기초**(컬럼 선택·DISTINCT·WHERE·연산자·LIKE·ORDER BY)를 연습하고, 별도 book DB를 만들어 **DML**(INSERT/UPDATE/DELETE)을 다뤘다. 한 줄 요약: **DB 기초의 핵심은 [[CRUD]]이고, 문법은 DBMS마다 달라도 기본 개념은 공통이다.**

> 강사: 황지영. 실습 도구: VS Code + SQLTools + SQLite. 실습 DB: chinook(SELECT), book(DML·수업 중 생성).

---

## 01. 데이터베이스란 / SQLite를 쓰는 이유 → [[데이터베이스]]

**데이터베이스(DB)** = "여러 사람이 공유해 사용할 목적으로 통합하여 관리되는 데이터의 모음". MariaDB·Oracle·Amazon Redshift 등 종류가 많지만, **세상의 모든 DB를 다 알 필요는 없다.** DB 종류에 따라 사용법이 조금씩 다를 뿐, **검색·분석에 쓰이는 기본 사용법은 DB 종류와 무관하게 동일**하다 — 그게 우리가 배우는 부분.

- **왜 SQLite인가**: DB 엔진은 많지만(Oracle·MySQL 등) 비대면·다양한 PC 환경에서 설치 난이도·충돌 위험이 큰 DB는 배제. **SQLite는 가볍고 설치 부담이 낮아 기초 SQL 학습에 적합.**
- **주의**: 실습 플랫폼 엘리스의 DB 엔진은 SQLite가 아닐 수 있음(MariaDB 등) → 세미콜론 등 문법 차이 가능. SQL 문법은 DBMS마다 차이가 있으나 기본 [[CRUD]] 개념은 공통.

→ [[데이터베이스]] · [[관계형데이터베이스]] · [[SQLite]] 참조

## 02. SQL과 CRUD → [[SQL]] · [[CRUD]]

**SQL** = **S**tructured **Q**uery **L**anguage. "데이터베이스에 접근하고 조작하기 위한 표준 언어"(= DB를 제어하는 방법). SQL이 할 수 있는 것: 데이터 검색·삽입·수정·삭제, 데이터베이스 생성, 테이블 생성 등.

**CRUD** = **C**reate / **R**ead / **U**pdate / **D**elete — DB 조작의 4대 기초. 강사 강조: **어려운 지점은 CRUD 자체가 아니라 여러 테이블 조합 / 조회 조건 설계에서 발생**한다.

```sql
DESC Employees;   -- 명령(DESC) + 대상(Employees). 테이블 구조 확인용
```
> ⚠️ 여기서의 `DESC`(구조 보기)는 [[ORDER BY]]의 `DESC`(내림차순)와 기능이 완전히 다르다.

→ [[SQL]] · [[CRUD]] 참조

## 03. 관계형 DB 구조 — 테이블·컬럼·레코드 → [[관계형데이터베이스]]

가장 많이 쓰이는 건 **관계형 / 비관계형** 데이터베이스. **관계형 DB** = "하나 이상의 테이블로 이루어지며 서로 연결된 데이터를 가지고 있음", SQL로 제어 가능.

**테이블 = 컬럼(Column) + 레코드(Record)로 구성된 표.** 모든 테이블은 고유 이름으로 구분.

| 사번 | 이름 | 성별 |
|:---|:---|:---|
| 001 | 홍길동 | 남성 |
| 002 | 김철수 | 남성 |
| 003 | 김영희 | 여성 |

- 가로 한 줄 = **레코드(행)**, 세로 한 칸 = **컬럼(열)**.
- 용어 메모: 강의자료는 "컬럼"을 쓰지만 실무에선 **"필드(field)"** 용어도 많이 쓰임 → 혼동 주의.

### ERD와 Crow's Foot 표기법 → [[ERD]]

테이블 간 관계를 그림으로 나타낸 게 **ERD(개체-관계 다이어그램)**. 구성: **개체(Entity)=테이블(박스)**, **속성(Attribute)=컬럼+자료형**, **관계(Relationship)=박스를 잇는 선**.

**Crow's Foot(까마귀발) 표기**: 선 끝 기호로 카디널리티를 읽음. 바깥=최대(`|` 하나 / `<` 다수), 안쪽=최소(`|` 필수 / `O` 선택).
- `||` 정확히 하나 · `O|` 0 또는 1 · `|<` 1 또는 다수 · `O<` 0 또는 다수(1:N에서 가장 흔함)

**chinook 구조(3영역)**: ① 음악 카탈로그 artists→albums→tracks(1:N) ② 플레이리스트 playlists↔**playlist_track**↔tracks(N:M, 정션 테이블) ③ 판매 customers→invoices→invoice_items(계층). N:M은 직접 못 잇고 **정션 테이블**을 거친다 → [[JOIN]]의 토대.

> 출처: 강사 라이브 정리(노션 260608) 보강. chinook ERD 그림은 [SQLite Tutorial 샘플 DB](https://www.sqlitetutorial.net/sqlite-sample-database/) 참고.

→ [[관계형데이터베이스]] · [[ERD]] 참조

## 04. 실습 환경 세팅 (1차 관문)

> 개념보다 운영/세팅 절차. "Successfully connected"까지 확인하는 게 1차 관문.

- **1차 관문 기준**: VS Code에서 코드 실행 시 결과값 정상 출력 + SQLite 연결 테스트에서 **"Successfully connected"** 확인.
- **VS Code 확장 3종** (Ctrl+Shift+X): ① SQLTools ② SQLTools SQLite ③ SQLite Viewer.
- **Windows Node.js**: SQLTools/SQLite 연동 시 확장 활성화 실패 가능 → Windows는 Node.js 설치 권장(**Add to PATH 체크**, 설치 후 재부팅). 확인: `node -v`, `npm -v`.
- **커넥션 생성**: SQLTools 패널 → Add New Connection → 타입 SQLite → Connection Name 임의 → Database File 경로(Windows는 `\`, Mac은 `/`) → Test Connection → Save → Connect Now.
- **단축키**: Run Selected Query를 **Ctrl+Enter**로 변경(진입: Win `Ctrl+K,Ctrl+S` / Mac `Cmd+K,Cmd+S`).
- **레이아웃**: View → Editor Layout → **Two Rows**로 결과창을 아래 배치.
- **실행 주의**: 일부 쿼리는 **선택 영역(드래그) 후 실행** 필요. "table이 없다" 메시지는 데이터 삽입 이전 상태일 수 있으니 상단부터 순차 실행.

## 05. SELECT / FROM · 컬럼 선택 · LIMIT → [[SELECT]] · [[LIMIT]]

> 코드 출처: `Day01_lecture.sql`(정답본). chinook 테이블: albums·artists·tracks·customers·invoices 등.

`SELECT 컬럼 FROM 테이블;` = 명령(SELECT) + 검색할 컬럼 + 테이블(FROM). `*`는 모든 컬럼. **LIMIT**는 데이터가 많을 때 상위 n개만 확인.

```sql
SELECT Title FROM albums;              -- 앨범 제목만
SELECT * FROM artists;                 -- 모든 컬럼
SELECT * FROM tracks LIMIT 10;         -- 앞 10건
SELECT Name, UnitPrice FROM tracks LIMIT 10;  -- 곡 이름·단가
```

## 06. DISTINCT — 중복 제거 → [[DISTINCT]]

**DISTINCT** = 뒤에 나오는 컬럼의 **중복을 제거**하고 보여준다. ⚠️ 컬럼을 2개 이상 적으면 **조합 기준**으로 중복 제거(한쪽이 같아도 다른 쪽이 다르면 다르게 취급).

```sql
SELECT DISTINCT Country FROM customers;        -- 국가 종류
SELECT DISTINCT UnitPrice FROM tracks;         -- 단가 종류
SELECT DISTINCT City, Country FROM customers;  -- 도시+국가 조합
```

→ [[DISTINCT]] 참조

## 07. WHERE + 비교 연산자 → [[WHERE]]

**WHERE** = "검색하고자 하는 데이터의 조건을 설정하는 명령". 비교 연산자: `>` `<` `>=` `<=` `=`(같다) `!=`(같지 않다). 문자열 비교 시 **따옴표** 사용(`'USA'`).

```sql
SELECT * FROM customers WHERE Country = 'USA';
SELECT * FROM tracks WHERE UnitPrice > 0.99 LIMIT 10;
SELECT * FROM invoices WHERE Total >= 10;
```

→ [[WHERE]] 참조

## 08. 복합 조건 · 기타 연산자 → [[연산자SQL]]

**복합 조건**: `AND`/`&&`(둘 다), `OR`/`||`(또는), `NOT`/`!`(아닌 값). **기타**: `BETWEEN A AND B`(경계 포함), `IN`(목록 포함), `NOT IN`(목록 미포함).

```sql
SELECT * FROM customers WHERE Country = 'USA' AND State = 'CA';
SELECT * FROM customers WHERE Country = 'USA' OR Country = 'Canada';
SELECT * FROM customers WHERE NOT Country = 'USA';   -- = WHERE Country != 'USA'

SELECT * FROM invoices WHERE Total BETWEEN 5 AND 10;
SELECT * FROM customers WHERE Country IN ('USA', 'Canada', 'Brazil');
SELECT * FROM customers WHERE Country NOT IN ('USA', 'Canada', 'Brazil');
```
> 강사: NOT은 최소화하고, 여러 국가 조건은 `IN(...)`이 더 명확하다.

→ [[연산자SQL]] · [[WHERE]] 참조

## 09. LIKE — 패턴 검색 → [[LIKE]]

**LIKE** = "특정 문자가 포함된 문자열을 찾고 싶을 때 사용". 와일드카드 `%`: `'K%'`(K로 시작) / `'%K'`(K로 끝) / `'%K%'`(K 포함).

```sql
SELECT * FROM albums WHERE Title LIKE 'Rock%';     -- Rock으로 시작
SELECT * FROM albums WHERE Title LIKE '%Live';     -- Live로 끝
SELECT * FROM tracks WHERE Name LIKE '%Love%' LIMIT 10;  -- Love 포함
```

→ [[LIKE]] 참조

## 10. ORDER BY — 정렬 → [[ORDER BY]]

**ORDER BY** = "데이터를 검색할 때 정렬하여 출력하는 명령어". `ASC`=오름차순(작은 값부터), `DESC`=내림차순(큰 값부터).

```sql
SELECT Name, UnitPrice FROM tracks ORDER BY UnitPrice DESC LIMIT 10;
SELECT * FROM invoices ORDER BY Total DESC LIMIT 5;       -- 결제 큰 5건
SELECT Title FROM albums ORDER BY Title ASC LIMIT 10;     -- 알파벳순
```

→ [[ORDER BY]] 참조

## 11. DML — INSERT / UPDATE / DELETE → [[DML]]

> 코드 출처: `Day01_dml_lecture.sql`(정답본). chinook 직접 조작 X → 별도 **book.db** 생성 후 DML 연습. 데이터 출처: books.toscrape.com(제목/가격은 사이트 값, 카테고리/평점/재고는 연습용).

**DML(데이터 조작어)** = 테이블의 데이터를 삽입·수정·삭제하는 SQL. 재실행 가능하게 `DROP TABLE IF EXISTS`로 시작하면 몇 번 실행해도 에러가 안 난다.

```sql
DROP TABLE IF EXISTS book;
CREATE TABLE book (
    id INTEGER PRIMARY KEY, title TEXT, category TEXT,
    price REAL, rating INTEGER, stock INTEGER
);
INSERT INTO book (id, title, category, price, rating, stock) VALUES
(1, 'A Light in the Attic', 'Poetry', 51.77, 3, 22);  -- (이하 시드 생략)
```

### 11.1 INSERT (삽입) → [[INSERT]]
`INSERT INTO 테이블(컬럼...) VALUES(값...);`. **컬럼을 생략하면 테이블 정의 순서대로** 삽입. 문자열 내 작은따옴표는 `''`(두 번)로 이스케이프.

```sql
INSERT INTO book (id, title, category, price, rating, stock)
VALUES (13, 'It''s Only the Himalayas', 'Travel', 45.17, 2, 19);

INSERT INTO book VALUES (14, 'Set Me Free', 'Young Adult', 17.46, 5, 19);  -- 컬럼 생략
```

### 11.2 UPDATE (수정) → [[UPDATE]]
`UPDATE 테이블 SET 컬럼=값 WHERE 조건;`. 기존 값 기반 연산도 가능(`stock = stock + 5`).

```sql
UPDATE book SET price = 39.99 WHERE title = 'Soumission';
UPDATE book SET stock = stock + 5 WHERE category = 'Poetry';
```

### 11.3 DELETE (삭제) → [[DELETE]]
`DELETE FROM 테이블 WHERE 조건;`. ⚠️ **WHERE 조건이 없으면 모든 데이터 삭제.**

```sql
DELETE FROM book WHERE rating = 1;
DELETE FROM book WHERE stock < 16;
-- ★ WHERE 누락 시 전체 삭제: DELETE FROM book; → book 전체 삭제
```
> 참고: 판서 회의록의 DELETE 과제 예시는 "재고=15 삭제"로 언급되나, 실제 lecture.sql 정답은 `stock < 16`(재고 16 미만)이다. 결과는 사실상 동일하며, 여기서는 **정답 파일 기준** `stock < 16`을 따른다. `[원문 확인 필요]`

## 보충

📌 **WHERE 누락 = 전체 수정/삭제 위험** (UPDATE·DELETE 공통). DML은 항상 WHERE를 먼저 확인.

📌 **DML은 별도 DB에서**: 기존 실습 DB(chinook) 손상 방지를 위해 book.db를 따로 생성. 동시에 여러 DB 연결 시 혼동 → 하나만 연결 유지(나머지 Disconnect).

📌 **ERD 보는 훈련 반복**: "강사 화면 따라 치기" 금지. ERD를 보고 컬럼/테이블을 확인한 뒤 작성.

📌 **DBMS별 문법 차이**: alias 사용, 숫자 인덱스 정렬 등 DBMS마다 다를 수 있음(엘리스 MariaDB 추정 vs SQLite).

📌 **운영 공지**: 만족도 조사(디스코드), DB 실습 약 7일 과정, 화~금 6교시 시험, 답지 매일 공유, 시험은 다음날부터 **classicmodels** DB 사용 예고. Copilot 자동 답안 제안은 퀴즈 공정성을 해쳐 비활성화 요청.
