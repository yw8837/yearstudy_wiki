# 비율 함수 (RATIO_TO_REPORT / PERCENT_RANK / CUME_DIST / NTILE)

**정의**: 윈도우 안에서 **비율·백분위·등급**을 계산하는 함수 계열. 전체 대비 기여도, 상대 순위(백분율), 등급 구간을 구한다.

---

## 왜 필요한가

"이 고객이 전체 매출의 몇 %인가", "상위 몇 %인가", "신용한도 상/중/하 등급"처럼 **상대적 위치**가 필요할 때. 단순 순위([[순위함수]])보다 비율·구간으로 표현하면 분석에 유용하다.

---

## 어떻게 작동하나

| 함수 | 의미 | 범위 / 비고 |
|:---|:---|:---|
| **RATIO_TO_REPORT(x)** | 파티션 전체 SUM 대비 비율 | Oracle 전용. SQLite/MariaDB는 **`x / SUM(x) OVER()`** 대체 |
| **PERCENT_RANK()** | 순위 백분율 | `[0,1]`, **최고=0** · 최저=1 |
| **CUME_DIST()** | 이하 건의 누적 백분율 | `(0,1]` |
| **NTILE(N)** | 정렬 후 **N등분** 그룹 번호 | 상세 → [[NTILE]] |

```sql
PERCENT_RANK() OVER (ORDER BY SALARY DESC)            -- 백분율 순위
ROUND(CUME_DIST() OVER (ORDER BY SALARY DESC), 4)     -- 누적 분포
(SALARY / SUM(SALARY) OVER ())                        -- RATIO_TO_REPORT 대체
```

---

## 실제 예시

```sql
-- 상위 고객 백분율 순위 / 누적분포 — chinook
SELECT c.CustomerId, ROUND(SUM(i.Total),2) AS TotalPurchase,
       ROUND(PERCENT_RANK() OVER (ORDER BY SUM(i.Total) DESC), 4) AS PctRank,
       ROUND(CUME_DIST()    OVER (ORDER BY SUM(i.Total) DESC), 4) AS CumeDist
FROM customers c JOIN invoices i ON c.CustomerId = i.CustomerId
GROUP BY c.CustomerId ORDER BY TotalPurchase DESC LIMIT 10;
```

---

## 자주 헷갈리는 것

**RATIO_TO_REPORT는 SQLite에 없다** → `값 / SUM(값) OVER()`로 직접 구현.

**PERCENT_RANK 최고=0**: 1등이 0, 꼴찌가 1. CUME_DIST는 0 초과 1 이하. 헷갈리기 쉬운 범위.

**전체합 분모 주의**: `SUM(x) OVER()`를 GROUP BY 결과 위에 쓰면 GrandTotal이 의도와 달라질 수 있다 → [[스칼라서브쿼리]] 권장.
