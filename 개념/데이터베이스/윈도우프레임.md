# 윈도우 프레임 (WINDOWING / ROWS BETWEEN)

**정의**: [[OVER절]]에서 윈도우 함수가 **계산에 포함할 행의 물리적 범위**를 지정하는 절. `ROWS BETWEEN 시작 AND 끝` 형태. 누적합·이동평균·잔여합처럼 "어디부터 어디까지"를 정한다.

---

## 왜 필요한가

같은 `SUM()`이라도 "처음~현재"면 누적합, "현재~끝"이면 잔여합이다. 강사 강조: **"창(window)의 너비/범위 설정에 따라 결과가 크게 달라진다."** 누적·이동평균 분석의 핵심 장치.

---

## 어떻게 작동하나

| 경계 키워드 | 의미 |
|:---|:---|
| `UNBOUNDED PRECEDING` | 시작 = 파티션 **첫 행** |
| `CURRENT ROW` | **현재 행** |
| `UNBOUNDED FOLLOWING` | 끝 = 파티션 **마지막 행** |
| `N PRECEDING` / `N FOLLOWING` | 앞/뒤 N개 행 (이동평균 등) |

```
ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW       → 처음~현재 (누적합)
ROWS BETWEEN CURRENT ROW AND UNBOUNDED FOLLOWING       → 현재~끝   (잔여합)
ROWS BETWEEN 2 PRECEDING AND CURRENT ROW               → 최근 3행  (이동평균)
ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING→ 파티션 전체
```

---

## 실제 예시

```sql
-- 누적합 — chinook
SUM(Total) OVER (ORDER BY InvoiceDate
                 ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS RunningTotal
```

---

## 자주 헷갈리는 것

**기본 프레임 함정**: `OVER`에 `ORDER BY`가 있고 `ROWS BETWEEN`을 **생략**하면 기본값이 `UNBOUNDED PRECEDING ~ CURRENT ROW`(처음~현재)다. 그래서 [[FIRST_VALUE LAST_VALUE|LAST_VALUE]]가 "현재 행 값"을 반환해 의도와 어긋난다 → 전체 최대/최소가 필요하면 `... AND UNBOUNDED FOLLOWING`까지 명시.

**ROWS vs RANGE**: ROWS=물리적 행 개수, RANGE=값(정렬키) 기준 범위. 실습은 주로 ROWS.
