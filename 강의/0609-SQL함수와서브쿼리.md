# 06/09 · SQL 함수와 서브쿼리

전일 SELECT 복습 후 **집계함수**(COUNT/SUM/AVG/MAX/MIN)와 **GROUP BY/HAVING** 그룹 집계, 다수 테이블 제어의 핵심인 **JOIN**(INNER/LEFT/RIGHT)과 NULL 필터링, 마지막으로 **서브쿼리**(단일행/다중행/위치별)를 다뤘다. 핵심 학습법: **"메인쿼리/서브쿼리를 먼저 분할 → 각각 실행 → 합치기".**

> 강사: 황지영. 실습 DB: chinook.
>
> 📌 **정답 출처**: `Day02_*_student.sql`은 정답 칸이 비어 있었으나 **강사 노션 답지(260609)에 핵심 문항 실제 정답이 있어 반영**했다. ✅ 실제 답지: HAVING 6~10, JOIN 14~16·19~20, 서브쿼리 1·4·5·6·10. ⚠ 재구성: 노션에도 없는 나머지 문항만 슬라이드 문법 기반(표현이 강사 의도와 다를 수 있음).

## 01. 집계 함수 → [[집계함수]]

**집계함수(Aggregate)** = 여러 행의 값을 하나로 요약. COUNT/SUM/AVG/MAX/MIN.

- **COUNT** = "검색 결과의 데이터 개수". ⚠️ **NULL인 데이터는 제외.** 전체 10행 중 특정 컬럼에 NULL 3개면 COUNT 결과는 7. `COUNT(*)`(모든 행) vs `COUNT(컬럼)`(NULL 제외).
- **SUM / AVG** = 합계 / 평균. AVG는 SUM/COUNT를 직접 안 써도 평균 산출.
- **MAX / MIN** = 최댓값 / 최솟값. **숫자형뿐 아니라 문자형도 가능.**

```sql
SELECT COUNT(id) FROM book;     -- id 값 개수 (NULL 제외)
SELECT COUNT(*)  FROM book;     -- 전체 행 개수
SELECT SUM(math) FROM grade;
SELECT AVG(korean), AVG(english), AVG(math) FROM grade;
SELECT MAX(korean) FROM grade;
SELECT MIN(english) FROM grade;
```
> **LIMIT 보강**: 인덱스 시작은 0 → `LIMIT 1, 5`는 2번째 데이터부터 5개. LIMIT는 Oracle에서 문법이 상이(DBMS 차이).
>
> 분석가 로드맵(강사): 기본문법 + 서브쿼리 + 조인 + **윈도우 함수**까지. 분석가는 SQL 외 보고서·엑셀 역량도 중요.

## 02. GROUP BY / HAVING → [[GROUP BY]] · [[HAVING]]

**GROUP BY** = 기준 컬럼이 같은 데이터끼리 그룹화. `SELECT 기준컬럼, 집계함수 FROM 테이블 GROUP BY 기준컬럼;`. 강사 강조: **GROUP BY 대상 컬럼은 SELECT 절에도 반드시 포함**(정석). SQLite가 예외 동작해도 정석 준수.

**HAVING** = GROUP BY 결과(그룹)에 조건 적용. **단독 사용 불가(GROUP BY 이후).** WHERE는 그룹 전 **행 필터**, HAVING은 그룹 후 **그룹 필터**.

```sql
-- 교안 예시(가상 rental 테이블)
SELECT user_id, COUNT(*) FROM rental GROUP BY user_id;
SELECT user_id, COUNT(*) FROM rental GROUP BY user_id HAVING COUNT(user_id) > 1;
```

**실습 (chinook) ✅ 노션 실제 답지** — `Day02_groupby_Join_student.sql` 문제 6~10:
```sql
-- 문제6. 앨범 5개 이상 아티스트 (답지 SQL은 > 5)
SELECT ArtistId, COUNT(*) AS album_cnt FROM albums GROUP BY ArtistId HAVING COUNT(*) > 5;
-- 문제8. 매출 합계 100 초과 국가
SELECT BillingCountry, SUM(Total) AS total_sales FROM invoices GROUP BY BillingCountry HAVING SUM(Total) > 100;
-- 문제9. 인보이스 7건 이상 고객
SELECT CustomerId, COUNT(*) AS invoice_cnt FROM invoices GROUP BY CustomerId HAVING COUNT(*) >= 7;
-- 문제10. 트랙 100개 이상 장르, 많은 순 (ORDER BY 2 = 2번째 컬럼)
SELECT GenreId, COUNT(*) AS track_cnt FROM tracks GROUP BY GenreId HAVING COUNT(*) >= 100 ORDER BY 2 DESC;
```

## 03. JOIN — 다수 테이블 결합 → [[JOIN]]

### 03.1 왜 나누고 다시 합치나 (정규화)
테이블을 나누는 이유: ① 중복/저장 낭비 방지 ② 수정 시 일괄 관리(유저 정보 변경 시 렌탈까지 다 고치는 문제 방지) ③ 삭제/무결성 문제 방지 → **정규화** 개념. 나눠둔 걸 조회 시 다시 합치는 게 [[JOIN]].

### 03.2 INNER JOIN → [[INNER JOIN]]
두 테이블 정보를 한 번에 조회, **교집합(매칭되는 키만)**. `FROM A INNER JOIN B ON A.key = B.key`. 매칭 안 되는 행은 제외.

```sql
SELECT * FROM rental INNER JOIN user ON user.id = rental.user_id;  -- 교안 예시
```

**작성 원칙**: ERD 보고 키 확인 후 작성. 컬럼명이 겹치면 `table.column`으로 명시(안 하면 `ambiguous column name` 오류). `Name` 같은 동일 컬럼명은 **별칭(AS)** 으로 구분. 강사는 별칭 남용보다 테이블명 명시를 선호.

**실습 (chinook) ✅ 노션 실제 답지** — 문제 14~16:
```sql
-- 문제14. invoice_items + tracks (항목ID·트랙명·단가·수량)
SELECT invoice_items.InvoiceLineId, tracks.Name, invoice_items.UnitPrice, invoice_items.Quantity
FROM invoice_items INNER JOIN tracks ON invoice_items.TrackId = tracks.TrackId;
-- 문제15. customers + employees (SupportRepId = EmployeeId) ← 데이터 정의서 사례
SELECT customers.FirstName AS customer_name, employees.FirstName AS support_rep
FROM customers INNER JOIN employees ON customers.SupportRepId = employees.EmployeeId;
-- 문제16. 3개 조인: Track→Album→Artist 경유 (직접 연결 불가)
SELECT tracks.Name AS track_name, albums.Title AS album_title, artists.Name AS artist_name
FROM tracks
INNER JOIN albums  ON tracks.AlbumId  = albums.AlbumId
INNER JOIN artists ON albums.ArtistId = artists.ArtistId
LIMIT 20;
```
> 강사: Track↔Artist는 직접 연결 불가 → **반드시 Album을 경유.** 실무에서 `SELECT *`는 금지에 가까움 — 조인 성공 확인용으로만 쓰고 필요한 컬럼으로 좁힌다.

### 03.3 LEFT / RIGHT JOIN + NULL 필터링 → [[LEFT JOIN]]
- **LEFT JOIN** = 왼쪽 테이블 모두 출력 + 매칭 실패 시 NULL. **RIGHT JOIN** = 오른쪽 모두.
- **NULL 필터링**: "관계 없는 행"은 `IS NULL` / `IS NOT NULL`로 거른다(= 비교로는 NULL 못 거름). 예: "앨범 없는 아티스트" → `WHERE albums.AlbumId IS NULL`.
- **실무 팁**: **RIGHT JOIN보다 LEFT JOIN 권장** — 테이블 순서를 바꿔 RIGHT 효과를 LEFT로 대체. RIGHT JOIN은 SQLite **3.39.0 이상**에서만 동작.

```sql
SELECT * FROM user LEFT  JOIN rental ON user.id = rental.user_id;  -- 교안
SELECT * FROM user RIGHT JOIN rental ON user.id = rental.user_id;
```

**실습 (chinook)** — 문제 17~18 ⚠재구성(NULL 필터링), 19~20 ✅노션 실제 답지:
```sql
-- 문제17~18 ⚠재구성: 앨범 없는 아티스트만 (LEFT 후 오른쪽 NULL)
SELECT artists.Name
FROM artists LEFT JOIN albums ON artists.ArtistId = albums.ArtistId
WHERE albums.AlbumId IS NULL;
-- 문제19 ✅: 모든 앨범 기준 RIGHT JOIN (SQLite 3.39.0+)
SELECT artists.Name, albums.Title
FROM artists RIGHT JOIN albums ON artists.ArtistId = albums.ArtistId;
-- 문제20 ✅: 19와 같은 결과를 LEFT로 치환 (테이블 순서 뒤집기)
SELECT artists.Name, albums.Title
FROM albums LEFT JOIN artists ON artists.ArtistId = albums.ArtistId;
```
> **데이터 정의서(Data Dictionary)**: `Customer.SupportRepId`처럼 컬럼명만으론 의미 파악이 어려운 FK는 정의서가 있으면 "SupportRepId = 담당 직원 EmployeeId"를 추론 없이 확인 가능.

## 04. 서브쿼리 → [[서브쿼리]]

**서브쿼리** = "하나의 쿼리 안에 포함된 또 하나의 쿼리". 메인쿼리가 서브쿼리를 포함하는 종속 관계.

**주의사항**: ① 괄호와 함께 사용 ② 서브쿼리 안에서 **ORDER BY 불가** ③ 연산자의 **오른쪽**에 사용 ④ 오로지 **SELECT문**으로만 작성.

**핵심 학습법(강사 반복 강조)**: **"분할 → 각각 실행 → 합치기".** 메인/서브를 먼저 텍스트로 구분하고 구조부터 잡을 것(바로 코딩 금지).

```sql
-- 'elice'의 급여를 몰라도 검색 가능
SELECT * FROM employee
WHERE 급여 > (SELECT 급여 FROM employee WHERE 이름 = 'elice');
```

### 04.1 단일행 / 다중행 → [[서브쿼리]]
- **단일행** = 1개 값 반환. 연산자 `= <> > >= < <=`.
- **다중행** = 2행 이상 반환. `IN`(하나라도 만족), `ANY`(하나라도, 비교 가능), `ALL`(모두, 비교 가능).
- ⚠️ **SQLite는 ANY/ALL 미지원 → MIN/MAX로 대체.** ALL → MAX(최댓값보다 큼), ANY → MIN(최솟값보다 큼).

### 04.2 위치별 분류 → [[스칼라서브쿼리]] · [[EXISTS]]
- **WHERE절** = 가장 일반적.
- **스칼라(SELECT절)** = 한 행만 반환, **JOIN과 같은 결과**.
- **FROM절(파생 테이블)** = **별칭 필수**.
- **EXISTS / NOT EXISTS(상관 서브쿼리)** = 존재 여부 판단. `NOT IN`보다 **NULL에 안전**.

**실습 (chinook) ✅ 노션 실제 답지** — 문제 1·4·5·6·10:
```sql
-- 문제1. [단일행 >] 'Balls to the Wall'(342562ms)보다 긴 트랙
SELECT Name, Milliseconds FROM tracks
WHERE Milliseconds > (SELECT Milliseconds FROM tracks WHERE Name = 'Balls to the Wall');
-- 문제4. [단일행 =] 앨범 'Let There Be Rock' 수록 트랙
SELECT Name FROM tracks WHERE AlbumId = (SELECT AlbumId FROM albums WHERE Title = 'Let There Be Rock');
-- 문제5. [단일행 <] 평균 Total보다 작은 인보이스
SELECT InvoiceId, Total FROM invoices WHERE Total < (SELECT AVG(Total) FROM invoices);
-- 문제6. [다중행 IN, 중첩] 'AC/DC' 발매 앨범의 모든 트랙
SELECT Name FROM tracks WHERE AlbumID IN (
    SELECT AlbumId FROM albums WHERE ArtistId = (SELECT ArtistId FROM artists WHERE Name = 'AC/DC'));
-- 문제10. [다중행 IN] 'Rock' 장르 트랙이 포함된 앨범 제목
SELECT Title FROM albums WHERE AlbumId IN (
    SELECT AlbumId FROM tracks WHERE GenreId = (SELECT GenreId FROM genres WHERE Name = 'Rock'));
```

**⚠ 재구성 추가연습**(노션 답지 없음 — 강의에서 다룬 개념):
```sql
-- ANY/ALL → SQLite 미지원 → MAX/MIN 대체 (ALL→MAX, ANY→MIN)
SELECT Name FROM tracks WHERE Milliseconds > (
    SELECT MAX(Milliseconds) FROM tracks WHERE GenreId = (SELECT GenreId FROM genres WHERE Name = 'Rock'));
-- 스칼라(SELECT절)·상관 서브쿼리: 앨범별 트랙 수
SELECT a.Title, (SELECT COUNT(*) FROM tracks t WHERE t.AlbumId = a.AlbumId) AS track_count FROM albums a;
-- FROM절 파생(별칭 필수): 앨범별 트랙 수의 전체 평균
SELECT AVG(cnt) FROM (SELECT AlbumId, COUNT(*) AS cnt FROM tracks GROUP BY AlbumId) AS sub;
-- NOT EXISTS(NULL 안전): 구매 안 된 트랙
SELECT Name FROM tracks t WHERE NOT EXISTS (SELECT 1 FROM invoice_items ii WHERE ii.TrackId = t.TrackId);
```
> 강사: `NOT IN`은 서브쿼리 결과에 NULL이 섞이면 아무것도 반환 안 할 수 있어 **NOT EXISTS가 더 안전.** 조인 vs 서브쿼리는 동일/유사 결과가 나오기도 해 "정답은 하나가 아니며" 결과 기준으로 이해.

## 보충

📌 **GROUP BY 대상 컬럼은 SELECT에도 포함**(정석). SQLite 예외 동작해도 정석 준수.

📌 **JOIN은 ERD/키 확인 후.** 컬럼명 겹치면 `table.column`, 동일 컬럼명(`Name`)은 별칭으로 구분.

📌 **`SELECT *`는 실무에서 금지에 가까움.** 조인 확인용으로만.

📌 **NULL: `IS NULL`/`IS NOT NULL`로만 거름.** `NOT IN`은 NULL에 취약 → `NOT EXISTS` 안전.

📌 **SQLite는 ANY/ALL 미지원 → MIN/MAX 대체.** RIGHT JOIN은 3.39.0+.

📌 **운영**: 시험은 classicmodels DB로 진행 예고. 답지는 노션 업로드. JOIN/서브쿼리 답안 플랫폼 추가 업로드.
