# AI 윤리·안전 활용 가이드 정리

AI를 안전하고 책임감 있게 쓰는 핵심 가이드를 **섹션별로 한눈에**. 상세는 개념 페이지 링크에서.

## 1. 데이터 입력 위험 → [[AI윤리가이드]]

```
민감정보를 AI에 입력 → 학습/유출 가능성 → 정보 노출 위험
```

- **왜 위험?** AI에 넣은 입력이 학습 데이터로 쓰이거나 저장될 수 있어서.
- **실제 사례(강사 강조):** 초기 ChatGPT 시기 **삼성전자 직원이 회사 기밀을 입력** 해 보안 이슈가 됨("삼성전자 ChatGPT 보안" 검색). → **비밀번호·API키·기밀·개인정보 업로드 금지.**
- **그래서?** 회사 기밀·개인정보는 그대로 넣지 말고, 입력 자체를 최소화한다. DeepSeek 등 데이터 수집 우려 모델은 회사 차원에서 가려 쓴다.
- **확산 통계(한국IDC):** 국내 조직 **72%** 도입(사용 중/예정), **78%** 생산성 향상 체감, 개인 **86.0%** 활용 — AI는 이미 '기본 도구'.
- AI 윤리가 중요한 이유 4대 위험: 개인정보 유출 / 기업 기밀 유출 / 허위 정보 생성 / 저작권 문제.
- OpenAI·Anthropic 이용약관에서 입력 데이터 처리 정책 확인 권장

## 2. 개인정보 비식별화 → [[개인정보비식별화]]

```
[원본]   전화 123-4567-890, 이메일 asdfgh@gmail.com, 12월 15일
[방법1]  플레이스홀더: XXX-YYYY-ZZZZ, sample@email, XX월 YY일
[방법2]  변수형:      [전화번호1], [이메일1], [날짜1]
```

- **왜?** 이름만 가려도 전화·이메일·날짜·금액 조합으로 신원이 드러나서.
- **그래서?** 식별 가능한 항목을 전부 마스킹/치환 후 입력. 변수형은 결과 복원에 유리.
- 단, 비식별화는 위험 완화일 뿐 — 민감정보 입력 최소화가 우선.

## 3. API 키 보안 → [[API키보안]]

```
키 하드코딩 금지 → 환경변수/별도 파일로 분리 → .gitignore에 추가
GitHub 공개 저장소 노출 금지 (노출 시 악용 위험)
```

- **왜?** 키는 곧 "내 계정으로 호출할 권한" — 새면 남이 내 비용·데이터를 쓴다.
- **그래서?** 코드에 박지 말고 환경변수로 분리, `.gitignore`로 깃 추적 제외.
- 이미 커밋·노출됐다면 지우는 것으로 끝이 아니라 **즉시 키 폐기·재발급**.

## 4. 안전한 생성형 AI 보안 4단계 (국정원 가이드 기반)

```
① 도입 전 점검 → ② 사용 준비 → ③ 사용 중 준수 → ④ 사용 후 관리
```

- **① 도입 전 점검:** 약관·보안·데이터 정책 검토 / 개인정보 위탁·법적 근거 확인 / 허용 업무 범위 명시.
- **② 사용 준비:** 민감·기밀정보 분류 / 사내 가이드·금지 사례 공지 / 업무용 계정·MFA·계정 분리.
- **③ 사용 중 준수:** 개인·기밀정보 입력 금지 / URL·파일 업로드 최소화 / 조직명·실명 노출 최소화 / 비인가 확장 금지.
- **④ 사용 후 관리:** 결과물 저장·공유 권한 통제 / 로그·대화 기록 보존·삭제 정책 / 유출·오류 시 즉시 신고.
- **왜 단계화?** 한 번에 다 막기 어려우니 도입 전 → 준비 → 사용 중 → 사용 후로 시점별로 좁혀가서.

## 5. 환각 · 아첨 → [[Hallucination]] · [[Sycophancy]]

```
Hallucination : 근거 없는 정보를 사실처럼 생성 → 교차검증 필요
Sycophancy    : 사용자에 무비판 동조 → 반론 요청·객관자료 대조
```

- **환각이 왜?** LLM은 "그럴듯한 다음 토큰"을 예측할 뿐, 사실 여부를 보장 안 해서.
- **발생 원인 4가지:** 모델 자체의 잘못된 지식 / 논리적 오류 / 존재하지 않는 근거자료 인용 / 업데이트되지 않은 정보. (모델 성능이 좋아져도 발생 — 최신 모델도 주의)
- **완전 제거 불가(강사):** 환각 없는 모델은 없고 모델 성능과 별개로 발생. 완화책은 **[[RAG]]** 로 양질 정보 주입 + 직접 검증.
- **그래서?** 자신감 있는 어조에 속지 말고 1차 출처로 확인.
- **아첨이 왜?** 과도하게 사용자를 치켜세우고 맞장구치는 현상. 단순 과장이 아니라 잘못된 정보 제공·유저 편견 강화로 신뢰도에 직결. 원인은 학습 방식·유저 피드백·시스템 프롬프트 등 다양.
- **실제 사례:** OpenAI는 ChatGPT 업데이트 후 아첨 현상이 심각해지자 결국 **롤백 패치**를 진행했다.
- **그래서?** 내 결론을 미리 흘리지 말고 중립적으로 질문, 일부러 반론을 요청.
- 둘이 겹치면 "원하는 거짓을 자신 있게" 말해 가장 위험 → 6·7번이 안전망.

## 6. AI 답변 교차검증 (원문 C8)

```
한 모델의 답 → [다른 모델/다른 출처로 대조] → [1차 출처 확인] → 사용
```

- **왜?** 환각·아첨 탓에 단일 답은 틀려도 그럴듯하게 보여서.
- **검증 3방법:** ① 공식 자료 확인(공식 문서·논문·기관 자료) ② 다른 출처 비교(교차 검증) ③ 숫자·데이터 검증(통계·수치·계산 결과 재확인). → AI 결과는 초안, 사람이 검증 후 활용.
- **그래서?** 중요한 사실은 여러 모델·여러 출처로 교차검증하고, 가능하면 원문(1차 자료)을 직접 확인한다.
- 코드·수치·법규처럼 틀리면 손해 큰 영역일수록 교차검증을 강하게.

## 7. 책임 — AIR CANADA 챗봇 / 가짜 판례 → [[AI윤리가이드]]

```
항공사 챗봇이 규정에 없는 할인 안내 → 회사가 책임지고 할인 (민사 중재 결정)
```

- **AIR CANADA:** 캐나다 최대 항공사의 웹사이트 AI 챗봇이 규정에 없는 항공료 할인을 안내 → **회사가 책임지고 그대로 할인하라는 민사 중재 결정.** 검증 안 된 AI 답변 한 마디로 회사가 패하고 손실.
- **가짜 판례:** 노무사가 AI가 만든 **가짜 판례(존재하지 않는 판례)를 검증 없이 제출**했다가 발각.
- **왜 중요?** "AI가 틀렸다"는 면책 사유가 안 됐다 — 도구의 출력도 그 도구를 쓴 주체의 책임.
- **그래서?** 고객 응대·법규 안내·공식 문서는 사람이 최종 검수. 책임 없는 무분별한 사용은 금물.

## 8. Human in the Loop → [[HumanInTheLoop]]

```
Human (지시·맥락 Context) → AI (초안 Draft) → Human (검토·수정·최종 책임)
```

- **왜?** 환각·아첨·책임 문제를 한 번에 막는 실용적 안전장치라서.
- **그래서?** AI는 빠른 초안 담당, 사실·품질·책임의 최종 판단은 사람이 쥔다.
- 마무리 메시지: **"AI는 도구(tool)"** — 운전대는 사람이 잡는다.

## 9. ★ RLHF — 피드백으로 모델 개선 → [[RLHF]]

```
좋아요 👍 → 보상 신호 → 모델이 그 방향으로 더 잘 답함
싫어요 👎 → 그 방향을 줄임 → 마음에 안 들면 적극 누르기
```

- 챗봇의 좋아요/싫어요는 단순 만족도가 아니라 **강화학습(RLHF)의 입력.**
- OpenAI ChatGPT(GPT-3 계열) **2022 논문** 의 핵심 키워드, 현재 대부분 모델에 차용 (정확한 논문 제목 `[원문 확인 필요]`, InstructGPT 계열 추정).
- 부작용: 사람이 좋아하는 답에 치우치면 [[Sycophancy]](아첨)이 생김.
- 심화 검색: **"RAG + 강화학습"** → [[RAG]].
