# 크롤링 (Web Crawling)

**정의**: 웹사이트를 자동으로 탐색하며 데이터를 수집하는 기술. 수집한 HTML에서 필요한 정보를 추출하는 과정은 파싱(Parsing)이라 한다.

---

## 왜 필요한가

검색엔진이 모든 웹페이지의 내용을 알고 있는 이유가 크롤링이다. Googlebot이 인터넷 전체를 돌아다니며 페이지 내용을 수집하고 색인에 저장한다.

AI 훈련 데이터의 상당 부분도 크롤링으로 수집된다. GPT가 인터넷의 방대한 텍스트를 학습했다는 것 = 크롤링으로 모은 데이터로 학습했다는 것.

---

## 어떻게 작동하나

### 크롤링 vs 파싱

```
크롤링: HTTP GET 요청 → HTML 페이지 받아오기
파싱:  받아온 HTML에서 필요한 정보만 추출
```

### Python으로 크롤링

```python
import requests
from bs4 import BeautifulSoup

# 1. 페이지 가져오기 (크롤링)
url = "https://news.ycombinator.com"
response = requests.get(url)
html = response.text           # HTML 전체 문자열

# 2. HTML 파싱
soup = BeautifulSoup(html, "html.parser")

# 3. 원하는 데이터 추출
titles = soup.find_all("span", class_="titleline")
for title in titles:
    link = title.find("a")
    print(link.text)           # 기사 제목 출력
```

### 정적 vs 동적 페이지

| 구분 | 설명 | 크롤링 방법 |
|:---|:---|:---|
| **정적 페이지** | 서버가 HTML을 바로 줌 | `requests` + `BeautifulSoup` |
| **동적 페이지** | JS가 실행되어야 내용이 나옴 | `Selenium`, `Playwright` |

인스타그램, 유튜브, 트위터(X)는 동적 페이지 → requests로는 빈 HTML만 옴 → Selenium 필요.

### robots.txt

크롤링 허용 범위를 명시하는 파일. `사이트주소/robots.txt`로 확인.

```
User-agent: *       # 모든 크롤러에 적용
Disallow: /admin/  # /admin/ 이하는 크롤링 금지
Disallow: /api/    # /api/ 이하도 금지
Allow: /public/    # /public/은 허용
```

## 자주 헷갈리는 것

**"크롤링 = 불법"**: 공개된 정보를 수집하는 것 자체는 불법이 아니다. 하지만 이용약관 위반, 저작권 침해, 개인정보 수집, 서버에 과도한 부하를 주는 것은 문제가 될 수 있다.

**"requests로 모든 사이트 크롤링 가능"**: 자바스크립트로 동적 렌더링하는 사이트는 requests로 가져온 HTML에 실제 콘텐츠가 없다. Selenium이나 Playwright가 필요.

**"크롤링하면 항상 차단된다"**: 적절한 딜레이(`time.sleep(1)`), User-Agent 설정, robots.txt 준수 등으로 상당 부분 방지 가능. 공격적인 크롤링은 IP 차단당한다.

---

## 더 알면 좋은 것

📌 **API 우선 검토**: 크롤링 전에 해당 서비스의 공식 API가 있는지 먼저 확인. API가 있으면 크롤링보다 안정적·합법적·효율적.

📌 **크롤링 딜레이**: 서버에 부하를 주지 않도록 요청 사이에 `time.sleep(1~3)` 추가. 사람처럼 보이게 하는 효과도 있다.

📌 **CSS Selector vs XPath**: BeautifulSoup에서 데이터를 찾는 두 가지 방식. CSS Selector가 더 직관적 (`soup.select(".class-name")`), XPath는 더 강력하지만 복잡함.
