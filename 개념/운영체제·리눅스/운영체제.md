# 운영체제 (OS, Operating System)

**정의**: 하드웨어와 애플리케이션 사이에서 자원을 관리하고 중재하는 시스템 소프트웨어.

---

## 왜 필요한가

앱이 직접 하드웨어를 제어한다면 카카오톡이 메모리를 몽땅 쓰거나 카메라를 독점하는 일이 생긴다. OS가 그 사이에서 교통정리를 한다.

OS의 두 핵심 역할:
1. **하드웨어 감추기**: 앱이 CPU·메모리·디스크를 직접 몰라도 쓸 수 있게
2. **자원 관리**: 여러 앱이 자원을 공정하게 나눠 쓰도록

---

## 어떻게 작동하나

### 구조

```
앱 (카카오톡, 크롬, ...)
        ↕ 시스템 콜(System Call)
     운영체제 (Kernel)
        ↕ 드라이버
     하드웨어 (CPU, 메모리, SSD, ...)
```

**커널(Kernel)**: OS의 핵심. 하드웨어를 직접 제어한다. 사용자가 직접 건드리면 안 되는 영역.

**시스템 콜**: 앱이 OS에게 "파일 열어줘", "메모리 더 줘" 같은 요청을 하는 인터페이스.

### OS의 4대 기능

강사가 강조한 OS의 핵심 기능 네 가지. LLM/AI 서비스를 운영할 때 자주 등장하는 키워드다.

| 기능 | 관리 내용 |
|:---|:---|
| **프로세스 관리** | 어떤 [[프로세스]]가 얼마나 CPU를 쓸지 (스케줄링), 생성·종료 |
| **메모리 관리** | 각 프로세스에 메모리 공간 할당·보호 |
| **파일 시스템 관리** | 데이터 저장·검색·권한 관리 |
| **네트워크 관리** | 통신 자원([[포트]] 등) 제어, 입출력(키보드·마우스·네트워크·모니터) |

### 주요 OS

| 환경 | OS |
|:---|:---|
| 데스크탑 | Windows, macOS, Linux |
| 서버 | Linux (Ubuntu, CentOS, Debian) |
| 모바일 | iOS (Apple), Android (Google) |
| 임베디드 | RTOS, VxWorks |

## 실제 예시

- iOS 앱과 Android 앱을 따로 개발해야 하는 이유: OS마다 카메라·GPS 등 하드웨어 접근 방식이 다름
- 같은 게임이라도 Windows 버전과 Mac 버전이 따로 있는 이유: OS가 제공하는 API가 다름
- 서버는 왜 Linux를 쓰나: 무료, 안정적, 가볍고, CLI 최적화, 전 세계 90% 이상의 서버가 Linux

## 자주 헷갈리는 것

**"운영체제 = Windows·macOS"**: 컴퓨터뿐 아니라 스마트폰(iOS·Android), 스마트워치, 냉장고, 자동차 인포테인먼트도 모두 OS가 있다.

**"커널 = 운영체제"**: 커널은 OS의 핵심 부분이지만 OS 전체가 아니다. OS는 커널 + 셸 + 유틸리티 + 파일 시스템 + UI 등 포함.

**"Linux = Ubuntu"**: Linux는 커널 이름. Ubuntu, CentOS, Debian, Fedora 등은 Linux 커널을 기반으로 만든 배포판(Distribution).

**"macOS = Linux"**: 아니다. 둘 다 **Unix 계열(Unix-like)** 이라 터미널 명령어가 비슷하지만, macOS는 **Darwin/BSD** 기반이고 Linux는 **독립 커널**이다. "사촌"이지 같은 OS가 아니다.

## 더 알면 좋은 것

📌 **멀티태스킹**: 실제로 CPU는 한 번에 하나의 작업만 처리한다. OS가 아주 빠르게 작업을 전환해서 동시에 돌아가는 것처럼 보이게 한다.

📌 **가상화(Virtualization)**: 하나의 물리 서버 위에 여러 OS를 실행. AWS·Azure 같은 클라우드의 기반 기술. 각 가상머신은 독립된 OS처럼 동작.

📌 **컨테이너(Docker)**: 가상화보다 가벼운 방식. OS를 통째로 가상화하는 대신 애플리케이션 실행 환경만 격리. → [[Docker]]

📌 **쿠버네티스**: 컨테이너가 많아지면 일일이 관리하기 어렵다. 여러 컨테이너를 자동으로 배치·복구·확장해주는 통합 관리 도구. → [[쿠버네티스]]
