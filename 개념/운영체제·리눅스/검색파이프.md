# 리눅스 검색·파이프·리다이렉션

**정의**: 파일에서 내용을 찾고(`grep`), 명령어를 연결하고(파이프 `|`), 출력을 파일로 보내는(`>` `>>`) 기능.

---

## 왜 필요한가

로그 파일은 수천 줄이다. 눈으로 다 볼 수 없으니 **원하는 줄만 찾고(grep)**, 명령어 결과를 **다음 명령으로 넘기고(파이프)**, 결과를 **파일로 저장(리다이렉션)** 해야 한다. 리눅스의 강력함은 이 조합에서 나온다.

---

## 어떻게 작동하나

### 검색 — `grep`

```bash
grep "error" app.log      # "error" 포함 줄만 출력
grep -i "error" app.log   # 대소문자 무시
grep -n "error" app.log   # 줄 번호 포함
grep -r "TODO" .          # 현재 폴더 전체 재귀 검색
```

> 문서 안에서 `Ctrl + F`로 찾는 것과 같은 역할.

### 파이프 `|` — 명령어 연결

앞 명령의 **출력**을 뒤 명령의 **입력**으로 넘긴다.

```bash
ls | grep "txt"           # 목록 중 txt 들어간 것만
ps -aux | grep python     # 실행 중 프로세스 중 python만
history | grep "cd"       # 명령 이력 중 cd만
cat app.log | grep "404"  # 로그에서 404만
```

### 리다이렉션 `>` `>>` — 출력을 파일로

```bash
echo "hi" > log.txt       # 덮어쓰기 (기존 내용 삭제!)
echo "more" >> log.txt    # 이어쓰기 (아래에 추가)
ls -al > files.txt        # 명령 결과를 파일로 저장
```

---

## 실제 예시

```bash
# 실시간 로그에서 에러만 골라 보기
tail -f server.log | grep "ERROR"

# 파이썬 프로세스의 PID 찾아 종료
ps -aux | grep python      # PID 확인 후
kill -9 <PID>
```

---

## 자주 헷갈리는 것

**`>` vs `>>`**: `>`는 기존 내용을 **싹 지우고** 덮어씀, `>>`는 **아래에 이어 붙임**. 실수로 데이터 날리지 않게 가급적 `>>`.

**파이프 방향**: 항상 **왼쪽 → 오른쪽**. `A | B`는 A의 결과를 B가 받아 처리.

**grep은 '줄' 단위**: 매칭된 단어가 아니라 그 단어가 포함된 **줄 전체**를 출력한다.

---

## 더 알면 좋은 것

📌 **`wc -l`**: 줄 수 세기. `grep "error" log | wc -l` → 에러 줄 개수.

📌 **`|` 여러 개 연결**: `cat log | grep "GET" | wc -l` 처럼 레고처럼 계속 이어붙일 수 있다.

📌 **`2>`**: 에러 출력만 따로 파일로 보내기 (표준에러 리다이렉션).
