# API 키 보안

**정의**: AI/외부 서비스 API 키가 노출되지 않도록 관리하는 원칙. 핵심은 **하드코딩 금지 + 공개 저장소 노출 금지**.

---

## 왜 필요한가

API 키는 곧 "내 계정으로 호출할 권한"이다. 키가 새면 남이 내 비용으로 API를 쓰거나 데이터에 접근한다. 특히 GitHub 공개 저장소에 키가 올라가면 봇이 수 분 내 긁어간다.

---

## 어떻게 하나

```
1. 키를 코드에 직접 쓰지 않는다 (하드코딩 금지)
2. 환경변수 / 별도 파일(.env)로 분리
3. .gitignore에 그 파일을 추가 → 깃에 안 올라감
4. GitHub 공개 저장소에 절대 노출 금지
```

키 노출 시 `IP` 등을 통해 악용·과금 사고로 이어진다.

---

## 자주 헷갈리는 것

**"커밋 후 지우면 된다"**: 안 된다. git 히스토리에 남는다. 노출됐으면 **즉시 키 폐기·재발급**.

**".gitignore면 끝"**: 이미 커밋된 파일은 gitignore가 안 막는다. 추적 해제 필요.
