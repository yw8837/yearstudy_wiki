# 관계형 대수 (Relational Algebra)

**정의**: 관계형 DB에서 원하는 정보를 **유도하기 위한 기본 연산의 집합**. 모든 연산의 입력과 출력이 릴레이션(테이블)이라는 점이 특징. SQL의 이론적 토대.

---

## 왜 필요한가

SQL 문법을 외우기 전에 "어떤 연산들이 가능한가"를 수학적으로 정리한 것. 집합 연산자·JOIN·WHERE·SELECT가 모두 관계형 대수의 어떤 연산에 대응하는지 알면 쿼리 설계가 명확해진다.

---

## 어떻게 작동하나

**① 일반 집합 연산** (집합론에서 옴)
| 연산 | SQL 대응 |
|:---|:---|
| 합집합 A∪B | [[UNION]] |
| 교집합 A∩B | [[INTERSECT]] |
| 차집합 A−B | [[EXCEPT]] |
| 카티션 곱 A×B | CROSS JOIN |

**② 순수 관계 연산** (관계형 모델 고유)
| 연산 | 기호 | SQL 대응 |
|:---|:---:|:---|
| 셀렉션(Selection) | σ | [[WHERE]] (행 필터) |
| 프로젝션(Projection) | ∏ | [[SELECT]] (열 선택) |
| 조인(Join) | ⋈ | [[JOIN]] (세타·동등·자연·외부) |
| 디비전(Division) | ÷ | (직접 대응 SQL 키워드 없음) |

---

## 실제 예시

- `SELECT 이름 FROM 직원 WHERE 부서='영업'` = 프로젝션(이름) + 셀렉션(부서='영업').

---

## 자주 헷갈리는 것

**일반 집합 연산 ↔ 순수 관계 연산**: 앞쪽(합·교·차·곱)은 집합론 그대로라 [[집합연산자]]로 직결되고, 뒤쪽(셀렉션·프로젝션·조인·디비전)은 관계형 모델 고유 연산이다.

---

## 더 알면 좋은 것

📌 디비전(÷)은 "모든 X를 만족하는 Y" 류 질의를 표현하지만 강사 언급상 **현업에서는 거의 안 쓴다**. 카티션 곱은 JOIN 단원에서 CROSS JOIN으로 다룬다.
