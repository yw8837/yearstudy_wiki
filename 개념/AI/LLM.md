# LLM (Large Language Model, 대형 언어 모델)

**정의**: 방대한 텍스트 데이터를 학습해 자연어를 이해하고 생성하는 대규모 딥러닝 모델.

---

## 왜 필요한가

인터넷에 있는 수천억 개의 문장을 학습해서 "다음에 어떤 단어가 올 것인가"를 예측하도록 훈련된 모델이다. 이 단순한 목표로 학습했는데, 결과적으로 번역·요약·코딩·수학 문제·창작까지 할 수 있게 됐다.

---

## 어떻게 작동하나

### 토큰(Token)

LLM은 텍스트를 "토큰" 단위로 처리한다.

```
"안녕하세요" → ["안녕", "하세요"] (2 tokens)
"Hello world!" → ["Hello", " world", "!"] (3 tokens)
```

토큰은 단어, 음절, 문자 등 다양하다. GPT-4는 영어 기준 약 0.75 단어 = 1 토큰.

### 컨텍스트 윈도우(Context Window)

한 번에 처리할 수 있는 토큰의 최대 수. 이 범위 밖의 내용은 "기억"하지 못한다.

```
GPT-3.5: ~4K 토큰 (~3,000 단어)
GPT-4:   ~128K 토큰 (~96,000 단어) → 단편 소설 한 편 분량
Claude:  최대 200K 토큰
```

### 주요 모델 비교

| 모델 | 회사 | 특징 |
|:---|:---|:---|
| GPT-4o | OpenAI | ChatGPT, 다중모달 (텍스트+이미지+음성) |
| Claude 3.5 | Anthropic | 긴 컨텍스트, 코딩, 안전성 강조 |
| Gemini | Google | Google 서비스 통합, 다중모달 |
| LLaMA 3 | Meta | 오픈소스, 로컬 실행 가능 |
| Mistral | Mistral AI | 유럽 기반, 오픈소스 강점 |

---

## 실제 예시

LLM이 실제로 하는 것들:
- **코드 작성·디버깅**: GitHub Copilot, Cursor
- **문서 요약**: 긴 계약서·논문을 핵심만
- **번역**: 단순 번역 넘어서 문화적 맥락까지
- **데이터 분석**: CSV 올리고 "이 데이터에서 패턴 찾아줘"
- **RAG(Retrieval-Augmented Generation)**: 회사 내부 문서 + LLM 결합

---

## 자주 헷갈리는 것

**"LLM은 검색과 같다"**: 다르다. 검색은 기존 문서를 찾아주지만, LLM은 새로운 텍스트를 생성한다. LLM은 학습 데이터에 없는 내용도 만들어낼 수 있다(이게 할루시네이션의 원인이기도 하다).

**"할루시네이션 = 버그"**: 설계상 피하기 어려운 특성이다. LLM은 "다음에 올 그럴듯한 토큰"을 예측하는 모델이라, 사실 여부와 무관하게 자신감 있게 틀린 정보를 생성할 수 있다.

**"파라미터가 많을수록 무조건 좋다"**: 어느 정도까지는 맞지만, 학습 방법·데이터 품질·파인튜닝이 더 중요한 경우도 많다. GPT-4의 파라미터 수는 공개 안 됐지만 GPT-3(1750억)보다 효율적 학습으로 더 뛰어난 성능.

---

## 더 알면 좋은 것

📌 **프롬프트 엔지니어링**: LLM에 어떻게 물어보느냐에 따라 결과가 크게 달라진다. "Step by step으로 생각해봐"(Chain-of-Thought), "역할을 부여해라"(Role-playing), "예시를 줘라"(Few-shot) 등의 기법이 있다.

📌 **RAG (Retrieval-Augmented Generation)**: LLM의 지식 한계를 보완하는 방법. 질문에 답하기 전에 관련 문서를 검색해서 컨텍스트로 제공. 기업 내부 문서 Q&A 시스템에 많이 사용.

📌 **멀티모달(Multimodal)**: 텍스트뿐 아니라 이미지·음성·영상도 처리. GPT-4o는 "o"가 omni(전방향)의 뜻.

📌 **LLM Agent**: LLM이 외부 도구(검색, 코드 실행, API)를 사용해 복잡한 작업을 자율적으로 수행. Claude MCP(Model Context Protocol)가 이 분야의 표준화 시도.
