## 01. 문자열/리스트 추가 메서드

```python
my_list = [2, 3, 5, 7, 11]
my_list.pop(0)      # 2  반환 후 삭제 (인덱스 지정)
my_list.pop()       # 11 반환 후 삭제 (마지막)
# [3, 5, 7] 남음

my_list.count(2)              # 특정 값 등장 횟수
"elice and alice".count("e")  # 3

# split: 문자열 → 리스트
"1 2 3".split()         # ['1', '2', '3']  (괄호 비우면 공백 기준)
"Na,Mg,Al".split(",")   # ['Na', 'Mg', 'Al']

# join: 리스트 → 문자열  (구분자.join(리스트) 순서 주의!)
"".join(["e","l","i","c","e"])     # "elice"
"→".join(["서울","대전","대구"])    # "서울→대전→대구"
```

> split ↔ join은 한 쌍. "쪼개서 가공 → 다시 합치기"는 데이터 처리의 기본 흐름.
> 💡 단어마다 앞뒤에 문자를 붙이는 등 가공할 때는, **리스트에 누적해 두고 마지막에 `join()`으로 한 번에 합치는** 것이 강사 권장 패턴.

## 02. 튜플 (Tuple)

```python
t = (1, 2, 3)           # 소괄호로 생성
t_one = (1,)            # 원소 1개: 반드시 쉼표 필요 ( (1)은 그냥 정수 )

# 리스트처럼: 인덱싱, 슬라이싱, in, len, +, * 가능
t[1]        # 2
t[:2]       # (1, 2)
2 in t      # True

# 다른 점: 값 변경 불가 (불변)
t[0] = 99   # TypeError!
```

**쓰는 경우**: 바뀌면 안 되는 데이터(좌표·날짜), 딕셔너리 Key, 함수에서 여러 값 반환.

> 💬 강사 코멘트: 튜플을 억지로 고치려고 **리스트로 변환 → 수정 → 다시 튜플**로 되돌리는 방식은 권장하지 않는다. 그럴 거면 처음부터 리스트를 써라. 튜플은 "바뀌면 안 되는 값"이라는 의도를 드러내는 자료형이다.

## 03. 딕셔너리 (Dictionary)

```python
person = {"name": "Rabbit", "age": 22}

person["name"]      # "Rabbit"   (접근)
person["mail"] = "rabbit@elice.com"  # 추가
person["age"] = 23  # 수정 (추가와 문법 동일)
del person["age"]   # 삭제

person.keys()       # dict_keys([...])
person.values()     # dict_values([...])
person.items()      # dict_items([(k, v), ...])
```

**Key 규칙**: 불변 자료형만 가능. str, int, tuple → OK / list → ❌ TypeError

> 💡 `keys()` / `values()` / `items()`가 돌려주는 건 **리스트처럼 보이지만 리스트가 아닌 뷰(view) 객체**다. 인덱싱 등 리스트 기능이 필요하면 `list(person.items())`로 형변환한다.

**for문과 조합**:
```python
for key, value in my_dict.items():        # 권장 (Pythonic) — 2개 변수로 언패킹
    print(f"{key}: {value}")

for key, value in zip(my_dict.keys(), my_dict.values()):  # 동일 결과
    print(f"{key}: {value}")
```

> ⚠️ **변수 하나로만 받으면 함정**: `for x in my_dict.items():`이면 `x`는 `(key, value)` **튜플**이라 값만 쓰려면 `x[1]`처럼 인덱싱해야 한다. 그래서 보통 `for key, value in my_dict.items():`처럼 **2개 변수로 언패킹**하는 게 깔끔하다.

## 04. 반복문

> 🎯 핵심은 문법이 아니라 **로직 설계**다. "리스트 원소를 다 더한다 / 개수를 센다 / 짝수만 고른다"를 *어떻게 반복으로 표현할지* 가 본질. **반복문 + 조건문 조합이 초보가 가장 많이 막히는 구간이니, 처음에 안 돼도 정상이다.**

### for 문
```python
for fruit in ["사과", "바나나"]:
    print(fruit)

# 합계·평균: 누적변수 초기화 → 반복하며 누적 → len()으로 분모 자동 계산
scores = [80, 90, 100]
total = 0
for s in scores:
    total += s
avg = total / len(scores)   # 5명이라고 5를 직접 쓰지 말고 len() 사용 (리스트 변경에 유연)
```

### for-range 문 (끝 숫자 미포함)
```python
range(5)        # 0~4
range(1, 6)     # 1~5
range(0, 10, 2) # 0,2,4,6,8

for i in range(len(my_list)):   # range + len + 인덱싱
    print(my_list[i])
```

### while 문
```python
i = 5
while i > 0:
    print(i)
    i -= 1      # 조건이 False가 되도록 반드시 변화를 줘야 함
```
> ⚠️ 조건이 항상 True → 무한루프. `break`로 탈출. while은 무한루프 위험이 커서 **break가 사실상 기본 패턴**.

### break 문
```python
while True:
    guess = int(input("숫자: "))
    if guess == 42:
        break
```

> **for vs while**: for → 횟수·범위가 정해진 경우 / while → 조건으로 멈추는 경우.
> 💬 실무 관점(강사): while은 **개발에선 필수**(프로그램은 종료조건 없으면 계속 돌아야 하니까)지만, **데이터 분석 업무에선 빈도가 낮다.** 분석 데이터는 범위가 정해져 있어 보통 **for가 적합**하다.

## 05. 함수와 메서드

### 내장 함수
```python
len([1,2,3])     # 3
sum([1,2,3])     # 6
max([1,2,3])     # 3
min([1,2,3])     # 1
```
> ⚠️ `sum`, `list`, `max` 같은 **내장 함수 이름을 변수명으로 쓰지 말 것.** `sum = 10`처럼 덮어쓰면 그 뒤로 `sum([...])`이 동작하지 않는다(흔한 실수).

### 사용자 정의 함수
```python
def plus_double(a, b):      # def 이름(매개변수):
    c = a + b
    return 2 * c            # return으로 값 돌려주기

plus_double(3, 4)          # 14
```
> `return` 없으면 결과는 `None`. 화면 확인(테스트)용이면 `print`만, **외부에서 값으로 활용하려면 반드시 `return`**. 즉 함수의 목적(테스트용/재사용용)에 따라 return 사용 여부가 갈린다.

### 매개변수 에러 읽기 (일부러 에러 내보며 의미 파악)
```python
def add(a, b):
    return a + b

add(1)          # TypeError: add() missing 1 required positional argument: 'b'
add(1, 2, 3)    # TypeError: add() takes 2 positional arguments but 3 were given
```
> 에러 메시지를 직접 읽는 연습이 디버깅의 시작.
> - `missing required positional argument` → 필수 매개변수를 **덜** 넣음
> - `takes N positional arguments but M were given` → 인자를 **더** 넣음

### default 매개변수 설계 ("고수 vs 하수")
```python
def greet(name, greeting="안녕"):   # greeting은 기본값 → "옵션"
    print(f"{greeting}, {name}!")

greet("철수")              # 안녕, 철수!     (필수 1개만)
greet("철수", "반가워")     # 반가워, 철수!   (옵션 지정)
```
> 💬 외부/다수 사용자가 쓰는 함수일수록 **필수 입력은 최소화(보통 1개)** 하고, 나머지는 **기본값(default)으로 제공해 옵션으로** 설계한다.
> 예: `pandas.read_csv()`는 매개변수가 많지만 **필수는 경로(path) 1개 중심**, 나머지는 기본값으로 동작. → 배포·사용자 관점에서 **사용자 편의성을 최우선**으로 설계.

### 전역 변수 vs 지역 변수  *(라이브 기준 6/2로 이월 — 다음 시간 예고)*
> 📌 이 파트는 라이브에서 **다음 수업(6/2)에서 클래스(Class)와 함께 다루기로 이월**되었다. 아래는 미리 보기.
```python
x = "전역"          # 어디서든 접근

def f():
    y = "지역"      # 함수 안에서만 존재
    print(x)        # 전역변수 읽기 OK

f()
print(y)            # NameError! — 함수 밖엔 y 없음
```
→ 자세히는 다음 강의 [[0602-클래스와모듈]] · 개념은 [[함수]]의 "전역/지역 변수" 참조.

### 함수 vs 메서드
- **함수**: `len(my_list)` — 독립적, 괄호 안에 대상
- **메서드**: `my_list.append(4)` — 자료형에 딸림, 점(`.`)으로 호출

## 06. git·GitHub 첫 실습 (+ uv 개발환경)

이날 파이썬 문법과 별개로 **git/GitHub 첫 실습**과 **uv 가상환경 실행**을 병행했다. 상세 개념은 [[Git]] · [[uv]].

### git/GitHub 흐름 (repo 생성 → clone → config → add/commit/push)
```bash
# 1) GitHub에서 New Repository 생성
#    - .gitignore: Python 선택 / License: 교육·공유 목적이면 MIT 권장
#    - 공개 범위: Private(공유 원치 않음) / Public(패키지 등 공유 목적)

# 2) Code > HTTPS 주소 복사 후 clone (Windows는 C드라이브 / Mac은 Desktop 등)
git clone https://github.com/yourname/your-repo.git

# 3) 본인 계정 정보로 config (강사 이메일·이름 그대로 따라치지 말 것!)
git config --global user.email "you@example.com"
git config --global user.name "Your Name"

# 4) add → commit → push
git add .
git commit -m "my first commit"
git push
```
> ✅ **정상 확인**: GitHub 레포 새로고침 시 커밋 반영 + 터미널에 빨간 에러·경고 없이 main으로 push 완료.
> 🆘 **오류 대응 원칙**: 개인 환경 오류는 원인 파악이 어렵다 → 검색·질문으로 해결 시도 → 최후엔 레포를 새로 만들고 처음부터 재진행. → [[Git]]

### uv 실행 & 트러블슈팅
```bash
uv sync
uv run jupyter lab
```
> 🆘 **`uv trampoline failed to canonicalize script path`** 에러 시 (git-bash에서 순서대로):
> ```bash
> rm -rf .venv
> uv cache clean
> uv sync
> uv run jupyter lab
> ```
> 그래도 안 되면 일부 실습은 **Google Colab**으로 전환. 자세히는 [[uv]] · [[개발환경-설정]].

## 수업 포인트

- `split()` / `join()`은 문자열 처리의 핵심 콤보 — 데이터 분석에서 자주 씀
- 딕셔너리 `items()`로 for문 돌리는 패턴이 가장 많음 (`zip`보다 간결), 결과는 **view 객체**
- `while True: ... break` 패턴 — 사용자 입력 받을 때 단골 / 분석 업무는 for가 더 적합
- `return` 없는 함수는 결과가 `None` — 함정 조심
- 매개변수는 **필수 최소 + 나머지 default**로 설계(사용자 편의 우선), 내장함수명은 변수로 쓰지 말 것
- 종합 실습으로 **FizzBuzz / 소수 판별 / 회문 판별 / 단어 빈도 / 성적 분석**을 직접 구현 → 자료형+반복문+함수의 결합
- 이날 **git/GitHub 첫 실습 + uv 개발환경** 병행 → 목요일 핵심 실습(패키지 제작) 대비

## 보충

📌 **`zip()`**: 두 리스트를 병렬로 묶어 튜플 쌍 반환. `dict(zip(keys, values))`로 딕셔너리 빠르게 생성.

📌 **`enumerate()`**: for문에서 인덱스+값 동시에. `for i, val in enumerate(list):`

📌 **`continue`**: `break`와 짝. 현재 반복만 건너뛰고 다음 반복으로.

📌 **타입 힌트(Type Hint)** *(수업에서 추가로 다룸)*: 매개변수·반환값의 자료형을 명시. 강제는 아니지만 가독성↑.
```python
def add(a: int, b: int) -> int:
    return a + b
```

📌 **독스트링(Docstring)** *(수업에서 추가로 다룸)*: 함수 첫 줄 `"""설명"""`. `help(함수명)`으로 조회, 라이브러리 공식 문서의 원천. → 출처: [Python 공식 문서 typing](https://docs.python.org/ko/3/library/typing.html)
