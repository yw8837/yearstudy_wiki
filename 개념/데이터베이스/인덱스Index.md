# 인덱스 (Index)

**정의**: 데이터베이스 테이블의 **검색 속도를 향상**시키는 자료구조. **책의 색인**처럼 특정 데이터를 빠르게 찾는다.

> 📎 이 노트는 DB 인덱스 개념. vault 최상위 `인덱스.md`(전체 지도 MOC)와는 다른 문서다.

---

## 왜 필요한가

큰 테이블에서 매번 전체를 훑으면(Full Scan) 느리다. 인덱스를 만들면 색인을 통해 원하는 행으로 바로 점프해 조회가 빨라진다.

---

## 어떻게 작동하나

```sql
CREATE INDEX 인덱스명 ON 테이블명(컬럼명);   -- 추가
SHOW INDEX FROM 테이블명;                    -- 확인 (MySQL)
ALTER TABLE 테이블명 DROP INDEX 인덱스명;     -- 삭제 (MySQL)
```

| | 장점 | 단점 |
|:---|:---|:---|
| 인덱스 | 검색 속도·성능↑ | 추가 저장공간, **삽입/수정/삭제 잦으면 갱신 비용↑** |

---

## 실제 예시

**인덱스가 좋은 경우:**
- 크기가 **큰 테이블**
- 삽입/수정/삭제가 **적은** 테이블
- `WHERE`·`ORDER BY`·`JOIN`에 **자주 쓰는 컬럼**
- **중복도 낮은(고유값 많은) 컬럼** — 예: 이메일·주민번호류

---

## 자주 헷갈리는 것

**인덱스가 항상 빠른 건 아니다.** 전수 조회(`SELECT * FROM`)나 변경이 잦은 테이블에선 오히려 갱신 비용 때문에 느려질 수 있다.

**SQLite 차이:** `CREATE INDEX`는 같지만 조회는 `PRAGMA index_list(테이블)`, 삭제는 `DROP INDEX 인덱스명;`(MySQL의 `ALTER TABLE ... DROP INDEX`와 다름).

---

## 더 알면 좋은 것

📌 "중복도 낮은 컬럼" = 같은 값이 적고 고유값이 많은 컬럼(카디널리티 높음) → 인덱스 효율이 높다.
