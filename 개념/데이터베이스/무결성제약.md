# 무결성 제약 (Integrity Constraints)

**정의**: 데이터의 **정확성·일관성을 보장**하기 위한 규칙들의 집합. [[제약조건]]은 이 무결성을 지키기 위한 수단이다.

---

## 왜 필요한가

DB는 여러 사용자가 공유하므로, 잘못된·모순된 데이터가 들어가면 신뢰성이 무너진다. 무결성 규칙으로 "올바른 상태"를 항상 유지한다.

---

## 어떻게 작동하나

| 무결성 | 규칙 | 수단 |
|:---|:---|:---|
| **개체 무결성** | 기본키는 NULL·중복 불가 | [[기본키]] |
| **참조 무결성** | 외래키는 부모 PK에 존재 or NULL | [[외래키]] |
| **도메인 무결성** | 값은 허용 범위(도메인) 내 | [[SQL자료형]] · [[CHECK]] |
| **NULL 무결성** | 특정 속성은 NULL 불가 | [[NOT NULL]] |
| **고유 무결성** | 속성값이 서로 달라야 함 | [[UNIQUE]] |
| **키 무결성** | 테이블에 키가 최소 1개 | PK |

---

## 실제 예시

- `school_db`: PK 중복 INSERT → 개체 무결성 위반 / 없는 `dept_id` 'GHOST' 참조 → 참조 무결성 위반 / grade=5 → 도메인 무결성 위반(CHECK).

---

## 자주 헷갈리는 것

**개체 무결성 vs 참조 무결성.** 개체는 **한 테이블 안**(PK가 깨끗한가), 참조는 **테이블 사이**(FK가 진짜 부모를 가리키나).

**참조 무결성과 DELETE.** 부모 행을 지우면 자식 FK가 깨질 수 있다 → 참조 중인 부모는 함부로 DELETE 못 함(또는 CASCADE 설정 필요).

---

## 더 알면 좋은 것

📌 각 무결성은 결국 [[제약조건]]([[기본키]]·[[외래키]]·[[NOT NULL]]·[[UNIQUE]]·[[CHECK]])으로 구현된다 — 개념(무결성)과 구현(제약)을 짝지어 기억.
📌 SQLite는 참조 무결성을 쓰려면 `PRAGMA foreign_keys = ON;`이 선행돼야 한다.
